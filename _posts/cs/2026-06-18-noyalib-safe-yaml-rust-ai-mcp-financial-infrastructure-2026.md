# Proč YAML potřebuje bezpečnější Rust stack pro AI, MCP a finanční infrastrukturu v roce 2026

<!-- lead-start -->
<aside class="lead" aria-label="Shrnutí článku">

**Stručně.** YAML tiše pohání workflow CI, manifesty Kubernetes, bezpečnostní politiky, infrastructure-as-code, definice nástrojů agentů a stále častěji konfiguraci serverů MCP. NoyaLib je čistý Rust stack YAML 1.2, který tuto plochu pojímá jako kritickou infrastrukturu — nulové unsafe, soulad se specifikací 406/406, streamovaný serde, bezztrátový CST, validace JSON Schema a vazby LSP/MCP/WASM dodávané společně, nikoli připojené dodatečně.

**Klíčové body:**

- **YAML je dnes kritická infrastruktura.** CI, Kubernetes, bezpečnostní politiky, nástroje agentů — jedna chyba parseru je výpadek v produkci.
- **Soulad se specifikací není „nice to have".** 406/406 testů oficiální sady; cokoli méně znamená dlouhý ocas jemných interoperačních chyb.
- **Streamovaný serde + bezztrátový CST pokryjí oba konce.** Rychlost pro velké konfigurace, bezztrátový strom pro nástroje a refaktoring.
- **Validace schématu patří do procesu.** JSON Schema jako pevná brána zastaví špatně tvarované konfigurace dříve, než se dostanou do produkce.
- **LSP + MCP + WASM v jednom stacku.** Editor, agent i prohlížeč hovoří se stejným enginem — bez driftu.

YAML působí skromně, dokud nerozbije produkci. Nese workflow CI, infrastrukturní politiky, manifesty Kubernetes, bezpečnostní pravidla, konfiguraci, metadata dokumentace a stále častěji definice nástrojů, které používají agenti. NoyaLib je důležitý, protože k YAML přistupuje jako ke kritické infrastruktuře, nikoli jako k pohodlnému textu.

Otevřeným referenčním bodem tohoto článku je [noyalib ⧉](https://github.com/sebastienrousseau/noyalib "noyalib"). Repozitář je pozicován jako: čistý Rust ekosystém YAML 1.2 s nulovým unsafe, stoprocentním souladem se specifikací napříč 406/406 testy oficiální sady, streamovaným serde, bezztrátovým CST, validací JSON Schema, CLI nástroji, LSP, MCP a vazbami WASM.

## Proč na tomto open source projektu záleží v roce 2026

Strategická hodnota open source se v roce 2026 už neomezuje na transparentnost, opětovné použití nebo dobrou vůli vývojářů. Pro banky a finanční instituce se open source infrastruktura stala nástrojem, jak ověřit předpoklady, otestovat kontroly, snížit neprůhlednost dodavatelů a převést architektonická tvrzení do kódu, který lze číst, forkovat, zpevňovat a provozovat. Nejužitečnější projekty nejsou ukázky. Jsou to referenční implementace, které odhalují, jak do sebe zapadají bezpečnost, přístupnost, výkon, soulad s předpisy a vývojářská zkušenost.

Tímto pohledem je třeba chápat i noyalib. Není to pouze repozitář; je to konkrétní designový argument. Říká, že kritická infrastruktura má být auditovatelná, kompozitní, dokumentovaná, testovatelná a srozumitelná lidem, kteří na ní závisejí. Ve finančních službách to má váhu, protože systémy stále častěji leží na průsečíku agentní AI, plateb v reálném čase, postkvantové kryptografie, cloud-native odolnosti, strukturovaných dat a regulatorních důkazů.

## Konfigurace je produkční kód

První argument je kulturní. K YAML se nemá přistupovat jako k neškodnému textu. Špatně tvarovaný, nejednoznačný nebo slabě validovaný konfigurační soubor může změnit infrastrukturu, zlomit CI, oslabit bezpečnostní politiku nebo špatně nastavit AI toolchain. Tím se kvalita parseru YAML stává systémovou otázkou.

## Proč na bezztrátovosti záleží

Bezztrátové parsování zachovává komentáře, pořadí, mezery a strukturu. Pro reálné soubory to má váhu, protože konfiguraci anotují lidé. Formátovači nebo migračnímu nástroji, který okolo dat zničí význam, inženýrské týmy nedůvěřují.

## YAML v agentním stacku

Agenti stále častěji konfiguraci čtou, zapisují a upravují. Pokud asistent AI aktualizuje deployment manifest, registr nástrojů MCP, frontmatter obsahu nebo workflow soubor, parser a validátor se stávají součástí bezpečnostní hranice. NoyaLib o této hranici poskytuje argument.
