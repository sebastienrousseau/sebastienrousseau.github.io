# De la extrase de cont la inteligență tranzacțională unificată: un parser open source pentru trezorerie

<!-- lead-start -->
<aside class="lead" aria-label="Pe scurt">

**Pe scurt.** Extrasele de cont sunt probă operațională — dar sosesc în CAMT, PAIN.001, MT940, OFX/QFX, CSV, PDF nativ și PDF scanat, fiecare cu particularitățile sale. BankStatementParser este setul de unelte open source în Python care le comprimă într-un singur model auditabil de tranzacții: parsere deterministe ISO 20022, fallback LLM pentru PDF-uri dezordonate, OCR pentru documente scanate, verificare a soldului, categorizare și o revizuire interactivă pe care trezoreria o poate folosi efectiv.

**Concluzii principale:**

- **Modelul unificat de tranzacții este produsul.** Parsarea este mijlocul; reconcilierea, prognoza și auditul sunt finalitatea.
- **Întâi deterministic, apoi AI.** Formatele structurate se parsează deterministic; doar PDF-urile dezordonate ajung la fallback LLM/OCR.
- **Verificarea soldului este poarta de încredere.** Sold inițial + sum(mișcări) = sold final — sau fișierul este respins, nu importat în tăcere.
- **Categorizarea este un flux de lucru, nu un model.** Regulile, sugestiile și revizuirea umană bat clasificarea opacă end-to-end.
- **Open source este pista de audit.** Trezoreria și riscul pot inspecta fiecare regulă de parsare, fiecare fallback, fiecare prompt.

Extrasele de cont nu sunt doar documente; ele sunt probă operațională. Pentru echipele de finanțe și trezorerie, provocarea este să transforme extrase eterogene într-un model coerent de tranzacții care să alimenteze reconcilierea, vizibilitatea numerarului, categorizarea, analiza și auditul. BankStatementParser este proiectul open source care concretizează această problemă.

Reperul open source pentru acest articol este [bankstatementparser ⧉](https://github.com/sebastienrousseau/bankstatementparser "bankstatementparser"). Depozitul este poziționat astfel: un parser Python pentru CAMT, PAIN.001, CSV, OFX/QFX, MT940 și PDF-uri, incluzând parsere deterministe ISO 20022, fallback LLM pentru PDF-uri, viziune pentru scanări, verificare a soldului, categorizare și mod de revizuire interactivă.

> - **Modelul unificat de tranzacții este produsul.** Parsarea contează pentru că permite reconcilierea, prognoza, categorizarea și revizuirea.

## Adevărata problemă este fragmentarea formatelor

Echipele de trezorerie nu trăiesc într-o lume curată de API-uri. Primesc fișiere MT940, rapoarte CAMT, exporturi CSV, extrase PDF, documente scanate și variații specifice fiecărei bănci. Valoarea BankStatementParser este că tratează eterogenitatea drept cazul normal, nu o excepție.

## De ce contează modelele unificate de tranzacții

Odată ce extrasele sunt normalizate într-un model comun de tranzacții, aceeași logică în aval poate susține reconcilierea, categorizarea, prognoza numerarului, detectarea anomaliilor și raportarea. Aici parsarea extraselor devine inteligență tranzacțională.

## AI acolo unde îi este locul

Cel mai bun tipar este: întâi deterministic, apoi AI. Formatele structurate ar trebui parsate cu reguli explicite. PDF-urile, scanările și aranjamentele ambigue pot necesita OCR și fallback LLM. Cerința de control este ca ieșirea AI să fie verificată, revizuibilă și explicabilă.
