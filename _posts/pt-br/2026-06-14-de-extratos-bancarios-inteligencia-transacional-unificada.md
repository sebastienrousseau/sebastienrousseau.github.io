# De extratos bancários à inteligência transacional unificada: um parser de código aberto para tesouraria

<!-- lead-start -->
<aside class="lead" aria-label="Resumo do artigo">

**TL;DR.** Extratos bancários são evidência operacional — mas chegam em CAMT, pain.001, MT940, OFX/QFX, CSV, PDF nativo e PDF digitalizado, cada um com suas peculiaridades. O BankStatementParser é o toolkit Python de código aberto que os consolida em um único modelo unificado de transações auditável: parsers determinísticos de ISO 20022, fallback LLM para PDFs confusos, OCR para digitalizações, verificação de saldo, categorização e um modo de revisão interativa que a tesouraria de fato consegue usar.

**Pontos-chave:**

- **O modelo unificado de transações é o produto.** O parsing é o meio; conciliação, previsão e auditoria são o fim.
- **Determinístico primeiro, IA depois.** Formatos estruturados são processados deterministicamente; só PDFs confusos chegam ao fallback LLM/OCR.
- **A verificação de saldo é a porta de confiança.** Saldo inicial + soma(movimentos) = saldo final — ou o arquivo é rejeitado, não importado silenciosamente.
- **Categorização é fluxo de trabalho, não modelo.** Regras, sugestões e revisão humana superam classificação opaca de ponta a ponta.
- **O código aberto é a trilha de auditoria.** Tesouraria e risco podem inspecionar cada regra de parsing, cada fallback, cada prompt.

Extratos bancários não são apenas documentos; são evidência operacional. Para equipes de finanças e tesouraria, o desafio é converter extratos heterogêneos em um modelo consistente de transações capaz de sustentar conciliação, visibilidade de caixa, categorização, analytics e auditoria. O BankStatementParser é o projeto de código aberto que torna esse problema concreto.

A referência de código aberto para este artigo é [bankstatementparser ⧉](https://github.com/sebastienrousseau/bankstatementparser "bankstatementparser"). O repositório se posiciona como: um parser Python para CAMT, pain.001, CSV, OFX/QFX, MT940 e PDFs, com parsers determinísticos de ISO 20022, fallback LLM para PDFs, visão para digitalizações, verificação de saldo, categorização e modo de revisão interativa.

> - **O modelo unificado de transações é o produto.** O parsing importa porque viabiliza conciliação, previsão, categorização e revisão.

## O problema real é a fragmentação de formatos

A tesouraria não vive em um mundo de APIs limpas. Recebe arquivos MT940, relatórios CAMT, exportações CSV, extratos em PDF, documentos digitalizados e variações específicas por banco. O valor do BankStatementParser é tratar a heterogeneidade como caso normal, não como exceção.

## Por que modelos unificados de transações importam

Uma vez que os extratos são normalizados em um modelo compartilhado de transações, a mesma lógica a jusante pode sustentar conciliação, categorização, previsão de caixa, detecção de anomalias e relatórios. É aqui que o parsing de extratos vira inteligência transacional.

## IA onde ela pertence

O melhor padrão é determinístico primeiro, IA depois. Formatos estruturados devem ser processados com regras explícitas. PDFs, digitalizações e layouts ambíguos podem precisar de OCR e fallback LLM. A exigência de controle é que a saída da IA seja verificada, revisável e explicável.
