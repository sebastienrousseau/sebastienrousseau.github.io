# 流動性再造：為何企業資金管理自動化仍只完成一半

**企業資金管理團隊花了十年推動支付數位化，但只有39%認為自家系統已大致或完全自動化；即時、無國界與具韌性的流動性，成敗就取決於這道落差。**

## 十年數位化，以及一個應該讓你不安的數字

過去十年，支付與更廣泛的企業資金管理職能歷經一段重大的數位轉型。這是比較讓人安心的說法，也是 J.P. Morgan 2026年報告 *Payments Outlook: Five shifts powering payments* 的開場白。比較不讓人安心的說法，藏在報告引用的一份調查裡。這份調查由 J.P. Morgan 與美洲 SAP 使用者協會（ASUG，Americas SAP User Group）合作進行，值得放慢速度讀。

87%的組織在資金管理與支付基礎設施上已有某種程度的自動化。讀到這裡就停下，畫面看似已經完成。再往下讀一個數字，畫面就不完整了：只有39%認為自家系統已大致或完全自動化。同一份調查指出，對許多組織（48%）而言，現有的自動化僅是部分自動化。樣本不大，n=107位受訪者，因此我會把這些百分比視為一張快照，而非普查。即便如此，方向很難忽視。

這份調查也明確定義了「自動化」，這一點很重要，因為這個詞常被過度延伸。它指的是資金管理與支付流程的端到端整合，涵蓋應付與應收帳款系統、銀行連線，以及以最少人工投入完成的自動對帳、例外處理與直通式處理（STP）。依此定義，自動化鏈條中的某一個步驟，並不代表整條鏈已經自動化。一個已有銀行連線、卻仍以人工對帳的資金管理團隊，屬於部分自動化的那一群。

停留在那裡的代價，報告也說得很直白。根據同一份 J.P. Morgan 與 ASUG 調查，人工處理是支付基礎設施最大的痛點。不是詐欺，不是成本，不是法規，而是人工作業。

我認為，這項發現應該左右創辦人與技術主管解讀後續所有內容的方式。即時流動性、無國界流動性與全天候資金管理，都是吸引人的構想。每一項都預設資金與資料的流動不需要有人重新輸入。如果多數組織距離這個前提只走了一半，真正值得問的就不是下一個該買哪項進階功能，而是哪一個人工步驟仍在卡住那些已經付錢買下的功能。

## 背景：成長具韌性，但有摩擦

J.P. Morgan Global Research 預期全球經濟在2026年將維持韌性。這是有所保留的預期，也應該這樣解讀。同一份資料對拖累因素則直言不諱：貿易緊張與衝突風險正在影響成長。

在此背景下，AI 主導的投資預期將成為未來五年經濟的核心驅動力。同樣地，這是預期而非結果。支付是將從 AI 驅動的技術進展中大幅受益的領域之一，但這也是前瞻性的說法，報告並未聲稱這已經發生。

為什麼一篇談資金管理底層管線的文章，要提總體經濟情勢？因為它解釋了壓力從何而來。經濟環境與新技術正在加速推動即時、無國界與具韌性的流動性，並改變營運資金管理。情勢越不確定，掌握現金在哪裡、並能移動它的價值就越高。技術正好在環境對它要求更多的時刻到位。

隨著企業追求高效率、自動化且透明的資金管理系統，財務職能正因資料、AI 與更緊密的連線而轉變。支付技術已在協助最佳化營運資金，並創造可見度，支援資金管理職能做出有依據的決策。關鍵字是「已在」：這部分不是臆測。

## 三種流動性

財務主管越來越重視即時流動性、無國界流動性與具韌性的流動性，以及動態營運資金解決方案。這是一套實用的分類，因為每個面向都有各自的工具，而且工具是逐項列出，不是模糊帶過。多幣別管理、虛擬帳戶管理（VAM）與集團內部付款最佳化，歸在無國界流動性之下。API 串接、名目資金池與自動資金歸集，歸在具韌性的流動性之下。即時流動性則是另外兩者共同倚賴的基礎，值得先看。

### 即時流動性：單一視角

即時流動性讓企業在任何時間點，都能掌握所有營運實體的現金部位。這種集中式單一視角背後的機制並不光鮮。它來自精簡法律實體與銀行帳戶布局，以及透過 API 串接，將銀行入口網站與資金管理系統（TMS）或企業資源規劃（ERP）軟體整合。

把這段話當成一份工程需求再讀一次。有兩件事必須發生：需要對帳的實體與帳戶變少，以及銀行與主要紀錄系統之間建立程式化連線。兩者都不是一鍵開啟的產品。前者是組織決策，後者是整合工作。這正是39%這個數字重要的原因：可見度這一層，倚賴的正是調查對自動化所定義的端到端整合。

接著由自動化負責移動資金。透過自動化，資金可依預先定義的事件在帳戶之間移動，無需人工介入。自動資金歸集讓資金主管能即時調度現金，並自動將其重新配置到最需要的地方，消除不同時區與截止時間造成的摩擦。任何曾看過資金歸集卡在另一個地區截止時間之後的人，都會明白它的吸引力。

同樣的邏輯也適用於應收帳款端。J.P. Morgan 董事總經理暨應收帳款解決方案主管 Michelle Conklin 表示，自動化正在大幅減少人工介入，並讓付款能近乎即時地沖銷發票，從而改變應收帳款與付款對帳作業。對帳正是那種例外繁多、預設仰賴人工的工作，讓組織一直停留在部分自動化的群體裡。

### 無國界流動性：移轉價值，而不移動資金

邁向即時流動性，開啟了無國界流動性的可能：資金主管能在多個國家或幣別之間，迅速完成即時付款或集團內部融資。報告將此定位為即時能力所開啟的可能性，我也會維持這個定位。它不會自動發生。

其中一項機制以具體的方式描述。以虛擬帳戶架構取代實體資金移動，用於集團內部交易結算，財務團隊就能在不於帳戶或地點之間移動資金的情況下，管理內部現金流並最佳化外匯。吸引人之處在於，資金移動變成一筆帳務事件，而非一筆轉帳，因此可能出錯的環節更少，需要等待的時間也更短。

更廣泛的支付軌道同樣重要。即時支付（RTP）機制傳統上以國內為主，但預期將變得更成熟，並與其他國家互相串連。兩個例子足以說明。印度的統一支付介面（UPI，Unified Payments Interface）被稱為全球最大的即時支付網路，每日處理逾6.4億筆交易，並將在2029年3月前擴展至逾20個國家。歐盟的 SEPA 目前涵蓋41個國家，並計畫將10萬歐元的交易上限，調升至理論上限略低於10億歐元。

請注意每項陳述的強度。UPI 的每日交易量以事實呈現。SEPA 的升級是一項計畫。報告由此推論出的結果，也就是對全歐洲的企業而言，過去需要數小時甚至數日才能結算的大額付款，將在數秒內完成清算，則是一項預測。我認為這項預測在資金管理規劃上值得認真看待，但它還不是結果，報告也沒有說明何時實現。

### 具韌性的流動性：安全防線

當動盪情勢打亂現金流或導致支出暴增時，能夠迅速從企業不同部門調度資金或擔保品，可能成為關鍵的安全防線。一句話就說完了韌性的理由。重點在於選擇權：當平常的計畫失靈時，現金與擔保品仍然可以調度。

報告描述了兩種結構性做法。第一種是支付集中化。資金管理部門可以考慮運用區域資金管理中心或集團內部銀行來集中現金，而不是倚賴各地分支辦公室。報告將此列為可考慮的選項，而非處方，我也會這樣解讀。

第二種是多幣別名目資金池，將多個不同銀行帳戶的餘額彙總，形成單一現金部位。實際效益說得很清楚：名目資金池讓資金管理部門能以某一幣別帳戶的剩餘現金，抵銷另一帳戶的赤字，減少對複雜集團內部借貸與外匯避險的需求。即使在暫時性的幣別短缺或錯配期間，它也能確保交易結算與自動現金調度持續運作。

把三個面向並排來看，依賴鏈一目了然。單一現金部位、自動資金歸集與 API 串接，底層都需要乾淨的整合。虛擬帳戶與資金池減少了資金的移動，但仍需要銀行與資金管理系統對餘額有一致的認定。

## 全天候資金管理，以及速度的代價

全天候資金管理是一種概念：資金可依可程式化的自動化機制，以及區塊鏈智慧合約等解決方案，全年無休地在組織內移動。這是前述自動資金歸集的邏輯終點：如果規則能依預先定義的事件觸發資金移動，原則上就沒有任何理由要等到營業時間。

機構對區塊鏈技術的採用，包括穩定幣與代幣化，正在快速成長。未來幾年，AI、區塊鏈與 API 串接等技術將進一步加速數位化。交易預期將變得更無摩擦、更快速也更便利。最後這兩句是前瞻性陳述，我會讓它們留在這個語氣裡：報告預期會加速，並未說已經完成。

接下來這部分，我認為值得比平常得到更多關注。交易速度提高，風險也隨之升高。報告直接這麼說，而這也順著全文的邏輯而來。如果資金能依預先定義的觸發條件在任何時刻移動，一道錯誤或詐欺的指令也能移動得一樣快。移除人工介入的自動化，同時也移除了原本可能讓人及時發現問題的那一段停頓。

網路犯罪者正運用 AI 強化詐欺手法。預期將造福支付的同一項技術，正被拿來對付支付。為因應不斷增加的 AI 驅動詐欺，企業正以更強的數位身分驗證與更嚴格的交易對手驗證，投入報告所稱的「比拚誰更鍥而不捨的競賽」。被點名的就是這兩項控制措施，而我要指出，兩者都在確認付款另一端是誰，而不是關於付款本身的速度。

封閉迴路生態系呈現了同一股張力的商業面。它讓企業對支付流程有更大的掌控，也為客戶提供更順暢的結帳流程，包括透過 AI 智能體結帳，而這類智能體將越來越常代替購物者完成交易。從智能體商務到嵌入式支付，下一波創新正讓支付變得更無摩擦、更個人化。掌控與便利在這裡同時到來；依照前面關於速度的邏輯，驗證的需求也一併到來。

## 這對資金管理路線圖意味著什麼

把報告的發現整理成實務立場，我會提出三個論點，而且每一個都以報告為依據，而非個人偏好。

第一，先完成已經開始的事，再追加流行的東西。調查顯示87%已有某種程度的自動化，只有39%已大致或完全自動化，而人工處理被點名為最大痛點。穩定幣、代幣化與 AI 智能體已在眼前，機構採用區塊鏈的速度也在快速成長，但一個仍以人工對帳的資金管理部門，有更迫切的問題要處理。調查本身對自動化的定義，涵蓋應付與應收帳款系統、銀行連線、自動對帳、例外處理與直通式處理，讀起來就像一份檢查清單，標出部分自動化的實作在哪裡停下。

第二，把可見度當成前提。即時流動性倚賴精簡的法律實體與銀行帳戶布局，以及銀行入口網站與 TMS 或 ERP 軟體之間的 API 整合。這些步驟讓單一現金部位成為可能；而名目資金池、自動資金歸集與虛擬帳戶架構，在其所依據的現金部位值得信賴時，都能運作得更好。

第三，在編列速度預算的同時，也編列風險預算。報告並未把詐欺控制當成事後補充，而是將它呈現為對一項可衡量轉變的回應：網路犯罪者運用 AI，企業則以更強的數位身分驗證與更嚴格的交易對手驗證回應。交易速度提高，這些控制措施的必要性也隨之提高。

以上都不是在反對路線圖中較具企圖心的那一端。即時支付機制互相串連、SEPA 規劃中的上限調升、UPI 在2029年3月前擴展至逾20個國家：這些發展都可能讓無國界流動性對更多資金管理部門變得可行。它們仍屬預期而非已完成，路線圖也應該如實註明。

## 數據留下的問題

調查呈現的是組織目前的位置：87%已有某種形式的自動化，39%已大致或完全自動化。它沒有告訴我們中間那一群，也就是表示部分自動化的48%，會以多快的速度前進。報告也沒有說明這些組織會優先處理三種流動性中的哪一種，或者更快的支付軌道是否會比讓它們安全的控制措施先到位。

最後這一點最值得關注。UPI 預定在2029年3月前擴展至逾20個國家，SEPA 正規劃略低於10億歐元的上限。如果數秒內完成結算成為全歐洲大額付款的常態，資金管理部門就必須證明數位身分驗證與交易對手驗證跟得上這個速度。更快的支付軌道與更嚴格的控制措施，哪一個先到，是值得持續追蹤的未解問題。

## 常見問題

**現今的資金管理與支付系統自動化到什麼程度？**
在報告引用的 J.P. Morgan 與 ASUG 調查中，87%的組織在資金管理與支付基礎設施上已有某種程度的自動化。只有39%認為自家系統已大致或完全自動化，而有48%僅為部分自動化。樣本為107位受訪者。

**調查中，什麼才算自動化？**
受訪者拿到的定義是：資金管理與支付流程的端到端整合，涵蓋應付與應收帳款系統、銀行連線，以及以最少人工投入完成的自動對帳、例外處理與直通式處理。只自動化單一步驟，並不符合這個定義。

**什麼是即時、無國界與具韌性的流動性？**
即時流動性讓企業在任何時間點，都能掌握所有營運實體的現金部位。無國界流動性讓資金主管能在多個國家或幣別之間，迅速完成即時付款或集團內部融資。具韌性的流動性，是在動盪情勢打亂現金流時，能迅速調度資金或擔保品的能力，並由名目資金池與自動資金歸集等工具支撐。

**為什麼付款更快會帶來更多風險？**
報告指出，交易速度提高，風險也隨之升高，而網路犯罪者正運用 AI 強化詐欺手法。企業正以更強的數位身分驗證與更嚴格的交易對手驗證因應。

**報告對 UPI 與 SEPA 有什麼說法？**
印度的 UPI 被稱為全球最大的即時支付網路，每日處理逾6.4億筆交易，並將在2029年3月前擴展至逾20個國家。SEPA 目前涵蓋41個國家，並計畫將10萬歐元的交易上限，調升至理論上限略低於10億歐元。
