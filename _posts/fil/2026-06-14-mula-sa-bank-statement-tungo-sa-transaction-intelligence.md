# Mula sa mga Bank Statement Tungo sa Unified Transaction Intelligence: Pagbuo ng Open Source Parser para sa mga Koponan ng Tresurya

<!-- lead-start -->
<aside class="lead" aria-label="At a glance">

**TL;DR.** Ang mga bank statement ay operational evidence — ngunit dumarating ang mga ito sa CAMT, PAIN.001, MT940, OFX/QFX, CSV, native PDF, at na-scan na PDF, bawat isa ay may sariling pagkukulang. Ang BankStatementParser ang open source na Python toolkit na nagpapatumba sa mga ito sa iisang nasusubaybayang transaction model: deterministic ISO 20022 parsers, LLM fallback para sa magulong PDF, OCR para sa mga scan, balance verification, kategorisasyon, at isang interactive review mode na talagang magagamit ng tresurya.

**Mga pangunahing tinik:**

- **Ang unified transaction model ang produkto.** Pamamaraan ang pag-parse; layunin ang reconciliation, forecasting, at audit.
- **Una ang deterministic, pangalawa ang AI.** Deterministic parsing ang mga istrukturadong format; mga magulong PDF lamang ang umaabot sa LLM/OCR fallback.
- **Ang balance verification ang pinto ng tiwala.** Opening + sum(movements) = closing — o tinatanggihan ang file, hindi tahimik na ini-import.
- **Workflow ang kategorisasyon, hindi modelo.** Higit pa sa malabong end-to-end classification ang mga rule, suhestyon, at pagsusuri ng tao.
- **Ang open source ang audit trail.** Maaaring suriin ng tresurya at risk ang bawat parsing rule, bawat fallback, bawat prompt.

Ang mga bank statement ay hindi lamang mga dokumento; sila ay operational evidence. Para sa mga koponan ng pananalapi at tresurya, ang hamon ay gawing pare-parehong transaction model ang magkakaibang statement na maaaring magpaandar ng reconciliation, cash visibility, kategorisasyon, analytics, at audit. Ang BankStatementParser ang open source na proyektong ginagawang kongkreto ang problemang iyan.

Ang sangguniang open source para sa artikulong ito ay [bankstatementparser ⧉](https://github.com/sebastienrousseau/bankstatementparser "bankstatementparser"). Ang imbakan ay nakaposisyon bilang: isang Python parser para sa CAMT, PAIN.001, CSV, OFX/QFX, MT940, at mga PDF, kabilang ang deterministic ISO 20022 parsers, LLM fallback para sa mga PDF, vision para sa mga scan, balance verification, kategorisasyon, at interactive review mode.

## Ang Tunay na Problema ay Pagkahati-hati ng Format

Hindi namumuhay sa malinis na API world ang mga koponan ng tresurya. Tumatanggap sila ng mga MT940 file, CAMT report, CSV export, PDF statement, na-scan na dokumento, at mga partikular sa bangko na pagkakaiba. Ang halaga ng BankStatementParser ay tinatrato nito ang pagkakaiba-iba bilang normal na kaso sa halip na pambihira.

## Bakit Mahalaga ang mga Unified Transaction Model

Kapag nor-normalize na ang mga statement sa iisang transaction model, maaaring suportahan ng parehong lohika sa ibaba ang reconciliation, kategorisasyon, cash forecasting, anomaly detection, at pag-uulat. Dito nagiging transaction intelligence ang pag-parse ng statement.

## AI sa Tamang Lugar

Ang pinakamahusay na pattern ay deterministic muna, AI pangalawa. Dapat i-parse ang mga istrukturadong format gamit ang mga tahasang rule. Maaaring kailanganin ng mga PDF, scan, at malabong layout ang OCR at LLM fallback. Ang kinakailangan sa kontrol ay dapat ma-verify, masuri, at maipaliwanag ang output ng AI.
