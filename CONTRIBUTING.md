# Contributing

Thanks for your interest in `sebastienrousseau.com`. This repository is a
secure, 28-language static-site pipeline: a Rust static-site generator (`ssg`)
core, Python generators and postbuild passes, and Cloudflare Workers, deployed
to GitHub Pages. This guide covers the toolchain, the build model, and the
conventions a change has to satisfy before it can merge.

## Toolchain

Tool versions are pinned so local builds match CI (see
[`project-docs/adr/0002-pin-build-toolchains.md`](project-docs/adr/0002-pin-build-toolchains.md)).
Use [`mise`](https://mise.jdx.dev/) to install them:

```bash
mise install          # installs the pinned Python, Node, and ssg versions from mise.toml
pip install -r requirements-dev.txt
```

Do not upgrade a pinned toolchain in a feature PR. The `ssg` version in
particular is load-bearing for every page; changing it is a dedicated,
separately-validated migration (see
[`project-docs/ssg-fixes-and-native-migration-spec.md`](project-docs/ssg-fixes-and-native-migration-spec.md)).

## Repository layout

| Path | What it is |
|---|---|
| `_posts/` | Article source (EN + 27 locale subdirectories). **Committed source of truth.** |
| `_layouts/` | Page shells + `main.js` / `search.js`. Some layouts are **generated** — see below. |
| `_data/` | i18n slug maps, feeds, proof metrics. |
| `scripts/generators/` | Python generators (`gen_layouts`, `gen_articles`, `build_topics`, …). |
| `scripts/postbuild/` | Postbuild passes over `public/` (SEO, CSP, citations, enrich, …). |
| `workers/` | Cloudflare Workers (lang router, CSP header). |
| `tests/` | 1,175+ tests: `unit/`, `validation/` (18 build gates), smoke. |
| `project-docs/` | Architecture, ADRs, specs, plans. |

## The build model — read this before editing

The build is **copy-based and source-mutation-safe**
([`project-docs/adr/0003-build-copy-pipeline.md`](project-docs/adr/0003-build-copy-pipeline.md)).
`build.sh` copies `_posts/` into `_posts_build/`, runs `ssg` + the generators +
postbuild against the **copy**, and validates `public/`. Your committed source
is never mutated by a normal build.

> [!WARNING]
> Several files are **generated**, and running a generator directly against
> `_posts/` mutates committed source:
>
> - `_layouts/*.html` are generated by `gen_layouts.py` from the `index.html`
>   shell — edit the shell / generator, not the outputs.
> - `_posts/{articles,projects}.md` are generated listings.
> - `make regenerate` runs generators against `_posts/` directly and is
>   **unsafe** for exactly this reason. Prefer `./build.sh`.
>
> If you edit a generated file directly, CI's pre-build generation step will
> revert it. Change the generator or its input instead.

### Local build vs CI

The pinned `ssg` 0.0.x emits some known-benign local warnings (YAML
"double-quoted continuation", lang-leakage) that do not reproduce in CI. When a
local build disagrees with CI, **trust CI** — it is the source of truth for
merge readiness. See
[`project-docs/ci.md`](project-docs/ci.md).

## Publishing an article

The daily flow is documented in
[`project-docs/daily-publishing.md`](project-docs/daily-publishing.md) and
automated by the `publish-today` command: promote the draft, pass the editorial
gate (`scripts/editorial/check_voice.py`), pick a banner, scaffold + translate
27 locale stubs, refresh listings + feeds, build, and open a `feat/<slug>` PR.

## Change conventions

- **Branches:** `feat/<slug>`, `fix/<slug>`, `docs/<slug>`. One topic per branch.
- **Commits:** [Conventional Commits](https://www.conventionalcommits.org/),
  GPG-signed **and signed off** (`git commit -S -s`). Content commits use
  `feat(content): <date> — <title>`. See [Sign-off (DCO)](#sign-off-dco).
- **Never** commit `public/` or `docs/` build output — CI builds and deploys
  `public/` fresh ([`project-docs/adr/0007-docs-to-public-deploy.md`](project-docs/adr/0007-docs-to-public-deploy.md)).
- **Never** add `ANTHROPIC_API_KEY` or other secrets to CI, env files, or
  workflows.
- **Never** invent statistics or sources in content.

## Sign-off (DCO)

Every commit must carry a `Signed-off-by` line. Add it with `-s`:

```bash
git commit -S -s -m "fix(build): ..."
```

which appends:

```
Signed-off-by: Your Name <your.email@example.com>
```

The two flags do different jobs and you want both. `-S` is a GPG signature: it
proves the commit came from you and has not been altered. `-s` is a sign-off:
it is your assertion that you have the right to submit this work under the
project's licence. A signature establishes *who*; a sign-off establishes
*entitled to*.

By signing off you certify the [Developer Certificate of Origin
1.1](https://developercertificate.org/), reproduced here in full:

```
Developer Certificate of Origin
Version 1.1

Copyright (C) 2004, 2006 The Linux Foundation and its contributors.

Everyone is permitted to copy and distribute verbatim copies of this
license document, but changing it is not allowed.


Developer's Certificate of Origin 1.1

By making a contribution to this project, I certify that:

(a) The contribution was created in whole or in part by me and I
    have the right to submit it under the open source license
    indicated in the file; or

(b) The contribution is based upon previous work that, to the best
    of my knowledge, is covered under an appropriate open source
    license and I have the right under that license to submit that
    work with modifications, whether created in whole or in part
    by me, under the same license (unless I am permitted to submit
    under a different license), as indicated in the file; or

(c) The contribution was provided directly to me by some other
    person who certified (a), (b) or (c) and I have not modified
    it.

(d) I understand and agree that this project and the contribution
    are public and that a record of the contribution (including all

    this project or the open source license(s) involved.
```

Use your real name and an email you can be reached at. If you forgot the
sign-off on the last commit, `git commit --amend -s --no-edit` fixes it; for
a longer branch, `git rebase --signoff main`.

There is no CLA. The DCO is deliberately the lighter mechanism: it asks you to
certify what you already know about your own work, and it does not assign
anyone any rights.

## What must be green before merge

Every PR runs the full gate set; all are required:

- **Static analysis** — `ruff`, `mypy` (strict tier), `radon` complexity,
  `jscpd` duplication (≤3%), naming, KV audit.
- **Build + smoke tests + partition** — 100% coverage gate on
  `postbuild_lib` (pre- and post-build), plus the 18 `tests/validation/` gates
  (i18n leakage, hreflang, CSP, RTL, sitemap, news-sitemap, JSON-LD, canonical,
  meta-description).
- **pa11y** ×4 shards at WCAG2AAA
  ([`project-docs/adr/0008-pa11y-sharding-and-cache.md`](project-docs/adr/0008-pa11y-sharding-and-cache.md)).
- **Lighthouse** — performance, accessibility, best-practices, SEO all gated.
- **CodeQL + OpenSSF Scorecard.**

Fix the root cause of a gate failure; never skip a gate.

## Security

Report vulnerabilities per [`SECURITY.md`](SECURITY.md). The security posture —

described in [`project-docs/security.md`](project-docs/security.md) and
[`project-docs/threat-model.md`](project-docs/threat-model.md).
