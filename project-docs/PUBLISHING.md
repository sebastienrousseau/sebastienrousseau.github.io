# Publishing guide

How an article moves from a Markdown file on your laptop to a live page
on `sebastienrousseau.com` in 28 languages — fully end-to-end, with
every step explained, every editorial decision exposed, every command
copy-pastable.

This document is the **definitive runbook**. The shorter
[`project-docs/daily-publishing.md`](daily-publishing.md) is the elevator pitch;
this one is what you read the first time you publish, when something
breaks, or when you fork this repo and adapt it for your own site.

## Mental model

Every published article is **28 things** to the build:

1. One canonical EN Markdown file in `_posts/YYYY-MM-DD-<slug>.md`.
2. 27 native-language Markdown files in `_posts/<lang>/<localised-slug>.md`,
   one per active locale in `scripts/lib/_lang_registry.py`.
3. One entry in each of 27 `_data/i18n/<lang>/slugs.json` `articles`
   maps, providing the EN→native slug mapping that the hreflang
   reciprocity gate enforces.

The static-site generator emits 28 HTML pages from those 28 Markdown
sources. The postbuild pass then stitches them together with:

- **hreflang alternates** — every page links to its 27 siblings.
- **Sitemap entries** — auto-generated from the rendered tree.
- **RSS / Atom / JSON Feed** — one canonical EN feed plus one per
  active locale (28 feeds total).
- **Schema.org JSON-LD** — `BlogPosting`, `TechArticle`,
  `SoftwareSourceCode`, `HowTo`, `FAQPage`, `ItemList`, `Person`,
  `Organization` graphs as appropriate per page.
- **Newsroom listing pages** — `/articles/` (auto-regenerated by
  `scripts/generators/gen_articles.py`) and `/papers/`, `/projects/`,
  `/playlists/` (each with its own `gen_*.py`).
- **Homepage `From the desk` card** — manually curated in
  `_posts/index.md`.

The pipeline enforces 13 CI gates against the final tree
([`project-docs/CI.md`](CI.md)). The two that bite most often when adding an
article are:

- `test_i18n_parity` — every EN slug must map to a native slug in
  every active locale's `slugs.json`.
- `test_hreflang_reciprocity` — every link must reciprocate.

The publish flow scaffolds the 27 stub posts + slug-map entries up
front so both gates pass before you've finished writing the
translations.

## Prerequisites

- Python 3.11+
- Rust + `cargo install shokunin` (the static-site generator)
- `wasm-pack` (optional; only needed for the `/labs/` WASM demos)
- `git` with commit signing configured
  (`commit.gpgsign=true`, an SSH or GPG signing key loaded in your
  agent)
- [Claude Code CLI](https://docs.claude.com/en/docs/claude-code/overview) on the laptop you'll publish from — translation runs in your local Claude session, no API key in the repo

`pip install -r requirements.txt` covers the Python deps (markdown-it-py, rjsmin, rcssmin).

## TL;DR daily flow

```bash
# 1. Drop today's article into _drafts/, dated:
cp my-piece.md _drafts/2026-05-20-my-piece.md

# 2. In Claude Code on your laptop:
/publish-today
```

That's the whole flow. Everything below is what `/publish-today` does
on your behalf, exposed so you can step through it manually if you ever
need to.

## Step-by-step: publish today's article

### Step 1 — Write the EN draft

Create `_drafts/<today>-<kebab-slug>.md`. The date prefix in the
filename **is** the publication date — the rest of the pipeline reads
it from there.

The body is standard Markdown with the [frontmatter
contract](#the-frontmatter-contract) at the top. Look at any
`_posts/2026-05-*.md` for the structural template — executive summary
aside → blockquote takeaways → numbered sections → architecture table
→ "what this means by …" → conclusion → FAQ → references.

### Step 2 — Run the slash command

In Claude Code:

```
/publish-today
```

The slash command (defined in
[`.claude/commands/publish-today.md`](../.claude/commands/publish-today.md))
walks Claude through every following step, with you approving every
file write.

You can also drive the pipeline manually — every step below is a
plain shell command.

### Step 3 — Promote draft → post

```bash
./scripts/editorial/publish-daily.sh
```

The script:

1. Finds `_drafts/<today>-*.md`. (If there isn't one but
   `_posts/<today>-*.md` already exists — i.e. someone re-ran the
   pipeline mid-day — it picks up from there.)
2. `git mv` from `_drafts/` to `_posts/`.
3. Calls `python3 scripts/editorial/translate_post.py <slug>`, which:
   - For each of 27 active non-EN locales, writes
     `_posts/<lang>/<localised-slug>.md` containing the localised
     frontmatter + the EN body wrapped in a
     `<!-- translation-stub: replace this body in Claude Code -->`
     marker.
   - Appends the EN→native slug mapping to each
     `_data/i18n/<lang>/slugs.json`.
4. Re-runs every `gen_*.py` listing-page regenerator so
   `_posts/articles.md`, `_posts/projects.md`, `_posts/papers.md`,
   `_posts/playlists.md` pick up the new post.
5. Runs `./build.sh` — full build + every CI gate.

If the build exits 0, the stub-shaped site is ready to ship. The next
two steps replace the stubs with real translations.

### Step 4 — Editorial: add the newsroom-grid card + featured tuple

Two files are **hand-curated** because the choices are editorial, not
mechanical:

#### `_posts/index.md` — the "From the desk" section on the homepage

Find the `<div class="newsroom-grid feat-latest-grid">` block. Five
`<article class="newsroom-card">` blocks live inside it. Prepend a new
card for today's article (mirror the existing card structure exactly),
drop the bottom-most card so the grid stays at five.

Each card needs:

- `<a class="newsroom-card-media" href="/<slug>/index.html" title="<title>">` wrapping the banner `<img>`
- `<img alt="<banner_alt>" src="<banner_url>" loading="lazy" decoding="async" width="600" height="600" />`
- `<span class="newsroom-eyebrow">Topic · Topic · Topic</span>`
- `<h3><a href="/<slug>/index.html">…title…</a></h3>`
- `<p class="newsroom-meta"><time datetime="YYYY-MM-DD">Month Day, Year</time></p>`
- `<p class="newsroom-excerpt">…120–180 char hook…</p>`

#### `scripts/generators/gen_articles.py` — `/articles/` featured story

Prepend an 8-tuple to the head of `ARTICLES = [...]`:

```python
("2026-05-20", "May 20, 2026", "Topic · Topic · Topic",
 "Title — same as above",
 "https://cloudcdn.pro/stocks/images/<banner>.webp",
 "<banner alt>",
 "<excerpt — same as above>",
 "/<slug>/index.html"),
```

Then re-run:

```bash
python3 scripts/generators/gen_articles.py
./build.sh
```

### Step 5 — Translate the 27 stubs

```bash
python3 scripts/editorial/translate_post.py <slug> --list-stubs
```

Prints every locale where the body still carries the
`<!-- translation-stub -->` marker. In Claude Code, walk through them
in this order (highest-traffic first):

```
fr es de it pt-br nl ja zh-hans zh-hant ko ar ru pl cs uk
ro tr he hi bn id vi th fil ha yo sv
```

For each path Claude prints, **rewrite the entire body** (preserving
frontmatter as-is), following the rules in
[`.claude/commands/publish-today.md`](../.claude/commands/publish-today.md).
Summary:

- Executive register. No hype. No "delve into", "embark on", "in
  conclusion".
- Markdown structure load-bearing. Headings, blockquotes, bullet
  lists, tables, code blocks — same nesting, same order, only the
  prose between markup changes.
- Citation links `[Source name](url "Source title")` — translate the
  visible text and `title` attribute, **never** the URL.
- Numbers, percentages, dates, statistics are facts. Translate the
  surrounding sentence, never the number.
- Acronyms (BIS, CPMI, FSB, NIST, NCSC, ISO 20022, RTGS, …) stay
  English on first mention with native expansion in parentheses if
  one is standard.
- Frontmatter `title`/`subtitle`/`description`/`keywords`/`twitter_*`
  fields get translated too. Match SEO intent.
- Don't invent statistics, sources, or claims the EN source doesn't make.

Idempotent — re-running `--list-stubs` between rounds is safe.

### Step 6 — Re-validate

```bash
./build.sh
```

Exit 0 means every CI gate passes. If a gate fails, see [Failure
modes](#failure-modes).

### Step 7 — Signed commit + push

```bash
today=$(date -u +%F)
slug=$(basename _posts/${today}-*.md .md)
title=$(grep -oE '^title: *"[^"]+"' "_posts/${slug}.md" | head -1 | sed 's/title: *"//;s/"$//' | head -c 80)
git add -A
git commit -S -m "content(${today}): ${title} + 27 translations"
git push
```

Cloudflare Pages picks up `main` and deploys automatically. Verify
within ~3 minutes:

```bash
curl -sI "https://sebastienrousseau.com/${slug}/" | head -3
```

The `last-modified` header should be recent.

## The frontmatter contract

Required keys (everything else is optional / has a sensible default):

```yaml
title: "Headline (publishable, 50-65 chars)"
subtitle: "One sentence framing, 120-180 chars"
description: "Two-sentence SEO summary, 155-250 chars"
date: "Month Day, Year"
keywords: "twenty-or-so, comma, separated, terms"
tags: "comma, separated, public-facing, tags"
banner: "https://cloudcdn.pro/stocks/images/<filename>.webp"
banner_alt: "WCAG alt text describing the article topic"
banner_width: "1425"
banner_height: "571"
layout: "report"            # or "page" / "article"
schema: "FAQPage, Article"  # JSON-LD types to emit
language: "en-GB"
locale: "en_GB"
hreflang: "en"
permalink: "https://sebastienrousseau.com/<slug>"
id:        "https://sebastienrousseau.com/<slug>"
url:       "https://sebastienrousseau.com/<slug>"
```

Plus a handful of social/feed fields (`item_*`, `twitter_*`,
`apple-mobile-web-app-title`, etc.) — copy them from a recent post and
adjust the strings. The translation scaffolder will localise them per
locale.

## Editorial decisions you make every day

Three choices the pipeline can't make for you:

| Decision | Where |
|----------|-------|
| Which old newsroom-grid card to drop | `_posts/index.md` |
| Which old `/articles/` cards to demote off the featured slot | `scripts/generators/gen_articles.py` |
| Whether the article is a feed item, a project, or a paper (different rotor) | Frontmatter `layout` + which `gen_*.py` regenerates that listing |

The slash command will ask you for the first two before doing anything
destructive.

## Translation flow

### How the scaffolder works

`scripts/editorial/translate_post.py <slug>` is **deterministic** — it never
calls an API. For each non-EN locale it:

1. Computes a target slug. A small per-locale dictionary in `_SLUG_DICT`
   substitutes recurring domain terms (`wholesale → mayorista` for
   ES, `payments → paiements` for FR, etc.). Locales without an entry
   keep the EN slug verbatim — slug shape is valid for the parity
   gate either way.
2. Writes `_posts/<lang>/<target-slug>.md` carrying:
   - the EN frontmatter with `language`, `locale`, `hreflang`, `url`,
     `permalink`, `id` rewritten to point at the localised URL;
   - the EN body wrapped in a `<!-- translation-stub -->` marker so
     re-runs of the script (and `--list-stubs`) know exactly which
     files still need a real translation.
3. Updates `_data/i18n/<lang>/slugs.json` with the EN→native mapping.

It is **idempotent** — files that no longer carry the marker (i.e.
already translated) are left alone. Re-running the script after
translating five locales overwrites the remaining 22 stubs with fresh
stubs (no-op for the translated five).

### How translation itself works

Translation is a human-in-the-loop step in Claude Code on your
laptop, using your **existing Claude subscription**. No
`ANTHROPIC_API_KEY` ever lives in this repo, in CI secrets, in an
`.env`, or anywhere else.

The rules Claude follows when translating are in
[`.claude/commands/publish-today.md`](../.claude/commands/publish-today.md).
That file is the single source of truth — edit it if the
tone-of-voice rules ever change.

Quality control: at the end of each translation, the build re-runs
`test_lang_no_leakage` which flags any EN chrome string that leaked
into a non-EN page. Body content is unrestricted (you can quote
English source material in a translation; the test exempts the
`<main>` region).

| Locale count | Time per article | Cost |

## What gets auto-refreshed (and what doesn't)

### Fully automatic — never touch

| Artifact | Refreshed by |
|----------|--------------|
| `sitemap.xml` (top-level + per-locale) | `shokunin` SSG |
| `rss.xml` / `atom.xml` / `feed.json` (28 of each) | `scripts/generators/build_lang_feeds.py` |
| `news-sitemap.xml` | `shokunin` + `postbuild.shrink_news_sitemap` |
| `llms.txt` / `llms-full.txt` | `scripts/postbuild_lib/output.py` |
| `robots.txt` | `scripts/postbuild_lib/output.py` |
| `/api/agents/index.json` + per-post agent-API JSON | `scripts/generators/build_agent_api.py` |
| `/topics/<topic>/` pages | `scripts/generators/build_topics.py` |
| Search indexes (EN + per-locale) | SSG + `tests/validation/test_search_indexes.py` |
| Schema.org JSON-LD per page | `scripts/postbuild_lib/seo.py` + `schemas.py` |
| Hreflang `<link rel="alternate">` tags | `scripts/postbuild_lib/article_furniture.py` |
| SRI integrity hashes on `_csp/*` + `main.*.js` | `scripts/postbuild.fix_sri` |
| CSP `script-src` hashes for inline JSON-LD | `scripts/postbuild.inject_jsonld_hashes` |
| CDN-transform-wrapped `<img>` URLs | `scripts/postbuild.wrap_cdn_images_in_transform` |
| LCP `<link rel=preload>` aligned to first `<img>` | `scripts/postbuild.inject_lcp_preload` |
| JS + CSS minification | `scripts/postbuild._bulk_minify_js/css` |
| Theme-init script inlined into `<head>` | `scripts/postbuild.inline_theme_init` |

### Editorial — you decide

| Artifact | Updated by |
|----------|------------|
| Homepage "From the desk" newsroom-grid (5 cards) | Hand-edit `_posts/index.md` |
| `/articles/` featured + grid order | Hand-edit `scripts/generators/gen_articles.py` `ARTICLES = [...]` |
| Newsletter subject/preview if you send one | Out-of-pipeline (your ESP) |

### Scaffolded — you fill in

| Artifact | Scaffolded by | You complete via |
|----------|---------------|------------------|
| 27 native-language post bodies | `scripts/editorial/translate_post.py` | Claude Code in `/publish-today` |

## Verification + deployment

After `git push`:

1. **Cloudflare Pages build** — visible at
   `github.com/sebastienrousseau/sebastienrousseau.github.io/actions`.
   Takes ~2 min from push to deploy.
2. **Edge cache warm-up** — the live origin's HTML carries
   `cache-control: max-age=3600`, so a stale edge response can persist
   for up to an hour after deploy. Cache-bust with `?_t=$(date +%s)`
   to confirm the new build is in:

   ```bash
   curl -sS "https://sebastienrousseau.com/<slug>/?_t=$(date +%s)" | head -20
   ```

3. **Lighthouse smoke** (optional, recommended):

   ```bash
   lighthouse "https://sebastienrousseau.com/<slug>/?_t=$(date +%s)" \
     --quiet --chrome-flags="--headless=new --no-sandbox" \
     --form-factor=mobile --throttling-method=simulate \
     --only-categories=performance,accessibility,best-practices,seo \
     --output=json --output-path=/tmp/lh-new-article.json
   ```

   A11y / Best-Practices / SEO should be 1.00; Performance ≥ 0.85.

4. **PSI** (eventually, post cache-warm): https://pagespeed.web.dev/

## Failure modes

Every CI gate, every common failure, every fix.

| Symptom | Cause | Fix |
|---------|-------|-----|
| `publish-daily.sh: nothing to publish` | No `_drafts/<today>-*.md` and no `_posts/<today>-*.md` | Drop a draft with today's date prefix. |
| `test_i18n_parity: missing article translation: <slug>` | A locale's `_data/i18n/<lang>/slugs.json` lacks the EN→native mapping | Re-run `python3 scripts/editorial/translate_post.py <slug>`. The scaffolder is idempotent and only fills in what's missing. |
| `test_hreflang_reciprocity: target does not reciprocate` | A locale's `_posts/<lang>/<slug>.md` file doesn't exist | Same fix — re-run the scaffolder. |
| `test_lang_no_leakage: <string> leaked into <lang>` | A locale's chrome translation is missing for that string | Add the translation to `_data/i18n/<lang>/chrome_patches.json` — the failing-test output names the exact string. |
| `test_csp_strict: missing sha256 token` | A new inline `<script>` or `<style>` block didn't get its sha256 in CSP | `scripts/postbuild.inject_jsonld_hashes` should cover any `<script>` body; check the failing page's actual inline content. |
| `test_sitemap_completeness: page missing from sitemap` | The page rendered to `public/` but the sitemap generator didn't see it | Re-run `./build.sh`. SSG emits the sitemap before postbuild adds the new page; running once more lets it pick up. |
| `test_rtl_safe: physical CSS property` | A new layout has `left:`/`right:`/`margin-left:` instead of `inline-start:`/`inline-end:` | Use logical properties. RTL locales (ar, he) break otherwise. |
| `test_jsonld_localized: inLanguage mismatch` | Translated post's frontmatter `language:` field doesn't match `inLanguage` in the emitted JSON-LD | The scaffolder sets `language: <lang>`; if you hand-edit a frontmatter, keep it consistent. |
| Build exits 0 but `_csp/*.css` SRI fails in browser | GitHub Pages appended a trailing `\n` that the SRI digest didn't account for | Already covered — `_PAGES_TRAILING_NEWLINE` in `scripts/postbuild.py` emits dual digests. If you see this error in 2026+, Pages changed behaviour again. |
| Cloudflare Pages deploy succeeded but `cf-cache-status: HIT` shows old HTML | Edge HTML cache hasn't expired yet | Wait or purge the URL in the Cloudflare dashboard. |
| `git commit -S` hangs | SSH agent has no identity loaded | `ssh-add ~/.ssh/id_ed25519`, retry. |

## Adding a new permanent section

E.g. "I want to add `/talks/` listing all my conference talks."

1. **Create a layout**: `_layouts/talks.html` (clone `_layouts/articles.html`, swap title strings).
2. **Create a generator**: `scripts/gen_talks.py` (clone
   `scripts/generators/gen_articles.py`, change the hard-coded list, change the
   output path to `_posts/talks.md`).
3. **Source page**: `_posts/talks.md` with frontmatter
   `layout: "talks"`, body = "to be replaced by gen_talks.py".
4. **Translate**: each locale needs a translated `talks.md`
   counterpart, and the static-slug map in
   `_data/i18n/<lang>/slugs.json` needs a `talks → <native-word>`
   entry (look at how `articles → articles` / `articles → maqalat` is
   set up).
5. **Wire navigation**: add a "Talks" link to the nav in every layout
   (`_layouts/*.html` and the i18n chrome patches if the label is
   translated).
6. **CI gate**: `test_sitemap_completeness` will start expecting
   `/talks/` to exist on every locale.

`project-docs/ARCHITECTURE.md` covers the deeper system. The above is the minimal
checklist.

## Adding a new language

See [`project-docs/I18N.md`](I18N.md) for the full workflow. Summary:

1. Append a `Language(...)` entry to
   [`scripts/lib/_lang_registry.py`](../scripts/lib/_lang_registry.py) with
   `active=False` initially.
2. Create `_data/i18n/<lang>/` with 11 JSON files (mirror an existing
   locale's structure).
3. Translate all 44 articles + 21 static pages into
   `_posts/<lang>/*.md`.
4. Flip `active=True`, wire the new locale into all 11
   `_layouts/*.html` switcher tables, push.
5. CI's per-locale parity gates enforce that nothing is missing.

## Forking this pipeline for your own site

This whole stack is Apache-2.0. To run your own version:

1. **Fork the repo.** Replace content (`_posts/`, `_drafts/`,
   `_data/`), branding (`_layouts/`, CSS in
   `_layouts/_skeletonic.min.css`), CDN base
   (`scripts/fix_cdn_urls.py:CDN_ROOT`).
2. **Strip the i18n machinery** if you don't need 28 languages:
   delete `_data/i18n/`, `scripts/generators/build_translations.py`,
   `scripts/generators/build_lang_feeds.py`, `scripts/test_i18n_*.py`,
   `_posts/<lang>/` directories. Keep `_lang_registry.py` with only
   `Language("en", …, active=True)`.
3. **Adapt the publishing flow**:
   - `scripts/editorial/publish-daily.sh` will keep working — the
     `translate_post.py` step becomes a no-op when no non-EN locales
     are active.
   - `.claude/commands/publish-today.md` — strip the translation
     section, keep the rest.
   - `project-docs/PUBLISHING.md` (this file) — adapt to your site's tone.
4. **Set up signing**: configure `commit.gpgsign=true` against your
   SSH or GPG key.
5. **Wire deployment**: point your GitHub Pages / Cloudflare Pages /
   Netlify / whatever at `main`. The existing build expects
   `docs/` → Pages.

Open an issue if you hit something that's hard-coded to
`sebastienrousseau.com` — there are a few CDN-host strings and a
canonical-URL constant that need to become config.
