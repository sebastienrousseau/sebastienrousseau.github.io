Àkàndé: GPT-Powered Voice Assistant for Executives

Arquitetura de um assistente de voz Python de código aberto: Whisper, GPT-4, cache SQLite e fpdf2

Resumo executivo / Pontos principais

  • Àkàndé ⧉ é um assistente de voz Python de código aberto que encadeia OpenAI Whisper para conversão de fala em texto, completions de chat GPT-4, um cache de respostas SQLite local e exportação PDF com fpdf2 em um único fluxo de trabalho por voz que não requer armazenamento em nuvem nem pesos de modelo de IA local.
  • O cache SQLite armazena hashes SHA-256 de strings de consulta normalizadas mapeados para o texto bruto das respostas API; acertos de cache não custam nenhum token e retornam em menos de 10 ms, tornando consultas repetidas (como revisar uma decisão tomada anteriormente em uma reunião) essencialmente gratuitas.
  • A conversa multi-turno é mantida construindo a lista messages em memória e passando-a a cada chamada à API Chat Completions — o modelo recebe o histórico completo da sessão para poder se referir a trocas anteriores, ao custo de um uso de tokens incrementalmente crescente por turno.
  • A geração de resumos PDF serializa a lista messages da sessão em um documento fpdf2 formatado: os turnos do usuário e do assistente são rotulados, carimbos de data/hora são inseridos e a paginação automática lida com sessões de qualquer comprimento; o arquivo é gravado no sistema de arquivos local, não enviado.
  • Fronteira de privacidade: apenas a consulta ativa (e o histórico da sessão até o limite da janela de contexto) sai do dispositivo — nenhuma gravação de áudio, nenhuma transcrição e nenhuma resposta em cache é enviada a qualquer serviço remoto além da API OpenAI.

Àkàndé ⧉ é um assistente de voz Python de código aberto construído em torno de três componentes modulares: OpenAI Whisper para reconhecimento de fala, a API GPT-4 Chat Completions para compreensão e geração de linguagem, e um banco de dados SQLite local para cache de respostas e persistência de sessão. O resultado é um fluxo de trabalho por voz executável em um laptop sem pesos de modelo local, infraestrutura de armazenamento offline ou pilha de contêineres.

Este artigo descreve a arquitetura técnica de cada componente, as decisões de design em torno do cache e do contexto multi-turno, e o pipeline de exportação PDF.

Visão geral do pipeline #

Uma única interação com Àkàndé segue esta sequência:

  1. Captura de áudio — o usuário fala; o aplicativo grava o áudio em um arquivo WAV temporário usando sounddevice ou uma biblioteca de áudio compatível.
  2. Fala para texto — o arquivo WAV é enviado a openai.audio.transcriptions.create() (API Whisper); a transcrição é retornada como uma string simples.
  3. Busca no cache — a transcrição é normalizada (minúsculas, espaços comprimidos) e submetida a hash SHA-256; o hash é buscado na tabela SQLite local response_cache.
  4. Chamada API ou acerto de cache — em caso de falha, a transcrição é adicionada à lista messages da sessão e enviada a openai.chat.completions.create(); o texto da resposta é armazenado no cache.
  5. Texto para fala — o texto da resposta é convertido em áudio usando o endpoint openai.audio.speech.create() (TTS) ou uma biblioteca TTS local, e reproduzido.
  6. Exportação PDF (sob demanda) — a lista completa messages é serializada em um documento fpdf2 formatado e gravada em disco.

Integração OpenAI: Chat Completions e Whisper #

Àkàndé usa o SDK Python openai tanto para reconhecimento de fala quanto para geração de texto. A chamada de transcrição Whisper:

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

A chamada Chat Completions mantém uma lista messages com escopo de sessão:

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

O prompt do sistema é adicionado uma única vez no início da sessão e controla a persona de Àkàndé, o formato de saída e quaisquer restrições específicas do domínio:

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

Definir temperature=0.2 troca variação criativa por determinismo — importante para consultas factuais como lembrar uma decisão tomada anteriormente na sessão.

Cache de respostas SQLite #

O esquema do cache é mínimo:

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

O caminho de leitura e escrita:

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

INSERT OR REPLACE garante que uma resposta em cache seja atualizada se a mesma consulta for enviada após uma atualização do modelo. Uma consulta de remoção baseada em TTL (DELETE WHERE created_at < ?) pode ser agendada na inicialização para limitar o tamanho do cache.

Desempenho dos acertos de cache: uma busca SQLite em um SSD local retorna em menos de 1 ms para tabelas com até ~100.000 linhas. A latência de ida e volta de uma chamada API GPT-4 em tempo real é tipicamente de 600–900 ms para respostas curtas. Para um briefing diário com algumas consultas repetidas, o cache elimina a maioria das chamadas API após a primeira sessão.

Geração de resumos PDF #

A exportação PDF usa fpdf2, uma biblioteca Python PDF mantida sem dependências binárias:

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell() lida com quebra de linha e quebras de página automáticas, de modo que sessões de qualquer comprimento produzem um documento bem formatado sem lógica de paginação manual. O resultado é um arquivo compatível com PDF/A sem fontes incorporadas além das métricas padrão Helvetica.

Modelo de privacidade #

A fronteira de privacidade em Àkàndé é definida por três fatos:

  1. O áudio é enviado à API Whisper via HTTPS e não é retido pela OpenAI além da chamada API (de acordo com a política de uso de dados da API OpenAI vigente em fevereiro de 2024).
  2. As chamadas à API Chat Completions transmitem a lista messages da sessão — que pode conter o histórico completo da conversa para sessões multi-turno.
  3. O banco de dados SQLite e os arquivos PDF residem inteiramente no sistema de arquivos local; nenhuma sincronização em segundo plano com qualquer serviço de nuvem ocorre.

Para casos de uso executivos envolvendo tópicos sensíveis — discussões de M&A, questões de pessoal, estratégia regulatória — o histórico da sessão transmitido à API deve ser revisado em relação à política de uso de IA da organização antes da implantação. O limite max_tokens no prompt do sistema pode ser usado para evitar a transmissão inadvertida de contexto que ultrapassa o escopo de divulgação pretendido.

Perguntas frequentes #

O Àkàndé retém o histórico de conversas após o encerramento da sessão? A lista messages em memória é descartada quando o processo encerra. O histórico de conversas só é retido se o usuário acionar uma exportação PDF ou se uma camada de persistência personalizada for adicionada. O cache SQLite armazena hashes de consultas e texto de respostas, não o contexto completo da conversa.

Como o cache lida com consultas semelhantes, mas não idênticas? O cache usa hash de correspondência exata na string de consulta normalizada. Duas consultas que diferem em uma única palavra produzirão hashes diferentes e resultarão em chamadas API separadas. O cache semântico (usando similaridade de embedding para corresponder a consultas quase duplicadas) exigiria uma etapa adicional de busca vetorial e não faz parte da implementação base.

Qual modelo GPT o Àkàndé usa por padrão? O padrão é gpt-4-turbo-preview a partir de fevereiro de 2024. O nome do modelo é um parâmetro de configuração, portanto qualquer modelo de chat completion OpenAI pode ser substituído. Mudar para gpt-3.5-turbo reduz o custo da API em aproximadamente 20× por token, mas reduz a qualidade de raciocínio para consultas complexas de múltiplas etapas.

O formato de exportação PDF pode ser personalizado? Sim. A função de exportação fpdf2 aceita a lista messages como sua única entrada necessária, portanto fonte, margens, tamanho de página, conteúdo do cabeçalho e rotulagem podem ser alterados editando a função de exportação. fpdf2 também suporta a adição de imagens, tabelas e fontes Unicode, permitindo layouts de documentos mais ricos para organizações com requisitos específicos de identidade visual.
