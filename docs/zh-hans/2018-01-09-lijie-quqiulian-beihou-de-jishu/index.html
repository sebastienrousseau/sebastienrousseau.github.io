执行摘要 / 核心要点

  • 问题所在。 数字现金需要解决双重支付问题：在没有可信清算机构的情况下，防止同一单位被消费两次。Bitcoin 2008 年的白皮书通过用密码学证明和分布式共识取代可信中介解决了这一问题（Nakamoto, 2008）。
  • 数据结构。 区块链是一个区块的链表，每个区块头都包含前一个区块头的 SHA-256 哈希值。哈希链使历史记录只可追加：修改任何过去的区块都会使此后每个哈希值失效，迫使攻击者重新完成所有后续的 proof-of-work。
  • Merkle 树。 区块内的交易被哈希化为二叉 Merkle 树。存储在区块头中的根哈希值允许高效验证任何单笔交易，无需下载完整区块——这是轻量级 SPV 客户端的基础。
  • Ethereum 的扩展。 Ethereum 的黄皮书（2014 年）引入了 EVM——一个在每个全节点上运行的确定性堆栈机器。智能合约是部署到链上的字节码；它们在所有节点上以相同方式执行并以原子方式结算，用自我执行代码取代了可信中介（Wood, 2014）。
  • 实际意义。 自 2017 年以来部署的每一个代币化资产、稳定币和 DeFi 协议都运行在这些基础之上。理解哈希链、Merkle 树和 EVM 执行模型，是使用任何基于 Ethereum 系统的前提条件。

区块链解决的问题 #

在 Bitcoin 出现之前，数字支付需要一个可信中介——银行、支付处理商或清算所——来防止双重支付。如果 Alice 向 Bob 发送代表 10 英镑的数字文件，文件本身没有任何东西能阻止她向 Carol 发送一份相同的副本。每个现有系统中的解决方案都是中心化记账：银行的账本显示钱已被花费，因此无法再次花费。

Bitcoin 的贡献在于用分布式账本取代了那个可信账本，其中所有交易的记录在数千个独立节点上被复制。节点间的相互不信任通过两种机制转化为安全性：

  1. 密码学链接。 每个交易区块都包含前一个区块的哈希值。哈希函数是一种单向确定性映射：给定任何输入，函数产生固定长度的输出，即使输入改变一个比特也会产生完全不同的输出。这意味着对历史区块的任何修改都会使其后的每个区块失效。

  2. Proof-of-work 共识。 添加新区块需要找到一个 nonce 值，使区块的哈希值低于目标阈值——找到它在计算上昂贵，验证它则极其廉价。这使得重写历史的代价与被修改区块的深度成正比，因为攻击者必须从该区块到链尖重新完成所有的 proof-of-work。

这种组合意味着，具有最多累积 proof-of-work 的最长链，从其构造上来说，就是由诚实参与者消耗真实资源所维护的那条链。

密码学构建块 #

区块链技术将三种预先存在的密码学原语组合成一种新的架构：

SHA-256 哈希函数 #

SHA-256（安全哈希算法 256 位）是由 NIST 标准化的 SHA-2 系列成员。它接受任意长度的输入，并产生 256 位的输出。区块链使用的关键特性：

  • 确定性。 相同的输入始终产生相同的输出。
  • 原像抗性。 给定哈希输出，在计算上不可行重建输入。
  • 雪崩效应。 改变输入的一个比特会改变大约一半的输出比特，使暴力搜索效率低下。
  • 碰撞抗性。 在计算上不可行找到产生相同哈希值的两个不同输入。

Bitcoin 将 SHA-256 应用两次（SHA-256d），以增强对长度扩展攻击的安全性。Ethereum 使用 Keccak-256，一种 SHA-3 决赛入围变体。

Merkle 树 #

Merkle 树是哈希值的二叉树。每个叶节点是一笔交易的哈希值。每个内部节点是其两个子节点的哈希值。根节点——Merkle 根——将区块中的所有交易汇总为存储在区块头中的单个 32 字节值。

实际意义：要验证特定交易是否包含在区块中，只需 log₂(n) 个哈希值，而不是所有 n 笔交易。对于包含 2,000 笔交易的区块，验证只需要 11 个哈希值而非 2,000 个——这是轻量级客户端简化支付验证（SPV）的基础。

数字签名（ECDSA） #

Bitcoin 和 Ethereum 中的交易授权使用基于 secp256k1 曲线的椭圆曲线数字签名算法（ECDSA）。私钥对交易签名；任何节点都可以使用相应的公钥验证签名，而无需知道私钥。这确保只有私钥持有者才能授权从某个地址进行花费。

Ethereum 地址是公钥 Keccak-256 哈希值的最后 20 个字节——这种派生方式使地址紧凑且可移植，同时在密码学上与密钥对绑定。

Bitcoin 区块链的工作原理 #

一个 Bitcoin 区块包含三个逻辑组件：

区块头——80 字节，包含：协议版本、前一个区块头的哈希值、交易的 Merkle 根、Unix 时间戳、当前难度目标和 nonce。矿工不断迭代 nonce（有时还有时间戳或 coinbase 交易中的额外 nonce），直到区块头的双重 SHA-256 哈希值低于难度目标。

交易列表——区块中包含的有序交易集合。coinbase 交易（第一笔）将区块奖励和交易费分配给矿工的地址。

链——区块头的链接。链中累积的 proof-of-work（生产每个区块所做的所有工作总和）决定哪个分叉是规范链。节点始终遵循具有最多累积工作量的链。

Bitcoin 的目标区块时间为 10 分钟。难度每 2,016 个区块（约两周）调整一次，以在总网络哈希率变化时维持该目标。

Ethereum 的可编程层 #

Ethereum 将 Bitcoin 的交易模型从"转移价值"泛化为"执行代码"。主要新增内容：

以太坊虚拟机（EVM）。 一个 256 位字、基于堆栈的虚拟机，在所有全节点上确定性地执行。每个操作码都有明确的 gas 成本。计算受区块 gas 限制约束，防止无限循环使网络停止。所有节点在相同状态下执行相同字节码必须产生相同输出——这种对执行的共识使智能合约无需信任。

账户。 Ethereum 有两种账户类型：由私钥控制的外部拥有账户（EOA），以及代码存储在链上的合约账户。发送到合约地址的交易会触发合约字节码的执行。

状态。 Ethereum 的全局状态是地址到账户状态（nonce、余额、存储、代码哈希）的映射。状态根——所有账户状态的 Merkle Patricia 前缀树——包含在每个区块头中，允许高效证明任何区块高度下任何账户的状态。

Gas。 用户为每个 EVM 操作支付 gas（以 ETH 计）。Gas 有两个功能：它补偿矿工/验证者的计算，并限制单笔交易可消耗的资源，防止通过昂贵操作进行拒绝服务攻击。

用 Solidity 编写智能合约 #

Solidity 是一种静态类型、面向合约的语言，可编译为 EVM 字节码。一个最小化的代币合约说明了核心概念：

pragma solidity ^0.8.0;

contract MyToken {
    string public name;
    string public symbol;
    uint8 public decimals;
    uint256 public totalSupply;
    mapping(address => uint256) public balanceOf;

    event Transfer(address indexed from, address indexed to, uint256 value);

    constructor(
        string memory _name,
        string memory _symbol,
        uint8 _decimals,
        uint256 _totalSupply
    ) {
        name = _name;
        symbol = _symbol;
        decimals = _decimals;
        totalSupply = _totalSupply;
        balanceOf[msg.sender] = _totalSupply;
    }

    function transfer(address _to, uint256 _value) external returns (bool) {
        require(balanceOf[msg.sender] >= _value, "Insufficient balance");
        balanceOf[msg.sender] -= _value;
        balanceOf[_to] += _value;
        emit Transfer(msg.sender, _to, _value);
        return true;
    }
}

关键观察：mapping(address => uint256) 是 EVM 存储布局，而不是内存数据结构——读写都需要消耗 gas。require 在失败时回滚整个交易，返还未使用的 gas。event Transfer 发出一个日志，链下索引器使用该日志追踪转账，而无需重新读取完整状态。constructor 在部署时运行一次；后续调用转到具名函数。

ERC-20 标准规范了同质化代币的通用接口——transfer、transferFrom、approve、allowance、balanceOf、totalSupply——允许任何 ERC-20 兼容代币与任何支持 ERC-20 的交易所或钱包协作，无需自定义集成。

从账本到金融基础设施 #

此处描述的区块链原语——哈希链、Merkle 树、EVM 和 ERC-20——在 2018 年至 2026 年间成为更广泛金融应用的基础：

去中心化金融（DeFi）。 借贷协议（Compound、Aave）、自动做市商（Uniswap）和收益聚合器都以 EVM 智能合约形式运行。它们用自我执行的代码和链上流动性池取代了传统金融中介的清算、托管和结算功能。

代币化资产。 中央银行和商业银行正在 EVM 兼容链的许可变体上试点代币化存款、代币化债券和代币化货币市场基金。其底层机制——哈希安全的状态转换、原子结算、可编程转账规则——是 2014 年 Ethereum 架构的直接后代。

央行数字货币。 Bank of England 的批发 CBDC 研究、ECB 的数字欧元计划以及 Project Agorá 都在探索源自或兼容 Bitcoin 和 Ethereum 基础设计的 DLT 架构。即使许可和治理模型与公共区块链完全不同，共识和哈希链结构仍然具有重要意义。

从 2008 年 Bitcoin 白皮书到 2026 年代币化金融的旅程跨越了二十年，但它运行在一个连贯的技术脉络上。理解 SHA-256 哈希链如何强制执行不可变性、Merkle 树如何实现高效验证，以及 EVM 如何以原子方式执行智能合约，是评估区块链在受监管金融服务中能做什么和不能做什么的先决条件。

常见问题 #

区块链与分布式数据库有什么区别？

传统的分布式数据库为了可用性和性能而在节点间复制数据，但信任是中心化的——管理员可以修改记录。区块链通过哈希链和共识使篡改在计算上代价高昂：修改任何历史记录需要重新完成所有后续的 proof-of-work 或 proof-of-stake，并说服网络接受修改后的分叉。其显著特性是通过密码学和激励设计而非访问控制来强制执行的防篡改性。

Ethereum 为什么使用 Keccak-256 而不是 SHA-256？

Ethereum 采用 Keccak-256（NIST 标准化调整前的 SHA-3 决赛入围算法），部分原因是其设计者希望独立于 Bitcoin 已经依赖的 SHA-2 系列。Keccak 还具有不同的代数特性，使其对某些 EVM 操作具有吸引力。对开发者的实际影响是，Ethereum 地址派生和存储槽哈希使用 Keccak-256，而不是 Bitcoin 中的 SHA-256d。

EVM 中的"gas"防止什么？

Gas 防止两类攻击。首先，它防止通过计算昂贵的操作进行拒绝服务攻击：每个操作码都消耗 gas，因此攻击者无法强迫网络免费执行无限循环。其次，区块 gas 限制限制了每个区块的总计算量，确保区块验证时间对全节点保持有界且可预测。没有 gas，单个合约调用可能通过执行无限计算使网络停止。

proof-of-stake 与 proof-of-work 相比如何改变安全模型？

在 proof-of-work 中，安全性由能源消耗提供：攻击链需要控制网络超过 50% 的哈希率，这意味着控制超过 50% 的物理硬件和电力。在 proof-of-stake 中（Ethereum 自 2022 年合并后采用），安全性由经济质押提供：验证者锁定 ETH 作为抵押品，如果他们签署相互冲突的区块，抵押品将被削减。51% 攻击需要获取并冒险使用超过 50% 的所有质押 ETH——这是资本成本而非硬件和能源成本。在理性验证者更倾向于费用收入而非资本损失的假设下，安全模型不同但在经济上具有数学上的可比性。
