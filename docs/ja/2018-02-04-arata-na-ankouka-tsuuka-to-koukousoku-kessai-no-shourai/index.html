新たな暗号資産と高速決済ソリューションの公開

Ethereum ERC-223スマートコントラクトとプログラマブル・ペイメントトークンによる2018年初頭の実験的取り組み。

TL;DR. 2018年初頭、EXTCプラットフォームはEthereum ERC-223スマートコントラクトを用いた高速な国際送金の可能性を探求しました——後の分散型金融が発展させる先駆的な設計図です。

エグゼクティブサマリー / 主要論点

  • 核心的な仮説。 Ethereumのスマートコントラクトは、国際送金におけるコルレス銀行のリレー方式を代替し、数日ではなく数秒で決済を完了させ、3〜7%の手数料層を排除できる（世界銀行、2018年）。
  • ERC-223固有の貢献。 この標準は、スマートコントラクトにtokenFallback関数の実装を義務付けることで、ERC-20のサイレント・トークン消失という欠陥を修正しました。失敗した送金はトークンを不可逆的に焼失させるのではなくリバートされるようになります（Ethereum EIPs）。
  • EXTCの決済プリミティブ。 トークン設計は、単一アトミック送金、時間指定の定期払い指示、複数署名による法人向け一括送金、即時担保付きマイクロローンを支援するものでした——すべて決済機関なしで実現します。
  • 実験が明らかにしたこと。 技術設計は一貫していましたが、2018年のEthereumメインネットは毎秒約15トランザクションを処理するに過ぎませんでした。スケールでの決済処理量には、当時まだ本番稼動に達していなかったレイヤー2ソリューションが必要でした。
  • 遺産。 EXTCの建築的アイデア——プログラマブルマネー、アトミック決済、コンプライアンス組み込み型トークンロジック——は、後のDeFiプロトコル、CBDC設計、トークン化預金フレームワークに再び姿を現しました。

課題：2018年の国際送金 #

2018年初頭の国際決済は、構造的に低速、高コスト、かつ不透明でした。英国から東南アジアへの個人送金には、通常2〜4行のコルレス銀行が介在し、それぞれが手数料を徴収して決済チェーンに1日を追加していました。世界銀行の「Remittance Prices Worldwide」データベースによれば、2018年第1四半期における200ドルの送金コストの世界平均は6.9%に上っていました。

暗号資産は、ピアツーピアのデジタルキャッシュが技術的に実現可能であることをすでに証明していました。Bitcoinは世界中で約10分以内にトランザクションを決済し、Ethereumのプログラマブル層はスマートコントラクトを加えました——送金そのものに支払いルールを直接エンコードできる、自己実行型のコードです。オンチェーンで技術的に可能なことと、レガシーなコルレス銀行が提供するものとの乖離が、EXTCが参入した設計空間でした。

技術的基盤：ERC-20とその欠陥 #

ERC-20標準は、Ethereum Improvement Proposal 20において正式化され、代替可能トークンの標準インターフェースを定義しています。balanceOf、transfer、transferFrom、approve、allowanceといった関数群です。2018年初頭、ERC-20は支配的なトークン標準となっており、数百のトークンがメインネット上にデプロイされていました。

しかしERC-20には構造的な問題がありました。標準のtransfer関数を使用してスマートコントラクトアドレスに直接トークンを送信した場合、そのコントラクトは着信送金を検知する手段も、それに応じて行動する手段も持っていませんでした。このようにして送信されたトークンは永久にロックされます。Ethereumコミュニティの推計では、2018年半ばまでに数百万ドル相当のERC-20トークンがこの方法で失われていました。

EthereumのGitHubイシュートラッカーでDexaranが提案したERC-223は、受信コントラクトにtokenFallback(address _from, uint _value, bytes _data)関数の実装を要件として追加することで、この問題に対処しました。受信コントラクトがtokenFallbackを実装していない場合、送金はリバートされ、トークンは送信者に返還されます。これによりERC-223の送金はアトミックになりました。つまり、コントラクトがトークンを受け入れてロジックを実行するか、トランザクションが明確に失敗するかのいずれかです。

EXTCトークンの設計 #

Express Transaction Creditsトークンは、5つのコア属性を中心に設計されました。

  • 名称、シンボル、小数点以下桁数。 標準的なERC-223の識別フィールドで、サブセント精度のために小数点以下18桁を採用。
  • 総供給量。 ミント時に固定され、失われたまたは未請求のトークンの再発行ができないため、EXTCはデフレ資産となります。
  • 残高と送金。 標準的な読み取りおよび書き込み関数に、ERC-223のtokenFallback要件を追加。
  • マルチシグネチャーサポート。 法人向け一括送金には、実行前に複数の認可アドレスからの共同署名が必要であり、中央集権的な決済機関なしに監査証跡を提供します。
  • 時間ロック送金。 定期払い指示プリミティブにより、EXTCは将来の支払いをスケジュールできます——従来の銀行送金が外部指示によって達成していた機能です。

プラットフォームが対象とした決済プリミティブ #

EXTCのアーキテクチャは、レガシーシステムが非効率に処理していた4つの具体的な決済ワークフローを代替するよう設計されていました。

単一アトミック決済 ——1回限りの送金で、単一のEthereumトランザクションで決済されます。2018年のメインネットでは通常15〜30秒以内。

時間指定の定期払い指示 ——時間ロックされたスマートコントラクト呼び出しとしてエンコードされた反復送金で、定期的な指示を受け取って再実行する銀行の必要性を排除します。

法人向け一括送金 ——1トランザクションで複数の受取人への一括決済を実現し、個々の送金ごとにマルチシグネチャー認証が必要で、コストとカウンターパーティリスクを削減します。

担保付き即時ローン ——借り手がスマートコントラクトにEXTCトークンを担保としてロックし、コントラクトが受領時に自動的にローン資金を放出します。信用委員会や審査遅延は不要です。

実験が明らかにしたこと #

EXTCの設計は技術的に一貫していました。ERC-223の基盤は支配的なトークン標準の最も重大な安全上の欠陥を解決し、決済プリミティブはコルレス銀行が非効率に処理していた実際のワークフローに直接対応していました。

実用上の制約はEthereumのスループットでした。2018年第1四半期、メインネットはブロックあたり約800万のガス上限で毎秒平均15トランザクションを処理していました。グローバルな送金量のわずかな割合でも処理する決済ネットワーク——世界銀行は2017年に2億7,000万人の移民が本国送金を行っていると推計——は、数分でメインネットを飽和させていたでしょう。

レイヤー2スケーリングソリューション、特にステートチャネルと後にロールアップ技術となるものの初期バージョンは、2018年に活発な研究が進んでいましたが、本番稼動には至っていませんでした。Lightning Networkは2018年1月にBitcoinメインネット上で多くの注意書きとともにようやく立ち上げられたばかりでした。ブロックチェーンベースの決済ネットワークがコルレス銀行規模で動作するための技術的前提条件は、まだ存在していなかったのです。

生き残ったアイデア #

EXTCおよび同時期のペイメントトークンプロジェクトから生まれたいくつかのアーキテクチャ概念は、その後の発展により実証されました。

プログラマブルマネー ——送金ロジックに直接支払いルールをエンコードすること——は、それぞれ2018年と2020年に立ち上げられたCompoundやAaveなど、DeFiレンディングプロトコルの中心的な機能となりました。

決済機関なしのアトミック決済 ——送金が完全に成功するかリバートするかのいずれかという性質——は、イングランド銀行や欧州中央銀行を含む中央銀行が検討するトークン化預金フレームワークやホールセールCBDCアーキテクチャの設計要件となっています。

コンプライアンス組み込み型トークン ——トークンコントラクト自体に送金制限と報告義務をエンコードすること——は、ERC-1400（セキュリティトークン）などの規制対象トークン標準や、Project Agoráおよび類似の複数中央銀行によるトークン化実験のコンプライアンス層設計に現れています。

EXTC実験は本番規模には達しませんでしたが、提起した問いかけ——プログラマブル決済、アトミック送金、自己執行型の支払いルールについて——は2018年において正しい問いでした。それらに答えるために必要なインフラが成熟するには、さらに5年を要することになります。

よくある質問 #

ERC-223とは何か、EXTCがERC-20ではなくそれを採用した理由は？

スマートコントラクトアドレスに直接送信されたERC-20トークンは、コントラクトが着信送金を検知する手段を持たないため、検知されることなく失われます。ERC-223は、受信コントラクトにtokenFallback関数の実装を義務付けることでこの問題を修正しました。この関数が存在しない場合、送金はトークンを焼失させるのではなくリバートされます。EXTCはすべてのオンチェーン送金をアトミックかつ安全なものとするためにERC-223を採用しました。

初期のペイメントトークンプロジェクトがコルレス銀行の代替へとスケールできなかった理由は？

2018年のEthereumメインネットは毎秒約15トランザクションを処理していました。貿易金融や法人決済を除いたグローバルな送金量だけでも、毎秒数万件のトランザクションを必要とします。そのスループットに到達するために必要なレイヤー2スケーリングインフラは、2021〜2023年まで本番稼動には至りませんでした。

EXTCの背後にあるアイデアはその後どうなったか？

コアとなる概念——プログラマブルな支払いルール、アトミック決済、コンプライアンス組み込み型トークンロジック——はDeFiプロトコル、規制対象のセキュリティトークン標準（ERC-1400）、中央銀行デジタル通貨研究に採用されました。現在、商業銀行がパイロットを進めるトークン化預金フレームワークは、EXTCのような初期のペイメントトークン実験が最初に提起した設計上の問いに直接遡ります。

2018年のEXTC設計と2026年のトークン化預金提案との比較は？

決済モデルは類似しています——分散型台帳上でアトミックに送金される金銭的請求を表すトークン。主な相違点は次の通りです。（1）2026年のトークン化預金は無記名トークンではなく商業銀行負債である。（2）公開メインネットではなく、規制監督のある許可制またはハイブリッド台帳上で動作する。（3）コンプライアンスと本人確認は、参加者任せではなくプロトコル層で実施される。
