Understanding the Technology behind Blockchain

エグゼクティブサマリー / 主なポイント

  • 問題。 デジタル現金は二重支払い問題を解決する必要があります。信頼できるクリアリングハウスなしに、同じ単位が2回支払われることを防ぐ問題です。Bitcoinの2008年のホワイトペーパーは、信頼できる仲介者を暗号学的証明と分散コンセンサスに置き換えることでこれを解決しました（Nakamoto, 2008）。
  • データ構造。 ブロックチェーンは、各ブロックヘッダーが前のヘッダーのSHA-256ハッシュを含むブロックのリンクリストです。ハッシュチェーンにより履歴は追記専用になります。過去のブロックを変更すると以降のすべてのハッシュが無効化され、攻撃者はすべての後続のproof-of-workをやり直すことを余儀なくされます。
  • Merkle tree。 ブロック内のトランザクションはバイナリMerkle treeにハッシュ化されます。ブロックヘッダーに格納されたルートハッシュにより、ブロック全体をダウンロードせずに個々のトランザクションを効率的に検証できます — 軽量SPVクライアントの基盤です。
  • Ethereumの拡張。 Ethereumのイエローペーパー（2014年）はEVM — すべてのフルノードで実行される決定論的なスタックマシン — を導入しました。スマートコントラクトはチェーンにデプロイされたバイトコードです。すべてのノードで同一に実行され、アトミックに決済されます（Wood, 2014）。
  • 実践的意義。 2017年以降にデプロイされたすべてのトークン化資産、ステーブルコイン、DeFiプロトコルはこれらの基盤の上で動作しています。ハッシュチェーン、Merkle tree、EVMの実行モデルを理解することは、Ethereumベースのシステムを扱うための前提条件です。

ブロックチェーンが解決した問題 #

Bitcoin以前、デジタル支払いには二重支払いを防ぐために信頼できる仲介者 — 銀行、決済処理業者、またはクリアリングハウス — が必要でした。アリスが£10を表すデジタルファイルをボブに送った場合、ファイル自体には彼女が同一のコピーをキャロルに送ることを止めるものは何もありませんでした。既存のすべてのシステムの解決策は集中型の記録管理でした。銀行の台帳がお金は使われたと示すため、再び使うことはできませんでした。

Bitcoinの貢献は、その信頼できる台帳を、すべてのトランザクションの記録が何千もの独立したノードに複製される分散型のものに置き換えることでした。ノード間の相互不信は2つのメカニズムを通じてセキュリティに変換されました：

  1. 暗号学的連結。 各トランザクションブロックには前のブロックのハッシュが含まれています。ハッシュ関数は一方向の決定論的マッピングです。任意の入力に対して、関数は固定長の出力を生成し、入力の1ビットを変更するだけでまったく異なる出力が生成されます。これは過去のブロックへのいかなる変更もそれ以降のすべてのブロックを無効にすることを意味します。

  2. proof-of-workコンセンサス。 新しいブロックを追加するには、ブロックのハッシュが目標しきい値を下回るようなnonce値を見つける必要があります — 見つけるのは計算コストが高く、検証するのは計算コストが低い。これにより、攻撃者はそのブロックからチェーンの先端までのすべてのproof-of-workをやり直す必要があるため、変更されるブロックの深さに比例して履歴の書き換えコストが高くなります。

この組み合わせにより、最も累積proof-of-workを持つ最長チェーンは、その構造上、実際のリソースを費やす誠実な参加者によって維持されるものになります。

暗号学的ビルディングブロック #

ブロックチェーン技術は3つの既存の暗号学的プリミティブを新しいアーキテクチャに組み合わせています：

SHA-256ハッシュ関数 #

SHA-256（Secure Hash Algorithm 256ビット）はNISTによって標準化されたSHA-2ファミリーのメンバーです。任意長の入力を受け取り、256ビットの出力を生成します。ブロックチェーン利用における主要な特性：

  • 決定論的。 同じ入力は常に同じ出力を生成します。
  • 原像抵抗性。 ハッシュ出力が与えられても、入力を再構築することは計算上不可能です。
  • アバランシェ効果。 入力の1ビットを変更すると、出力ビットの約半分が変化し、ブルートフォース検索を非効率にします。
  • 衝突耐性。 同じハッシュを生成する2つの異なる入力を見つけることは計算上不可能です。

BitcoinはLength Extension攻撃に対する追加のセキュリティのためにSHA-256を2回適用します（SHA-256d）。EthereumはSHA-3の最終候補変種であるKeccak-256を使用します。

Merkle Tree #

Merkle treeはハッシュのバイナリツリーです。各リーフノードはトランザクションのハッシュです。各内部ノードはその2つの子のハッシュです。ルート — Merkleルート — はブロック内のすべてのトランザクションをブロックヘッダーに格納された単一の32バイト値に要約します。

実践的な結果：特定のトランザクションがブロックに含まれていることを検証するには、n個のトランザクション全てではなくlog₂(n)個のハッシュだけが必要です。2,000のトランザクションを持つブロックの場合、検証には2,000ではなく11のハッシュが必要です — 軽量クライアントにおける簡易決済検証（SPV）の基盤です。

デジタル署名（ECDSA） #

BitcoinとEthereumでのトランザクション承認は、secp256k1曲線上の楕円曲線デジタル署名アルゴリズム（ECDSA）を使用します。秘密鍵がトランザクションに署名します。任意のノードは秘密鍵を知ることなく対応する公開鍵を使って署名を検証できます。これにより、秘密鍵の保持者だけがアドレスからの支払いを承認できることが保証されます。

EthereumアドレスはKeccak-256公開鍵ハッシュの最後の20バイトです — これにより、鍵ペアと暗号学的に結びついたままアドレスをコンパクトで移植性の高いものにする派生が行われます。

Bitcoin ブロックチェーンの仕組み #

Bitcoinブロックには3つの論理コンポーネントが含まれています：

ブロックヘッダー — 80バイト：プロトコルバージョン、前のブロックヘッダーのハッシュ、トランザクションのMerkleルート、Unixタイムスタンプ、現在の難易度ターゲット、nonceで構成されます。マイナーはヘッダーのdouble-SHA-256ハッシュが難易度ターゲットを下回るまでnonce（場合によってはコインベーストランザクションのタイムスタンプまたはエクストラnonce）を繰り返します。

トランザクションリスト — ブロックに含まれるトランザクションの順序付きセット。コインベーストランザクション（最初のもの）はブロック報酬とトランザクション手数料をマイナーのアドレスに割り当てます。

チェーン — ヘッダーのリンク。チェーン内の累積proof-of-work（すべてのブロックを生成するために行われたすべての作業の合計）がどのフォークが正規チェーンかを決定します。ノードは常に最も累積作業量の多いチェーンに従います。

Bitcoinのブロック時間は10分が目標です。ネットワーク全体のハッシュレートが変化するにつれてその目標を維持するため、難易度は2,016ブロック（約2週間）ごとに調整されます。

Ethereumのプログラマブルレイヤー #

Ethereumは「価値の転送」から「コードの実行」へとBitcoinのトランザクションモデルを一般化しました。主な追加事項：

Ethereum Virtual Machine（EVM）。 すべてのフルノードで決定論的に実行される256ビットワード、スタックベースの仮想マシンです。すべてのオペコードには明示的なガスコストがあります。ブロックのガスリミットによって計算が制限されるため、無限ループがネットワークを停止させることを防ぎます。同じ状態で同じバイトコードを実行するすべてのノードは同じ出力を生成しなければなりません — この実行上のコンセンサスがスマートコントラクトをトラストレスにするものです。

アカウント。 Ethereumには2種類のアカウントがあります：秘密鍵で制御される外部所有アカウント（EOA）と、コードがオンチェーンに格納されているコントラクトアカウントです。コントラクトアドレスへのトランザクションはコントラクトのバイトコード実行を開始します。

状態。 Ethereumのグローバル状態は、アドレスからアカウント状態（nonce、残高、ストレージ、コードハッシュ）へのマッピングです。状態ルート — すべてのアカウント状態のMerkle Patricia trie — は各ブロックヘッダーに含まれており、任意のブロック高さでの任意のアカウントの状態の効率的な証明を可能にします。

ガス。 ユーザーはすべてのEVM操作に対してガス（ETH建て）を支払います。ガスは2つの機能を果たします：マイナー/バリデータの計算に対して報酬を与え、1回のトランザクションが消費できるリソースを上限設定し、高コストな操作によるサービス拒否攻撃を防ぎます。

Solidityでスマートコントラクトを書く #

Solidityは静的型付けのコントラクト指向言語で、EVMバイトコードにコンパイルされます。最小限のトークンコントラクトがコアコンセプトを示しています：

pragma solidity ^0.8.0;

contract MyToken {
    string public name;
    string public symbol;
    uint8 public decimals;
    uint256 public totalSupply;
    mapping(address => uint256) public balanceOf;

    event Transfer(address indexed from, address indexed to, uint256 value);

    constructor(
        string memory _name,
        string memory _symbol,
        uint8 _decimals,
        uint256 _totalSupply
    ) {
        name = _name;
        symbol = _symbol;
        decimals = _decimals;
        totalSupply = _totalSupply;
        balanceOf[msg.sender] = _totalSupply;
    }

    function transfer(address _to, uint256 _value) external returns (bool) {
        require(balanceOf[msg.sender] >= _value, "Insufficient balance");
        balanceOf[msg.sender] -= _value;
        balanceOf[_to] += _value;
        emit Transfer(msg.sender, _to, _value);
        return true;
    }
}

主な観察点：mapping(address => uint256)はインメモリデータ構造ではなく、EVMストレージレイアウトです — 読み書きにはガスがかかります。requireは失敗時にトランザクション全体をリバートし、未使用のガスを返還します。event Transferはオフチェーンインデクサーがフルステートを再読することなく転送を追跡するために使用するログを発行します。constructorはデプロイ時に1回だけ実行されます。その後の呼び出しは名前付き関数に向かいます。

ERC-20標準は代替可能トークンの共通インターフェース — transfer、transferFrom、approve、allowance、balanceOf、totalSupply — を形式化し、ERC-20準拠のトークンが独自統合なしに任意のERC-20対応取引所またはウォレットと連携できるようにしました。

台帳から金融インフラへ #

ここで説明したブロックチェーンプリミティブ — ハッシュチェーン、Merkle tree、EVM、ERC-20 — は2018年から2026年の間により広範な金融アプリケーションの基盤となりました：

分散型金融（DeFi）。 貸付プロトコル（Compound、Aave）、自動マーケットメーカー（Uniswap）、利回りアグリゲーターはすべてEVMスマートコントラクトとして動作します。従来の金融仲介機関のクリアリング、カストディ、決済機能を自己実行コードとオンチェーン流動性プールで置き換えます。

トークン化資産。 中央銀行と商業銀行は、EVM互換チェーンの許可型バリアントでトークン化預金、トークン化債券、トークン化マネーマーケットファンドを試験運用しています。基礎となるメカニクス — ハッシュで保護された状態遷移、アトミック決済、プログラマブルな転送ルール — は2014年のEthereumアーキテクチャの直系の子孫です。

中央銀行デジタル通貨。 Bank of EnglandのホールセールCBDC研究、ECBのデジタルユーロプログラム、Project Agoráはすべて、BitcoinとEthereumの基礎設計から派生または互換性のあるDLTアーキテクチャを探求しています。パーミッショニングとガバナンスモデルがパブリックブロックチェーンと完全に異なる場合でも、コンセンサスとハッシュチェーン構造は関連性を保ち続けています。

2008年のBitcoinホワイトペーパーから2026年のトークン化金融への旅は20年にわたりますが、一貫した技術的系譜の上に成り立っています。SHA-256ハッシュチェーンがどのように不変性を強制するか、Merkle treeがどのように効率的な検証を可能にするか、EVMがどのようにスマートコントラクトをアトミックに実行するかを理解することが、規制された金融サービスでブロックチェーンができることとできないことについてのあらゆる主張を評価するための前提条件です。

よくある質問 #

ブロックチェーンと分散型データベースの違いは何ですか？

従来の分散型データベースは可用性とパフォーマンスのためにノード全体にデータを複製しますが、信頼は集中化されています — 管理者がレコードを変更できます。ブロックチェーンはハッシュチェーンとコンセンサスを通じて改ざんを計算上コストの高いものにします。過去のレコードを変更するには、後続のすべてのproof-of-workまたはproof-of-stakeをやり直し、改変されたフォークを受け入れるようネットワークを説得する必要があります。区別する特性は、アクセス制御ではなく、暗号学とインセンティブ設計によって強制される改ざん証拠です。

EthereumはSHA-256ではなくKeccak-256を使用するのはなぜですか？

EthereumがKeccak-256（NIST標準化調整前のSHA-3最終候補）を採用した理由の1つは、設計者たちがBitcoinがすでに依存していたSHA-2系統からの独立性を望んだからです。Keccakはまた、特定のEVM操作に魅力的な異なる代数的特性も持っています。開発者にとっての実際の影響は、Ethereumのアドレス導出とストレージスロットハッシュ化にKeccak-256が使用され、BitcoinのようにSHA-256dではないということです。

EVMにおける「ガス」は何を防ぎますか？

ガスは2種類の攻撃を防ぎます。第一に、計算コストの高い操作によるサービス拒否を防ぎます。すべてのオペコードにガスがかかるため、攻撃者は無コストで無限ループを実行するようネットワークを強制することができません。第二に、ブロックのガスリミットがブロックごとの総計算量を上限設定し、ブロック検証時間がフルノードにとって有界かつ予測可能なままであることを保証します。ガスがなければ、単一のコントラクト呼び出しが無限計算を実行することでネットワークを停止させる可能性があります。

proof-of-stakeはproof-of-workと比べてセキュリティモデルをどのように変えますか？

proof-of-workでは、セキュリティはエネルギー消費によって提供されます。チェーンを攻撃するには、ネットワークのハッシュレートの50%超を制御する必要があり、これはその物理ハードウェアと電力の50%超を制御することを意味します。proof-of-stake（2022年のマージ以来Ethereumで使用）では、セキュリティは経済的ステーキングによって提供されます。バリデータはETHを担保としてロックし、矛盾するブロックに署名した場合はスラッシュされます。51%攻撃にはすべてのステーキングETHの50%超を取得してリスクにさらす必要があります — ハードウェアとエネルギーコストではなく、資本コストです。セキュリティモデルは異なりますが、合理的なバリデータが資本破壊よりも手数料収入を好むという前提の下、経済的観点から数学的に比較可能です。
