Audio Analyser: Azure Speech, NLP, and Translation Pipeline

Azureバックエンドを活用した音声分析ツールのアーキテクチャとパイプライン

TL;DR. Audio AnalyserはAzure Cognitive Servicesの音声テキスト変換ニューラルモデル、Text Analytics NLP、CherryPyを使用して音声録音を感情スコア、キーワード抽出、多言語翻訳付きの検索可能なトランスクリプトに変換します。

Points clés

  • Audio Analyser の仕組み：アーキテクチャの概要. パイプラインには 5 つの独立したステージがあります：.
  • Azure Cognitive Services：バッチ文字起こしエンジン. Azure Speech サービスのバッチ文字起こし API（/speechtotext/v3.0/transcriptions）は、Azure Blob Storage 内の音声ファイルへの参照と設定 JSON 本文を受け付けます。Audio Analyser は、事前署名された SAS URL を使用してローカルファイルを Blob Storage にアップロードし、文字起こしジョブを送信します。.
  • Azure AI Language による自然言語処理. 文字起こし後、Audio Analyser は azure-ai-textanalytics Python SDK を通じて表示形式の文字起こしを Azure AI Language に送信します：.
  • Azure Translator による多言語サポート. Azure Translator は、ユーザーが対象言語を要求した際に言語検出後に呼び出されます。このサービスは、ニューラル機械翻訳（NMT）で 135 の言語と方言をサポートしています。Audio Analyser は /translate REST エンドポイントを from パラメーターとして autodetect を使用するため、ソース言語の指定は不要です：.

エグゼクティブサマリー / 主なポイント

  • Azure Batch Transcription API は最大 2.5 時間の音声ファイル（WAV/MP3/OGG/FLAC）を受け付け、非同期で処理し、フレーズごとの nBest 候補、信頼度スコア、逆テキスト正規化（ITN）出力、オプションの話者ダイアリゼーションを含む recognizedPhrases JSON 配列を返します。ストリーミング接続は不要です（Microsoft Azure、2024 年）。
  • Microsoft のニューラル音響モデルは、Switchboard 会話ベンチマークにおける隠れマルコフモデル（HMM）ベースラインと比較して単語誤り率を約 50% 削減し、そのデータセットで専門の人間の文字起こし担当者と同等の約 5.1% の WER を達成しました（Xiong ら、Microsoft Research、2016 年 / 2021 年更新）。
  • Azure Text Analytics（現在は Azure AI Language の一部）は、Python SDK を使用した単一の analyze_sentiment または begin_analyze_actions 呼び出しで、キーフレーズ抽出、固有表現認識（NER）、意見マイニング付き感情分析、言語検出を通じて文字起こしテキストを処理します。
  • CherryPy は、URL ルーティング、マルチパートアップロード処理、セッション管理、Jinja2 テンプレートレンダリングを提供する Web レイヤーとして機能します。オーケストレーションのオーバーヘッドなしに、低コストの単一 VM 上で動作します。
  • Azure Translator NMT はソース言語を自動検出し、135 の対象言語のいずれかに文字起こしを翻訳します。同じパイプライン実行内で、元のテキストと翻訳されたテキストの両方に対して下流の NLP 分析が可能です。

Audio Analyser ⧉ は、Batch Transcription（音声テキスト変換）、Azure AI Language（Text Analytics、NLP）、Azure Translator（多言語出力）という 3 つの Azure Cognitive Services を単一のワークフローに連携させるオープンソースの Python アプリケーションです。Web インターフェースは CherryPy で提供され、結果は JSON、プレーンテキスト、またはローカルの SQLite データベースに保存できます。

この記事では、各パイプラインステージの技術的なアーキテクチャ、Azure API のコントラクト、CherryPy レイヤーでの設計上の選択について説明します。

Audio Analyser の仕組み：アーキテクチャの概要 #

パイプラインには 5 つの独立したステージがあります：

  1. アップロード — ユーザーが CherryPy Web インターフェースを通じて音声ファイルを送信します。CherryPy はファイルを一時ディレクトリに保存し、ジョブ ID を返します。
  2. 文字起こし — Audio Analyser がファイルを Azure Batch Transcription REST API に送信します。バッチ文字起こしは非同期であるため、アプリケーションはジョブステータスエンドポイントを定期的にポーリングし、Succeeded 状態になるまで待機してから次のステップに進みます。
  3. NLP — 生の文字起こしテキストが Azure AI Language に渡され、キーフレーズ抽出、NER、感情分析、言語検出が行われます。
  4. 翻訳（オプション）— 対象言語が指定されている場合、文字起こしは Azure Translator に送信され、翻訳されたテキストに対して NLP 分析が再実行されます。
  5. 出力 — 結果は選択した出力形式（JSON、TXT、または SQLite）に書き込まれ、CherryPy の Web UI にレンダリングされます。

Python 標準ライブラリ以外で必要なランタイム依存関係は azure-cognitiveservices-speech、azure-ai-textanalytics、azure-ai-translation-text、および cherrypy のみです。すべての Azure 認証情報は環境変数から読み込まれます。

Azure Cognitive Services：バッチ文字起こしエンジン #

Azure Speech サービスのバッチ文字起こし API（/speechtotext/v3.0/transcriptions）は、Azure Blob Storage 内の音声ファイルへの参照と設定 JSON 本文を受け付けます。Audio Analyser は、事前署名された SAS URL を使用してローカルファイルを Blob Storage にアップロードし、文字起こしジョブを送信します。

最小限のジョブ送信ペイロード：

{
  "contentUrls": ["https://<account>.blob.core.windows.net/<container>/<file>.wav?<sas>"],
  "locale": "en-US",
  "displayName": "audio-analyser-job-001",
  "properties": {
    "diarizationEnabled": true,
    "wordLevelTimestampsEnabled": true,
    "punctuationMode": "DictatedAndAutomatic",
    "profanityFilterMode": "Masked"
  }
}

レスポンスの recognizedPhrases 配列には、認識された発話ごとに 1 つのオブジェクトが含まれます。各エントリには以下が含まれます：

  • nBest[0].confidence — 0 から 1 の浮動小数点数
  • nBest[0].lexical — 話された通りの生の単語
  • nBest[0].itn — 逆テキスト正規化形式（数字、日付、通貨が展開）
  • nBest[0].display — 句読点付きの読みやすい形式
  • speaker — ダイアリゼーションが有効な場合の整数話者 ID

Custom Speech ファインチューニングは、ドメイン固有の語彙に対して利用できます。発音辞書またはアダプテーションコーパス（ドメインを代表するテキスト文のセット）をアップロードすることで言語モデルが調整され、金融用語や医学用語などの専門コンテンツでの WER を大幅に削減できます。

Azure AI Language による自然言語処理 #

文字起こし後、Audio Analyser は azure-ai-textanalytics Python SDK を通じて表示形式の文字起こしを Azure AI Language に送信します：

from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential

client = TextAnalyticsClient(
    endpoint=os.environ["AZURE_LANGUAGE_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["AZURE_LANGUAGE_KEY"])
)

documents = [{"id": "1", "language": detected_lang, "text": transcript}]

sentiment_result = client.analyze_sentiment(documents, show_opinion_mining=True)
for doc in sentiment_result:
    print(f"Sentiment: {doc.sentiment}")
    print(f"Scores: pos={doc.confidence_scores.positive:.2f} "
          f"neg={doc.confidence_scores.negative:.2f} "
          f"neu={doc.confidence_scores.neutral:.2f}")
    for sentence in doc.sentences:
        for opinion in sentence.mined_opinions:
            print(f"  Target: {opinion.target.text}, "
                  f"Assessment: {[a.text for a in opinion.assessments]}")

keyphrases_result = client.extract_key_phrases(documents)
entities_result  = client.recognize_entities(documents)

show_opinion_mining=True はアスペクトレベルの感情分析を有効にします。API はドキュメントレベルの極性だけでなく、特定のターゲット–評価ペア（例：ターゲット="音声品質"、評価="不良"）も返します。これにより、カスタマーサービスの通話分析で具体的な問題を特定するのに役立つ出力が得られます。

固有表現認識は、スパンを次のいずれかに分類します：Person、Organization、Location、Event、Product、DateTime、Quantity、IP、URL、Email、PersonType、Skill、Address、PhoneNumber。

Azure Translator による多言語サポート #

Azure Translator は、ユーザーが対象言語を要求した際に言語検出後に呼び出されます。このサービスは、ニューラル機械翻訳（NMT）で 135 の言語と方言をサポートしています。Audio Analyser は /translate REST エンドポイントを from パラメーターとして autodetect を使用するため、ソース言語の指定は不要です：

import requests, uuid

url = "https://api.cognitive.microsofttranslator.com/translate"
params = {"api-version": "3.0", "to": target_lang}
headers = {
    "Ocp-Apim-Subscription-Key": os.environ["AZURE_TRANSLATOR_KEY"],
    "Ocp-Apim-Subscription-Region": os.environ["AZURE_TRANSLATOR_REGION"],
    "Content-type": "application/json",
    "X-ClientTraceId": str(uuid.uuid4())
}
body = [{"text": transcript}]
response = requests.post(url, params=params, headers=headers, json=body)
translated_text = response.json()[0]["translations"][0]["text"]
detected_language = response.json()[0]["detectedLanguage"]["language"]

翻訳後、Audio Analyser はオプションとして翻訳されたテキストに対して Text Analytics NLP パスを再実行し、キーフレーズと感情の出力をソース言語と対象言語の両方で利用できるようにします。

出力形式の選択（JSON、TXT、SQLite）は起動時に設定されます。SQLite 出力では、各分析セッションがジョブ ID、タイムスタンプ、ソース言語、文字起こし、翻訳された文字起こし、感情スコア、JSON ブロブとしてのキーフレーズの列を持つ行として保存され、セッション間での SQL クエリが可能になります。

CherryPy を Web レイヤーとして使用 #

CherryPy は、クラスベースのコントローラーを使用して URL ルートを Python メソッドにマッピングします。Audio Analyser は 3 つのルートを使用します：

ルート メソッド 説明
GET / index() アップロードフォームをレンダリング
POST /analyse analyse() マルチパートアップロードを受け付け、パイプラインを起動し、ジョブ ID を返す
GET /results/<job_id> results() ジョブステータスをポーリング；完了時に結果ページをレンダリング

最小限の設定でサーバーのフットプリントを小さく保ちます：

import cherrypy

cherrypy.config.update({
    "server.socket_host": "0.0.0.0",
    "server.socket_port": 8080,
    "tools.sessions.on": True,
    "tools.sessions.timeout": 60
})
cherrypy.quickstart(AudioAnalyserApp(), "/", conf)

セッション状態は、現在のジョブ ID、選択した出力形式、対象翻訳言語を保持します。CherryPy のビルトインセッションストレージはデフォルトでファイルベースであり、外部キャッシュレイヤーは不要です。

よくある質問 #

Audio Analyser はどのような音声形式とファイルサイズを受け付けますか？ Azure Batch Transcription API は、最大 2.5 時間の WAV、MP3、OGG、FLAC ファイルをサポートしています。この範囲を超えるファイルはアップロード前に分割する必要があります。ステレオファイルは受け付けられ、モノラル変換は不要です。

話者ダイアリゼーションはどのように機能しますか？ バッチ文字起こしリクエストで diarizationEnabled: true を設定すると、Azure の話者分離モデルが有効になります。レスポンス内の各 recognizedPhrase には整数の speaker フィールドが含まれます。モデルは音響特性によって話者を識別し、セッション内で一貫した ID を割り当てますが、別途音声プロファイルの登録ステップなしには話者が誰であるかは特定しません。

文字起こし後、音声ファイルは保持されますか？ 音声ファイルは短期間の SAS URL を使用して Azure Blob Storage にアップロードされ、アップロード完了後に一時ローカルディレクトリから削除されます。Azure Blob Storage でのブロブの保持は、コンテナのライフサイクルポリシーに依存します。デフォルトでは Audio Analyser は明示的な削除ポリシーを設定しないため、本番環境では Azure ポータルで短い TTL ルール（例：1 日以上経過したブロブを削除）を設定することをお勧めします。

翻訳なしで NLP 分析を実行できますか？ はい。翻訳はオプションのパイプラインステージで、--target-lang CLI フラグまたは Web UI の対象言語ドロップダウンで制御されます。対象言語が選択されていない場合、パイプラインは音声テキスト変換と Text Analytics のみを実行します。
