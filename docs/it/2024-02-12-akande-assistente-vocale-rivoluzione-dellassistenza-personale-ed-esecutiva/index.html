Àkàndé: GPT-Powered Voice Assistant for Executives

Architettura di un assistente vocale Python open-source: Whisper, GPT-4, cache SQLite e fpdf2

Sintesi esecutiva / Punti chiave

  • Àkàndé ⧉ è un assistente vocale Python open-source che concatena OpenAI Whisper per la conversione voce-testo, le chat completion GPT-4, una cache di risposte SQLite locale e l'esportazione PDF con fpdf2 in un unico flusso di lavoro vocale che non richiede archiviazione cloud né pesi di modelli IA locali.
  • La cache SQLite memorizza hash SHA-256 di stringhe di query normalizzate associati al testo grezzo delle risposte API; i successi della cache non costano alcun token e ritornano in meno di 10 ms, rendendo le query ripetute (come rivedere una decisione presa prima in una riunione) essenzialmente gratuite.
  • La conversazione multi-turno viene mantenuta costruendo la lista messages in memoria e passandola ad ogni chiamata API Chat Completions — il modello riceve la cronologia completa della sessione per potersi riferire agli scambi precedenti, al costo di un uso di token incrementalmente crescente per turno.
  • La generazione di riassunti PDF serializza la lista messages della sessione in un documento fpdf2 formattato: i turni dell'utente e quelli dell'assistente sono etichettati, vengono inseriti i timestamp e l'impaginazione automatica gestisce sessioni di qualsiasi lunghezza; il file viene scritto nel filesystem locale, non caricato.
  • Confine di privacy: solo la query attiva (e la cronologia della sessione fino al limite della finestra di contesto) lascia il dispositivo — nessuna registrazione audio, nessuna trascrizione e nessuna risposta memorizzata nella cache viene inviata a servizi remoti diversi dall'API OpenAI.

Àkàndé ⧉ è un assistente vocale Python open-source costruito attorno a tre componenti modulari: OpenAI Whisper per il riconoscimento vocale, l'API GPT-4 Chat Completions per la comprensione e la generazione del linguaggio, e un database SQLite locale per la cache delle risposte e la persistenza delle sessioni. Il risultato è un flusso di lavoro vocale eseguibile su un laptop senza pesi di modelli locali, infrastruttura di archiviazione offline o stack di container.

Questo articolo descrive l'architettura tecnica di ciascun componente, le decisioni progettuali relative alla cache e al contesto multi-turno, e la pipeline di esportazione PDF.

Panoramica della pipeline #

Una singola interazione con Àkàndé segue questa sequenza:

  1. Acquisizione audio — l'utente parla; l'applicazione registra l'audio in un file WAV temporaneo usando sounddevice o una libreria audio compatibile.
  2. Da voce a testo — il file WAV viene inviato a openai.audio.transcriptions.create() (API Whisper); la trascrizione viene restituita come stringa semplice.
  3. Ricerca nella cache — la trascrizione viene normalizzata (tutto minuscolo, spazi compressi) e hashata con SHA-256; l'hash viene cercato nella tabella SQLite locale response_cache.
  4. Chiamata API o successo della cache — in caso di mancanza, la trascrizione viene aggiunta alla lista messages della sessione e inviata a openai.chat.completions.create(); il testo della risposta viene memorizzato nella cache.
  5. Da testo a voce — il testo della risposta viene convertito in audio usando l'endpoint openai.audio.speech.create() (TTS) o una libreria TTS locale, e riprodotto.
  6. Esportazione PDF (su richiesta) — la lista completa messages viene serializzata in un documento fpdf2 formattato e scritta su disco.

Integrazione OpenAI: Chat Completions e Whisper #

Àkàndé usa l'SDK Python openai sia per il riconoscimento vocale che per la generazione di testo. La chiamata di trascrizione Whisper:

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

La chiamata Chat Completions mantiene una lista messages con ambito di sessione:

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

Il prompt di sistema viene anteposto una sola volta all'inizio della sessione e controlla la persona di Àkàndé, il formato di output e qualsiasi vincolo specifico del dominio:

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

L'impostazione temperature=0.2 privilegia il determinismo rispetto alla variazione creativa — importante per query fattuali come ricordare una decisione presa prima nella sessione.

Cache di risposte SQLite #

Lo schema della cache è minimale:

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

Il percorso di lettura e scrittura:

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

INSERT OR REPLACE garantisce che una risposta memorizzata nella cache venga aggiornata se la stessa query viene inviata dopo un aggiornamento del modello. Una query di eliminazione basata su TTL (DELETE WHERE created_at < ?) può essere pianificata all'avvio per limitare la dimensione della cache.

Prestazioni dei successi della cache: una ricerca SQLite su un SSD locale ritorna in meno di 1 ms per tabelle fino a ~100.000 righe. La latenza round-trip per una chiamata API GPT-4 dal vivo è tipicamente di 600–900 ms per risposte brevi. Per un briefing quotidiano con alcune query ripetute, la cache elimina la maggior parte delle chiamate API dopo la prima sessione.

Generazione di riassunti PDF #

L'esportazione PDF usa fpdf2, una libreria Python PDF mantenuta senza dipendenze binarie:

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell() gestisce l'a capo automatico e le interruzioni di pagina automatiche, in modo che sessioni di qualsiasi lunghezza producano un documento ben formattato senza logica di impaginazione manuale. L'output è un file compatibile PDF/A senza font incorporati oltre alle metriche standard Helvetica.

Modello di privacy #

Il confine di privacy in Àkàndé è definito da tre fatti:

  1. L'audio viene inviato all'API Whisper tramite HTTPS e non viene conservato da OpenAI oltre la chiamata API (secondo la politica di utilizzo dei dati API di OpenAI in vigore a febbraio 2024).
  2. Le chiamate all'API Chat Completions trasmettono la lista messages della sessione — che può contenere la cronologia completa della conversazione per sessioni multi-turno.
  3. Il database SQLite e i file PDF risiedono interamente nel filesystem locale; non avviene alcuna sincronizzazione in background con alcun servizio cloud.

Per i casi d'uso esecutivi che coinvolgono argomenti sensibili — discussioni di M&A, questioni di personale, strategia normativa — la cronologia della sessione trasmessa all'API dovrebbe essere esaminata rispetto alla politica di utilizzo dell'IA dell'organizzazione prima della distribuzione. Il limite max_tokens nel prompt di sistema può essere utilizzato per prevenire la trasmissione involontaria di contesto che supera l'ambito di divulgazione previsto.

Domande frequenti #

Àkàndé conserva la cronologia delle conversazioni dopo la fine della sessione? La lista messages in memoria viene eliminata quando il processo termina. La cronologia delle conversazioni viene conservata solo se l'utente attiva un'esportazione PDF o se viene aggiunto un livello di persistenza personalizzato. La cache SQLite memorizza hash delle query e testo delle risposte, non il contesto completo della conversazione.

Come gestisce la cache le query simili ma non identiche? La cache usa l'hashing a corrispondenza esatta sulla stringa di query normalizzata. Due query che differiscono di una sola parola produrranno hash diversi e daranno luogo a chiamate API separate. Il caching semantico (che usa la similarità degli embedding per corrispondere a query quasi duplicate) richiederebbe un ulteriore passaggio di ricerca vettoriale e non fa parte dell'implementazione base.

Quale modello GPT usa Àkàndé per impostazione predefinita? Il valore predefinito è gpt-4-turbo-preview a partire da febbraio 2024. Il nome del modello è un parametro di configurazione, quindi qualsiasi modello di chat completion OpenAI può essere sostituito. Passare a gpt-3.5-turbo riduce il costo API di circa 20× per token ma riduce la qualità del ragionamento per query complesse a più passaggi.

Il formato di esportazione PDF può essere personalizzato? Sì. La funzione di esportazione fpdf2 accetta la lista messages come unico input richiesto, quindi font, margini, dimensione della pagina, contenuto dell'intestazione e etichettatura possono tutti essere modificati editando la funzione di esportazione. fpdf2 supporta anche l'aggiunta di immagini, tabelle e font Unicode, consentendo layout di documenti più ricchi per organizzazioni con requisiti specifici di branding.
