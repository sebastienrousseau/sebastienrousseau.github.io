The making of the Express Transaction Credits Platform

สถาปัตยกรรมโทเค็น, การเบิกจ่ายแบบ multi-signature และการโอนแบบ time-locked บน Ethereum ในปี 2018

แพลตฟอร์ม EXTCERC-223สมาร์ทคอนแทรกต์ Ethereumสถาปัตยกรรมโทเค็นmulti-signatureการโอนแบบ time-lockedการชำระเงินบล็อกเชนสินเชื่อค้ำประกันการเงินแบบกระจายศูนย์คริปโต 2018

TL;DR. เจาะลึกทางเทคนิคเกี่ยวกับการสร้างแพลตฟอร์ม EXTC บน Ethereum ERC-223 ในปี 2018: สถาปัตยกรรมโทเค็น, การเบิกจ่ายแบบ multi-sig, การโอนแบบ time-locked และสินเชื่อทันทีที่มีหลักทรัพย์ค้ำประกัน

บทสรุปผู้บริหาร / ประเด็นสำคัญ

  • ปัญหาหลัก ERC-20 มาตรฐานโทเค็น Ethereum ที่โดดเด่นในปี 2018 มีข้อบกพร่องเชิงโครงสร้าง: โทเค็นที่โอนโดยตรงไปยังที่อยู่สัญญาอัจฉริยะจะถูกทำลายอย่างเงียบๆ หากสัญญาขาดตัวจัดการ แพลตฟอร์มการชำระเงินใดๆ ที่สร้างบน ERC-20 สืบทอดความเสี่ยงนั้น (Ethereum EIPs)
  • ERC-223 เป็นการแก้ไข ERC-223 กำหนดให้สัญญาผู้รับต้องนำฟังก์ชัน tokenFallback(address, uint, bytes) ไปใช้ หากไม่มี การโอนจะย้อนกลับอย่างเป็นอะตอมิก ไม่มีโทเค็นใดที่สามารถสูญหายอย่างเงียบๆ ได้ (Ethereum EIPs GitHub)
  • ต้นแบบสัญญาห้าประการของ EXTC เอกลักษณ์โทเค็น (ชื่อ, สัญลักษณ์, ความแม่นยำ 18 ตำแหน่งทศนิยม), อุปทานคงที่, การโอนที่สอดคล้องกับ ERC-223, การเบิกจ่ายขององค์กรแบบหลายลายเซ็น และคำสั่งถาวรที่ล็อคตามความสูงของบล็อก
  • กลไกสินเชื่อหลักประกัน ผู้กู้ล็อคโทเค็น EXTC ในสัญญา escrow; สัญญาปล่อยเงินกู้อย่างเป็นอะตอมิกเมื่อได้รับหลักประกัน โดยไม่มีความล่าช้าในการรับประกันหรือการอนุมัติจากคณะกรรมการสินเชื่อ
  • สิ่งที่การทดลองเผยให้เห็นเกี่ยวกับข้อจำกัดของ Ethereum ที่ปริมาณงาน mainnet ~15 TPS และค่าใช้จ่าย gas $0.10–$1.00 ต่อธุรกรรมในช่วงสูงสุดของเดือนมกราคม 2018 เครือข่ายการชำระเงินที่ประมวลผลแม้แต่ปริมาณระดับการส่งเงินก็ไม่คุ้มทุนและไม่เป็นไปได้ทางเทคนิคบน Ethereum สาธารณะโดยไม่มีโครงสร้างพื้นฐาน Layer-2

ปัญหาการออกแบบ: เหตุใด ERC-20 จึงไม่เพียงพอ #

มาตรฐาน ERC-20 ที่เสนอในปี 2015 และได้รับการจัดทำอย่างเป็นทางการใน Ethereum Improvement Proposal 20 ได้กำหนดอินเทอร์เฟซโทเค็นที่ใช้แทนกันได้แบบ canonical ที่ขับเคลื่อนกระแส ICO ในปี 2017–2018 ฟังก์ชันหลักหกประการ — totalSupply, balanceOf, transfer, transferFrom, approve และ allowance — เพียงพอสำหรับการออกโทเค็นและการแลกเปลี่ยนอย่างง่าย

อย่างไรก็ตาม สำหรับแพลตฟอร์มการชำระเงิน ERC-20 มีข้อบกพร่องที่สำคัญในการผลิต ฟังก์ชัน transfer(address _to, uint256 _value) ย้ายโทเค็นไปยังที่อยู่ใดก็ได้ รวมถึงที่อยู่สัญญา โดยไม่กระตุ้นรหัสใดๆ ในสัญญาที่รับ สัญญาที่ไม่ได้รับการตั้งโปรแกรมเป็นพิเศษเพื่อติดตามการโอน ERC-20 ที่เข้ามาไม่มีทางตรวจจับได้ โทเค็นที่ส่งด้วยวิธีนี้ถูกดักจับอย่างถาวร โดยไม่มีกลไกการกู้คืน

ชุมชน Ethereum ประเมินว่าโทเค็น ERC-20 มูลค่าหลายสิบล้านดอลลาร์ถูกสูญหายอย่างถาวรภายในกลางปี 2018 ผ่านกลไกนี้ การสร้างแพลตฟอร์มการชำระเงินที่การโอนอาจล้มเหลวอย่างเงียบๆ และทำลายเงินของผู้ใช้เป็นสิ่งที่ยอมรับไม่ได้

วิธีแก้ปัญหา ERC-223: การโอนแบบอะตอมิกพร้อมการแจ้งเตือน #

ERC-223 ที่เสนอในตัวติดตามปัญหา GitHub ของ Ethereum EIPs ได้แก้ไขปัญหาการสูญหายแบบเงียบโดยการเปลี่ยนสิ่งที่การโอนโทเค็นต้องทำ ภายใต้ ERC-223, transfer(address _to, uint256 _value, bytes _data) ตรวจสอบว่าที่อยู่ผู้รับมีรหัสสัญญาหรือไม่ หากมี การโอนจะเรียก _to.tokenFallback(address _from, uint256 _value, bytes _data)

คุณสมบัติที่สำคัญ: หากสัญญาผู้รับไม่ได้นำ tokenFallback ไปใช้ ธุรกรรมการโอนทั้งหมดจะย้อนกลับ ไม่มีโทเค็นใดออกจากยอดดุลของผู้ส่ง ไม่มีโทเค็นใดถูกดักจับ การโอนเป็นแบบอะตอมิก — มันเสร็จสมบูรณ์ด้วยรหัสของผู้รับที่กำลังดำเนินการ หรือล้มเหลวอย่างสิ้นเชิงโดยที่สถานะไม่เปลี่ยนแปลง

สำหรับ EXTC นี่หมายความว่า:

  • การชำระเงินให้กับสัญญาอัจฉริยะปลอดภัยโดยการก่อสร้าง สัญญา escrow, กระเป๋าเงินแบบหลายลายเซ็น และสัญญาการให้กู้ยืมสามารถรับโทเค็น EXTC ได้โดยไม่มีความเสี่ยงที่เงินจะสูญหายอย่างไม่สามารถย้อนกลับได้
  • ฟิลด์ _data เปิดใช้งานข้อมูลเมตาการชำระเงินที่สมบูรณ์ เพย์โหลดไบต์สามารถพกพาการอ้างอิงใบแจ้งหนี้, รหัสการกำหนดเส้นทาง หรือการรับรองการปฏิบัติตามกฎระเบียบ — ข้อมูลที่การโอน ERC-20 ธรรมดาไม่สามารถส่งได้
  • ค่าใช้จ่าย gas สูงกว่าเล็กน้อย การเรียก tokenFallback เพิ่มประมาณ 2,000–5,000 gas ต่อการโอน ซึ่งเป็นค่าใช้จ่ายเล็กน้อยที่ราคา gas ในปี 2018

สถาปัตยกรรมสัญญา EXTC #

สัญญาโทเค็น EXTC เป็นการนำไปใช้ Solidity ที่มีโครงสร้างรอบห้าโมดูล:

1. เอกลักษณ์โทเค็น #

string public name = "Express Transaction Credits";
string public symbol = "EXTC";
uint8 public decimals = 18;

สิบแปดตำแหน่งทศนิยมให้ความแม่นยำต่ำกว่าหนึ่งเซนต์แก่ EXTC ซึ่งตรงกับความละเอียดที่จำเป็นสำหรับกรณีการใช้งานไมโครเพย์เมนต์และไมโครโลน สัญลักษณ์ EXTC เป็นตัวระบุบน chain ที่ลงทะเบียนในสัญญาโทเค็น

2. อุปทานรวมคงที่ #

อุปทานรวมถูกกำหนดเมื่อการนำสัญญาไปใช้งานและไม่สามารถเพิ่มขึ้นได้โดยการสร้างครั้งต่อๆ ไป การเลือกการออกแบบนี้ทำให้ EXTC เป็นแบบ deflationary: โทเค็นใดๆ ที่ถูกลบออกจากการหมุนเวียนอย่างถาวร — ผ่านการดำเนินการเผาที่ไม่สามารถย้อนกลับได้ — ลดอุปทานโดยไม่มีการทดแทน โมเดลอุปทานคงที่เป็นมาตรฐานในการออกแบบโทเค็นการชำระเงินในปี 2018 สะท้อนถึงสมมติฐานที่ได้รับอิทธิพลจาก Bitcoin ว่าแรงกดดัน deflationary เป็นคุณสมบัติสำหรับสื่อกลางในการแลกเปลี่ยน

3. ยอดดุลและการโอนที่สอดคล้องกับ ERC-223 #

ฟังก์ชันการโอนหลักนำอินเทอร์เฟซ ERC-223 เต็มรูปแบบไปใช้ การแมปยอดดุลภายในติดตามการถือครองของแต่ละที่อยู่ ตัวช่วย isContract(address) แยกแยะที่อยู่ EOA (บัญชีที่เป็นเจ้าของภายนอก) จากที่อยู่สัญญาเพื่อพิจารณาว่าจำเป็นต้องเรียก tokenFallback หรือไม่

4. การเบิกจ่ายขององค์กรแบบหลายลายเซ็น #

เวิร์กโฟลว์การชำระเงินขององค์กรต้องการการอนุญาตร่วม: ผู้ลงนามคนเดียวไม่สามารถเริ่มต้นการเบิกจ่ายเกินกว่าเกณฑ์ที่กำหนดได้โดยฝ่ายเดียว สัญญา EXTC นำสคีมหลายลายเซ็นแบบสอง-จาก-N ไปใช้:

  1. ผู้เริ่มต้นที่กำหนดเสนอการโอน โดยระบุผู้รับ จำนวน และ nonce
  2. ผู้ลงนามร่วมยืนยัน nonce
  3. หลังจากที่ทั้งสองลายเซ็นถูกบันทึกบน chain เท่านั้นที่การโอนจะดำเนินการ

สิ่งนี้ขจัดความเสี่ยงของจุดล้มเหลวเดียวสำหรับบัญชีองค์กรในขณะที่รักษาการไหลของการอนุญาตทั้งหมดบน chain และสามารถตรวจสอบได้โดยไม่ต้องมีตัวกลางบ้านหักบัญชี

5. คำสั่งถาวรที่ล็อคตามความสูงของบล็อก #

การชำระเงินที่เกิดขึ้นซ้ำ — เงินเดือน, การสมัครสมาชิก, การชำระคืนสินเชื่อตามกำหนดการ — ต้องการต้นแบบคำสั่งถาวร EXTC นำสิ่งนี้ไปใช้เป็นการล็อคเวลา: บันทึกการโอนถูกจัดเก็บในสัญญาพร้อมพารามิเตอร์ releaseBlock การโอนไม่สามารถดำเนินการได้จนกว่าความสูงของบล็อก Ethereum จะถึง releaseBlock

ความสูงของบล็อกในฐานะพร็อกซีเวลาเป็นการเลือกที่ใช้ได้จริงในปี 2018 Ethereum มุ่งหมายที่ช่วงเวลาบล็อก 15 วินาที ทำให้ความสูงของบล็อกเป็นพร็อกซีที่น่าเชื่อถือสำหรับเวลานาฬิกาแขวนภายในช่วงเวลาไม่กี่นาที การประทับเวลาสัมบูรณ์ (block.timestamp) มีอยู่แต่เสี่ยงต่อการจัดการโดยนักขุดภายในหน้าต่าง ±900 วินาที ทำให้ความสูงของบล็อกเป็นข้อมูลอ้างอิงที่ปลอดภัยกว่าสำหรับสัญญาทางการเงิน

กลไกสินเชื่อทันทีที่ค้ำประกันด้วยหลักประกัน #

ต้นแบบการให้กู้ยืม EXTC เป็นองค์ประกอบที่ซับซ้อนที่สุด การออกแบบ:

  1. ผู้กู้ล็อคหลักประกัน ผู้กู้เรียก lockCollateral(uint256 _collateralAmount), โอนโทเค็น EXTC ไปยัง escrow สัญญาการให้กู้ยืมผ่าน ERC-223 tokenFallback
  2. การตรวจสอบอัตราส่วนสินเชื่อต่อมูลค่า สัญญาอ่านอัตราส่วน LTV ที่กำหนดไว้ล่วงหน้า (เช่น 50%) และคำนวณจำนวนเงินกู้สูงสุดตามหลักประกันที่ล็อค
  3. การเบิกจ่ายสินเชื่อแบบอะตอมิก หากหลักประกันเป็นไปตามเกณฑ์ขั้นต่ำ สัญญาจะโอนจำนวนเงินกู้ไปยังที่อยู่ของผู้กู้ทันที ไม่มีคิวการรับประกัน ไม่มีคณะกรรมการสินเชื่อ ไม่มีความล่าช้าในการชำระหนี้
  4. การชำระคืนและการปลดปล่อย เมื่อชำระคืน — เงินต้นบวกกับอัตราดอกเบี้ยคงที่ — สัญญาจะปล่อยหลักประกันกลับคืนให้กับผู้กู้ การไม่ชำระคืนก่อน releaseBlock จะกระตุ้นการชำระบัญชีอัตโนมัติ: สัญญาจะโอนหลักประกันไปยังที่อยู่ที่กำหนดของผู้ให้กู้

การไหลทั้งหมดถูกบังคับใช้โดยรหัสสัญญา ไม่มีฝ่ายใดต้องไว้วางใจอีกฝ่ายหรือพึ่งพาตัวกลางเพื่อบังคับใช้เงื่อนไข

สิ่งที่การทดลองเผยให้เห็น #

สถาปัตยกรรมสัญญา EXTC มีความสอดคล้องกันทางเทคนิค ERC-223 แก้ไขข้อบกพร่องด้านความปลอดภัยที่ร้ายแรงที่สุดของ ERC-20 ต้นแบบหลายลายเซ็นและการล็อคเวลาแมปโดยตรงกับเวิร์กโฟลว์การชำระเงินขององค์กรจริง กลไกสินเชื่อหลักประกันแสดงให้เห็นว่าการให้กู้ยืมที่มีหลักประกันสามารถทำให้เป็นอัตโนมัติอย่างสมบูรณ์และบังคับใช้เองบน chain

ข้อจำกัดสองประการเผยตัวออกมาในทางปฏิบัติ:

ค่าใช้จ่าย gas ในช่วงสูงสุดของเดือนมกราคม 2018 ราคา gas Ethereum ถึง 50–100 gwei ทำให้การโอนโทเค็น ERC-223 เพียงรายการเดียวมีค่าใช้จ่าย $0.50–$2.00 สำหรับไมโครเพย์เมนต์หรือการส่งเงิน $10–$50 ค่าธรรมเนียมเหล่านั้นสูงมาก

ปริมาณงาน ขีดจำกัด gas บล็อก Ethereum mainnet ในต้นปี 2018 อยู่ที่ประมาณ 8 ล้าน gas การโอน ERC-223 ใช้ประมาณ 50,000–80,000 gas ดังนั้นเครือข่ายสามารถประมวลผลการโอนโทเค็น EXTC ได้ประมาณ 100–160 รายการต่อบล็อก หรือประมาณ 7–11 รายการต่อวินาทีที่ช่วงเวลาบล็อก 15 วินาที ขนาดเครือข่ายการชำระเงิน — หลายร้อยหรือหลายพันธุรกรรมต่อวินาที — ไม่สามารถบรรลุได้บน Ethereum สาธารณะโดยไม่มีโครงสร้างพื้นฐาน Layer-2 ที่ยังไม่มีอยู่ในรูปแบบการผลิต

สิ่งเหล่านี้เป็นข้อจำกัดด้านโครงสร้างพื้นฐาน ไม่ใช่ข้อบกพร่องในการออกแบบของ EXTC ตรรกะสัญญาถูกต้อง blockchain ที่อยู่เบื้องหลังยังไม่สามารถรองรับปริมาณการชำระเงินในระดับอุตสาหกรรมการเงินได้

แนวคิดที่เข้าสู่การผลิต #

รูปแบบการออกแบบหลายประการจาก EXTC ได้รับการตรวจสอบความถูกต้องโดยการพัฒนาในภายหลัง:

การโอนโทเค็นแบบอะตอมิกพร้อมการแจ้งเตือนผู้รับ — คุณสมบัติหลักของ ERC-223 — กลายเป็นพื้นฐานสำหรับ ERC-777 (2019) ซึ่งขยายโมเดลการแจ้งเตือนและต่อมาถูกนำมารวมไว้ในโปรโตคอลการให้กู้ยืม DeFi รูปแบบ tokenFallback ปรากฏตลอดทั่วสถาปัตยกรรม DeFi สมัยใหม่

การอนุญาตหลายลายเซ็นสำหรับการเบิกจ่ายขององค์กร — รูปแบบที่ต้องการลายเซ็นหลายรายการบน chain ก่อนดำเนินการ — กลายเป็นโมเดลมาตรฐานสำหรับการจัดการคลัง DAO และโซลูชันการดูแลสถาบัน Gnosis Safe ที่เปิดตัวในปี 2018 ทำให้รูปแบบนี้เป็นที่นิยมในระดับขนาดใหญ่

สินเชื่อทันทีที่มีหลักประกันโดยไม่มีตัวกลาง — กลไกของการล็อคหลักประกันใน escrow และปล่อยเงินกู้อย่างเป็นอะตอมิก — เป็นการออกแบบพื้นฐานของโปรโตคอลการให้กู้ยืม DeFi เช่น Compound (2018) และ Aave (2020)

การล็อคเวลาตามความสูงของบล็อกสำหรับการชำระเงินตามกำหนดการ — รูปแบบของการเข้ารหัสเวลาดำเนินการในอนาคตในสัญญา — ปรากฏในสัญญา vesting โทเค็น, ข้อเสนอการกำกับดูแลที่ล่าช้า และการออกแบบ oracle ราคาเฉลี่ยถ่วงน้ำหนักตามเวลา (TWAP) ทั่วระบบนิเวศ DeFi

การทดลอง EXTC ไม่ถึงขนาดการผลิต โครงสร้างพื้นฐานที่จำเป็นเพื่อทำให้การออกแบบใช้ได้จริงใช้เวลาอีกสามถึงห้าปีในการเติบโต คำถามการออกแบบที่มันถามเป็นคำถามที่ถูกต้องสำหรับปี 2018

คำถามที่พบบ่อย #

เหตุใด ERC-223 จึงไม่ได้รับการยอมรับเป็นมาตรฐานโทเค็นที่โดดเด่นแม้จะแก้ไขข้อบกพร่องของ ERC-20?

ERC-223 กำหนดให้สัญญาผู้รับต้องนำ tokenFallback ไปใช้ ทำลายความเข้ากันได้ย้อนหลังกับสัญญาหลายพันรายการที่ถูกนำไปใช้งานแล้วสำหรับโทเค็น ERC-20 ระบบนิเวศ ERC-20 ที่มีอยู่มีขนาดใหญ่เกินไปที่จะย้ายถิ่นฐาน ข้อเสนอในภายหลัง — โดยเฉพาะ ERC-777 และ ERC-1363 — แก้ไขปัญหาเดียวกันด้วยการแลกเปลี่ยนความเข้ากันได้ที่แตกต่างกัน แต่ ERC-20 ยังคงโดดเด่นผ่านการรวมกันของผลกระทบจากเครือข่ายและการแนะนำรูปแบบโทเค็นที่ห่อหุ้มซึ่งหลีกเลี่ยงสถานการณ์การสูญหายแบบเงียบ

เกิดอะไรขึ้นกับโทเค็นและแพลตฟอร์ม EXTC?

EXTC เป็นโปรเจ็กต์พิสูจน์แนวคิดและการวิจัยเบื้องต้นจากปี 2018 ตลาด ICO และโทเค็นการชำระเงินที่กว้างขึ้นหดตัวอย่างรวดเร็วในช่วงปี 2018–2019 เมื่อข้อจำกัดความสามารถในการปรับขนาดของ Ethereum และความไม่แน่นอนด้านกฎระเบียบชัดเจนขึ้น แนวคิดที่ฝังอยู่ในการออกแบบ EXTC ปรากฏขึ้นอีกครั้งในโปรโตคอลในภายหลังที่มีสิทธิ์เข้าถึงโครงสร้างพื้นฐาน Layer-2, เครื่องมือที่ดีกว่า และกรอบกฎระเบียบที่ชัดเจนกว่า

โมเดลสินเชื่อหลักประกันของ EXTC เปรียบเทียบกับโปรโตคอล DeFi สมัยใหม่เช่น Aave อย่างไร?

กลไกหลักเหมือนกัน: ล็อคหลักประกัน, รับสินเชื่อที่กำหนดขนาดตามอัตราส่วน LTV, ชำระคืนหรือเผชิญกับการชำระบัญชี ความแตกต่างคือ: (1) โปรโตคอล DeFi สมัยใหม่ใช้ฟีดราคา oracle สำหรับ LTV แบบไดนามิกแทนอัตราส่วนคงที่; (2) ใช้อัตราดอกเบี้ยแบบ algorithmic ที่ตอบสนองต่อการใช้งานพูล; (3) ดำเนินการบนเครือข่าย Layer-2 ที่มีค่าใช้จ่าย gas ต่ำกว่า mainnet ปี 2018 ถึง 10–100 เท่า; (4) Aave และ Compound ผ่านการตรวจสอบความปลอดภัยอย่างเป็นทางการและถือสภาพคล่องหลายพันล้านดอลลาร์ ให้การตรวจสอบเชิงประจักษ์ว่าโมเดลพื้นฐานนั้นสมเหตุสมผล

ข้อจำกัดเวอร์ชัน Solidity ในต้นปี 2018 คืออะไร?

สัญญา EXTC ถูกเขียนสำหรับ Solidity 0.4.x ซึ่งเป็นเวอร์ชันที่โดดเด่นในต้นปี 2018 Solidity 0.4 ขาดคุณสมบัติความปลอดภัยหลายประการที่นำมาใช้ในเวอร์ชันหลังจากนี้: การตรวจสอบ integer overflow (เพิ่มโดยอัตโนมัติใน 0.8.0), require/revert พร้อมข้อความแสดงข้อผิดพลาด (จำกัดใน 0.4) และการมองเห็นฟังก์ชันที่ชัดเจน (ค่าเริ่มต้นเป็น public ใน 0.4) สัญญาพึ่งพาไลบรารี SafeMath ของ OpenZeppelin เพื่อป้องกัน overflow ซึ่งเป็นรูปแบบทั่วไปก่อนที่คอมไพเลอร์จะบังคับใช้สิ่งนี้โดยธรรมชาติ
