TL;DR. 블록체인 작동 원리에 대한 기술적 소개: 암호 해시 체인, Merkle 트리, 분산 합의, Ethereum의 프로그래밍 가능한 레이어가 결제 원장을 스마트 컨트랙트와 토큰화 자산 플랫폼으로 변환한 방법을 설명합니다.

Points clés

  • 블록체인이 해결한 문제. Bitcoin 이전에는 이중 지불을 방지하기 위해 디지털 결제에 은행, 결제 처리업체 또는 청산소와 같은 신뢰할 수 있는 중개자가 필요했습니다.
  • 암호학적 구성 요소. 블록체인 기술은 세 가지 기존 암호학적 기본 요소를 새로운 아키텍처로 조합합니다:.
  • Bitcoin 블록체인 작동 방식. Bitcoin 블록에는 세 가지 논리적 구성 요소가 포함됩니다:.
  • Ethereum의 프로그래밍 가능 레이어. Ethereum은 Bitcoin의 거래 모델을 "가치 전송"에서 "코드 실행"으로 일반화했습니다.

요약 / 핵심 요점

  • 문제. 디지털 현금은 이중 지불 문제를 해결해야 합니다: 신뢰할 수 있는 청산소 없이 동일한 단위가 두 번 지불되는 것을 방지하는 것입니다. Bitcoin의 2008년 백서는 신뢰할 수 있는 중개자를 암호학적 증명과 분산 합의로 대체함으로써 이를 해결했습니다 (Nakamoto, 2008).
  • 데이터 구조. 블록체인은 각 블록 헤더에 이전 헤더의 SHA-256 해시가 포함된 블록의 연결 리스트입니다. 해시 체인은 역사를 추가 전용으로 만듭니다: 과거 블록을 변경하면 이후의 모든 해시가 무효화되어 공격자가 모든 후속 proof-of-work를 다시 수행해야 합니다.
  • Merkle 트리. 블록 내의 거래는 이진 Merkle 트리로 해시됩니다. 블록 헤더에 저장된 루트 해시는 전체 블록을 다운로드하지 않고도 개별 거래를 효율적으로 검증할 수 있게 합니다—경량 SPV 클라이언트의 기반입니다.
  • Ethereum의 확장. Ethereum의 옐로우 페이퍼(2014)는 EVM—모든 전체 노드에서 실행되는 결정론적 스택 머신—을 도입했습니다. 스마트 컨트랙트는 체인에 배포된 바이트코드입니다; 모든 노드에서 동일하게 실행되고 원자적으로 결제되어 신뢰할 수 있는 중개자를 자체 실행 코드로 대체합니다 (Wood, 2014).
  • 실용적 의의. 2017년 이후 배포된 모든 토큰화 자산, 스테이블코인, DeFi 프로토콜은 이러한 기반 위에서 실행됩니다. 해시 체인, Merkle 트리, EVM 실행 모델을 이해하는 것은 Ethereum 기반 시스템과 작업하기 위한 전제 조건입니다.

블록체인이 해결한 문제 #

Bitcoin 이전에는 이중 지불을 방지하기 위해 디지털 결제에 은행, 결제 처리업체 또는 청산소와 같은 신뢰할 수 있는 중개자가 필요했습니다. Alice가 £10을 나타내는 디지털 파일을 Bob에게 보냈다면, 파일 자체에는 Carol에게 동일한 사본을 보내는 것을 막을 수 있는 것이 아무것도 없었습니다. 모든 기존 시스템의 해결책은 중앙화된 기록 유지였습니다: 은행의 원장에 돈이 사용되었다고 명시되어 있으므로 다시 사용할 수 없었습니다.

Bitcoin의 기여는 그 신뢰할 수 있는 원장을 수천 개의 독립 노드에서 모든 거래 기록이 복제되는 분산 원장으로 대체한 것입니다. 노드 간의 상호 불신은 두 가지 메커니즘을 통해 보안으로 변환되었습니다:

  1. 암호학적 연결. 각 거래 블록에는 이전 블록의 해시가 포함됩니다. 해시 함수는 단방향 결정론적 매핑입니다: 주어진 입력에 대해 함수는 고정 길이 출력을 생성하며, 입력의 한 비트만 변경해도 완전히 다른 출력이 생성됩니다. 이는 역사적 블록에 대한 모든 변경이 그 이후의 모든 블록을 무효화한다는 것을 의미합니다.

  2. Proof-of-work 합의. 새 블록을 추가하려면 블록의 해시가 목표 임계값 아래로 떨어지는 nonce 값을 찾아야 합니다—찾기에는 계산적으로 비용이 많이 들지만 검증하기는 매우 저렴합니다. 이로 인해 역사를 다시 쓰는 것이 변경되는 블록의 깊이에 비례하여 비용이 많이 들게 됩니다. 공격자는 해당 블록에서 체인 끝까지의 모든 proof-of-work를 다시 수행해야 하기 때문입니다.

이 조합은 가장 많은 누적 proof-of-work를 가진 가장 긴 체인이 구조적으로 실제 자원을 사용하는 정직한 참여자들이 유지하는 것임을 의미합니다.

암호학적 구성 요소 #

블록체인 기술은 세 가지 기존 암호학적 기본 요소를 새로운 아키텍처로 조합합니다:

SHA-256 해시 함수 #

SHA-256(보안 해시 알고리즘 256비트)은 NIST가 표준화한 SHA-2 계열의 구성원입니다. 임의 길이의 입력을 받아 256비트 출력을 생성합니다. 블록체인 사용을 위한 핵심 속성:

  • 결정론적. 동일한 입력은 항상 동일한 출력을 생성합니다.
  • 역상 저항성. 해시 출력이 주어졌을 때 입력을 재구성하는 것은 계산적으로 불가능합니다.
  • 눈사태 효과. 입력의 한 비트를 변경하면 출력 비트의 약 절반이 변경되어 무차별 대입 검색이 비효율적입니다.
  • 충돌 저항성. 동일한 해시를 생성하는 두 가지 다른 입력을 찾는 것은 계산적으로 불가능합니다.

Bitcoin은 길이 확장 공격에 대한 추가 보안을 위해 SHA-256을 두 번 적용합니다(SHA-256d). Ethereum은 SHA-3 결선 진출 변형인 Keccak-256을 사용합니다.

Merkle 트리 #

Merkle 트리는 해시의 이진 트리입니다. 각 리프 노드는 거래의 해시입니다. 각 내부 노드는 두 자식의 해시입니다. 루트—Merkle 루트—는 블록의 모든 거래를 블록 헤더에 저장된 단일 32바이트 값으로 요약합니다.

실용적인 결과: 특정 거래가 블록에 포함되어 있는지 확인하려면 모든 n개 거래가 아닌 log₂(n)개 해시만 필요합니다. 2,000개의 거래가 있는 블록의 경우 2,000개가 아닌 11개의 해시만으로 검증이 가능합니다—경량 클라이언트의 간소화된 결제 검증(SPV)의 기반입니다.

디지털 서명(ECDSA) #

Bitcoin과 Ethereum에서의 거래 승인은 secp256k1 곡선 위의 타원 곡선 디지털 서명 알고리즘(ECDSA)을 사용합니다. 개인 키가 거래에 서명하며, 모든 노드는 개인 키를 알지 못해도 해당 공개 키를 사용하여 서명을 검증할 수 있습니다. 이를 통해 개인 키를 보유한 사람만이 주소에서 지출을 승인할 수 있습니다.

Ethereum 주소는 공개 키의 Keccak-256 해시의 마지막 20바이트입니다—이 파생 방식은 주소를 간결하고 이동 가능하게 하면서 암호학적으로 키 쌍에 연결된 상태를 유지합니다.

Bitcoin 블록체인 작동 방식 #

Bitcoin 블록에는 세 가지 논리적 구성 요소가 포함됩니다:

블록 헤더—80바이트로 구성됩니다: 프로토콜 버전, 이전 블록 헤더의 해시, 거래의 Merkle 루트, Unix 타임스탬프, 현재 난이도 목표 및 nonce. 채굴자는 헤더의 이중 SHA-256 해시가 난이도 목표 아래로 떨어질 때까지 nonce(때로는 coinbase 거래의 타임스탬프 또는 추가 nonce)를 반복합니다.

거래 목록—블록에 포함된 정렬된 거래 집합입니다. coinbase 거래(첫 번째)는 블록 보상과 거래 수수료를 채굴자의 주소에 할당합니다.

체인—헤더의 연결입니다. 체인의 누적 proof-of-work(모든 블록을 생성하기 위해 수행된 모든 작업의 합)가 어떤 포크가 정규 체인인지 결정합니다. 노드는 항상 가장 많은 누적 작업량을 가진 체인을 따릅니다.

Bitcoin의 블록 시간 목표는 10분입니다. 난이도는 총 네트워크 해시 속도가 변화함에 따라 그 목표를 유지하기 위해 매 2,016블록(약 2주)마다 조정됩니다.

Ethereum의 프로그래밍 가능 레이어 #

Ethereum은 Bitcoin의 거래 모델을 "가치 전송"에서 "코드 실행"으로 일반화했습니다. 주요 추가 사항:

이더리움 가상 머신(EVM). 모든 전체 노드에서 결정론적으로 실행되는 256비트 워드, 스택 기반 가상 머신입니다. 모든 opcode에는 명시적인 gas 비용이 있습니다. 계산은 블록 gas 한도로 제한되어 무한 루프가 네트워크를 중단시키는 것을 방지합니다. 동일한 상태에서 동일한 바이트코드를 실행하는 모든 노드는 동일한 출력을 생성해야 합니다—이 실행에 대한 합의가 스마트 컨트랙트를 신뢰 없이 만드는 것입니다.

계정. Ethereum에는 두 가지 계정 유형이 있습니다: 개인 키로 제어되는 외부 소유 계정(EOA), 코드가 체인에 저장된 컨트랙트 계정. 컨트랙트 주소로 전송된 거래는 컨트랙트의 바이트코드 실행을 트리거합니다.

상태. Ethereum의 전역 상태는 주소를 계정 상태(nonce, 잔액, 스토리지, 코드 해시)에 매핑합니다. 상태 루트—모든 계정 상태의 Merkle Patricia 트라이—는 각 블록 헤더에 포함되어 모든 블록 높이에서 모든 계정 상태를 효율적으로 증명할 수 있게 합니다.

Gas. 사용자는 모든 EVM 작업에 대해 gas(ETH 단위)를 지불합니다. Gas는 두 가지 기능을 합니다: 채굴자/검증자의 계산에 보상을 제공하고, 단일 거래가 소비할 수 있는 자원을 제한하여 비용이 많이 드는 작업을 통한 서비스 거부 공격을 방지합니다.

Solidity로 스마트 컨트랙트 작성하기 #

Solidity는 EVM 바이트코드로 컴파일되는 정적 타입, 컨트랙트 지향 언어입니다. 최소한의 토큰 컨트랙트가 핵심 개념을 설명합니다:

pragma solidity ^0.8.0;

contract MyToken {
    string public name;
    string public symbol;
    uint8 public decimals;
    uint256 public totalSupply;
    mapping(address => uint256) public balanceOf;

    event Transfer(address indexed from, address indexed to, uint256 value);

    constructor(
        string memory _name,
        string memory _symbol,
        uint8 _decimals,
        uint256 _totalSupply
    ) {
        name = _name;
        symbol = _symbol;
        decimals = _decimals;
        totalSupply = _totalSupply;
        balanceOf[msg.sender] = _totalSupply;
    }

    function transfer(address _to, uint256 _value) external returns (bool) {
        require(balanceOf[msg.sender] >= _value, "Insufficient balance");
        balanceOf[msg.sender] -= _value;
        balanceOf[_to] += _value;
        emit Transfer(msg.sender, _to, _value);
        return true;
    }
}

주요 관찰 사항: mapping(address => uint256)은 인메모리 데이터 구조가 아닌 EVM 스토리지 레이아웃입니다—읽기와 쓰기에 gas가 소비됩니다. require는 실패 시 전체 거래를 되돌리고 사용되지 않은 gas를 반환합니다. event Transfer는 오프체인 인덱서가 전체 상태를 다시 읽지 않고 이전을 추적하는 데 사용하는 로그를 발행합니다. constructor는 배포 시 한 번 실행됩니다; 이후 호출은 명명된 함수로 이동합니다.

ERC-20 표준은 대체 가능한 토큰에 대한 공통 인터페이스를 공식화했습니다—transfer, transferFrom, approve, allowance, balanceOf, totalSupply—이를 통해 ERC-20 호환 토큰이 커스텀 통합 없이 모든 ERC-20 지원 거래소 또는 지갑과 작동할 수 있습니다.

원장에서 금융 인프라로 #

여기서 설명된 블록체인 기본 요소들—해시 체인, Merkle 트리, EVM, ERC-20—은 2018년에서 2026년 사이에 더 광범위한 금융 애플리케이션의 기반이 되었습니다:

탈중앙화 금융(DeFi). 대출 프로토콜(Compound, Aave), 자동화된 시장 조성자(Uniswap), 수익 애그리게이터 모두 EVM 스마트 컨트랙트로 실행됩니다. 이들은 자체 실행 코드와 온체인 유동성 풀로 전통적인 금융 중개자의 청산, 보관 및 결제 기능을 대체합니다.

토큰화 자산. 중앙 은행과 상업 은행은 EVM 호환 체인의 허가된 변형에서 토큰화된 예금, 토큰화된 채권, 토큰화된 머니 마켓 펀드를 시범 운영하고 있습니다. 기본 메커니즘—해시로 보호된 상태 전환, 원자적 결제, 프로그래밍 가능한 이전 규칙—은 2014년 Ethereum 아키텍처의 직접적인 후손입니다.

중앙은행 디지털 화폐. Bank of England의 도매 CBDC 연구, ECB의 디지털 유로 프로그램, Project Agorá 모두 Bitcoin과 Ethereum의 기본 설계에서 파생되거나 호환되는 DLT 아키텍처를 탐구하고 있습니다. 허가 및 거버넌스 모델이 공개 블록체인과 완전히 다른 경우에도 합의 및 해시 체인 구조는 관련성을 유지합니다.

2008년 Bitcoin 백서에서 2026년 토큰화 금융까지의 여정은 20년에 걸쳐 있지만, 일관된 기술적 계보 위에서 실행됩니다. SHA-256 해시 체인이 불변성을 어떻게 강제하는지, Merkle 트리가 효율적인 검증을 어떻게 가능하게 하는지, EVM이 스마트 컨트랙트를 원자적으로 어떻게 실행하는지 이해하는 것은 규제된 금융 서비스에서 블록체인이 무엇을 할 수 있고 할 수 없는지에 대한 모든 주장을 평가하기 위한 전제 조건입니다.

자주 묻는 질문 #

블록체인과 분산 데이터베이스의 차이점은 무엇인가요?

전통적인 분산 데이터베이스는 가용성과 성능을 위해 노드 간에 데이터를 복제하지만 신뢰는 중앙화되어 있습니다—관리자가 레코드를 수정할 수 있습니다. 블록체인은 해시 체인과 합의를 통해 변조를 계산적으로 비용이 많이 들게 만듭니다: 모든 역사적 레코드를 수정하려면 모든 후속 proof-of-work 또는 proof-of-stake를 다시 수행하고 네트워크가 변경된 포크를 수락하도록 설득해야 합니다. 구별되는 속성은 접근 제어가 아닌 암호학과 인센티브 설계에 의해 강제되는 변조 방지입니다.

Ethereum이 SHA-256 대신 Keccak-256을 사용하는 이유는 무엇인가요?

Ethereum은 Keccak-256(NIST 표준화 조정 전 SHA-3 결선 진출자)을 채택했는데, 부분적으로는 설계자들이 Bitcoin이 이미 의존하는 SHA-2 계보에서 독립성을 원했기 때문입니다. Keccak은 또한 특정 EVM 작업에 매력적인 다른 대수적 속성을 가지고 있습니다. 개발자에 대한 실질적인 영향은 Ethereum 주소 파생과 스토리지 슬롯 해싱이 Bitcoin에서와 같이 SHA-256d가 아닌 Keccak-256을 사용한다는 것입니다.

EVM에서 "gas"는 무엇을 방지하나요?

Gas는 두 가지 범주의 공격을 방지합니다. 첫째, 계산적으로 비용이 많이 드는 작업을 통한 서비스 거부를 방지합니다: 모든 opcode에 gas가 소비되므로 공격자는 네트워크를 무비용으로 무한 루프를 실행하도록 강제할 수 없습니다. 둘째, 블록 gas 한도는 블록당 총 계산을 제한하여 전체 노드의 블록 검증 시간이 제한되고 예측 가능하게 유지되도록 합니다. Gas가 없으면 단일 컨트랙트 호출이 무한 계산을 실행하여 네트워크를 중단시킬 수 있습니다.

proof-of-stake는 proof-of-work에 비해 보안 모델을 어떻게 변경하나요?

proof-of-work에서 보안은 에너지 지출로 제공됩니다: 체인을 공격하려면 네트워크 해시 속도의 50% 이상을 제어해야 하며, 이는 물리적 하드웨어와 전력의 50% 이상을 제어하는 것을 의미합니다. proof-of-stake(2022년 머지 이후 Ethereum에서 사용)에서 보안은 경제적 지분으로 제공됩니다: 검증자는 ETH를 담보로 잠그며, 충돌하는 블록에 서명하면 삭감됩니다. 51% 공격은 모든 스테이킹된 ETH의 50% 이상을 획득하고 위험에 노출시켜야 합니다—하드웨어 및 에너지 비용이 아닌 자본 비용입니다. 합리적인 검증자가 자본 파괴보다 수수료 수입을 선호한다는 가정 하에 보안 모델은 다르지만 경제적 측면에서 수학적으로 비교 가능합니다.
