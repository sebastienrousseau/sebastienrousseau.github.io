Audio Analyser: Azure Speech, NLP, and Translation Pipeline

Azure 기반 음성 분석 도구의 아키텍처 및 파이프라인

TL;DR. Audio Analyser는 Azure Cognitive Services 음성-텍스트 변환 신경망 모델, Text Analytics NLP, CherryPy를 사용하여 음성 녹음을 감정 점수, 키워드 추출, 다국어 번역이 포함된 검색 가능한 트랜스크립트로 변환합니다.

Points clés

  • Audio Analyser 작동 방식: 아키텍처 개요. 파이프라인은 다섯 개의 개별 단계로 구성됩니다:.
  • Azure Cognitive Services: 배치 전사 엔진. Azure Speech 서비스 배치 전사 API(/speechtotext/v3.0/transcriptions)는 Azure Blob Storage의 오디오 파일에 대한 참조와 구성 JSON 본문을 수락합니다.
  • Azure AI Language를 사용한 자연어 처리. 전사 후 Audio Analyser는 azure-ai-textanalytics Python SDK를 통해 표시 형식의 전사본을 Azure AI Language로 전송합니다:.
  • Azure Translator를 통한 다국어 지원. Azure Translator는 사용자가 대상 언어를 요청할 때 언어 감지 후 호출됩니다.

경영진 요약 / 핵심 요점

  • Azure Batch Transcription API는 최대 2.5시간 길이의 오디오 파일(WAV/MP3/OGG/FLAC)을 수락하고 비동기적으로 처리하며, 구문별 nBest 후보, 신뢰도 점수, 역 텍스트 정규화(ITN) 출력 및 선택적 화자 분리 기능이 포함된 recognizedPhrases JSON 배열을 반환합니다 — 스트리밍 연결이 필요 없습니다(Microsoft Azure, 2024).
  • Microsoft의 신경망 음향 모델은 Switchboard 대화 벤치마크에서 기존 은닉 마르코프 모델(HMM) 기준선 대비 단어 오류율을 약 50% 감소시켜, 해당 데이터셋에서 약 5.1% WER로 전문 인간 전사자와 동등한 수준에 도달했습니다(Xiong 등, Microsoft Research, 2016/2021 업데이트).
  • Azure Text Analytics(현재 Azure AI Language의 일부)는 핵심 구문 추출, 명명된 엔티티 인식(NER), 의견 마이닝을 포함한 감정 분석 및 언어 감지를 통해 전사본 텍스트를 처리합니다 — Python SDK를 사용한 단일 analyze_sentiment 또는 begin_analyze_actions 호출로 모두 처리됩니다.
  • CherryPy는 웹 레이어를 제공합니다: URL 라우팅, 멀티파트 업로드 처리, 세션 관리, Jinja2 템플릿 렌더링을 오케스트레이션 오버헤드 없이 단일 저비용 VM에서 실행 가능한 최소한의 Python 프로세스로 처리합니다.
  • Azure Translator NMT는 소스 언어를 자동 감지하고 전사본을 135개 대상 언어 중 하나로 번역하여, 동일한 파이프라인 실행 내에서 원본 및 번역 텍스트 모두에 대한 다운스트림 NLP 분석을 가능하게 합니다.

Audio Analyser ⧉는 세 가지 Azure Cognitive Services를 단일 워크플로에 연결하는 오픈소스 Python 애플리케이션입니다: 음성 텍스트 변환을 위한 Batch Transcription, NLP를 위한 Azure AI Language(Text Analytics), 다국어 출력을 위한 Azure Translator. 웹 인터페이스는 CherryPy가 제공하며, 결과는 JSON, 일반 텍스트 또는 로컬 SQLite 데이터베이스에 저장할 수 있습니다.

이 문서는 각 파이프라인 단계의 기술 아키텍처, Azure API 계약 및 CherryPy 레이어에서 이루어진 설계 선택을 설명합니다.

Audio Analyser 작동 방식: 아키텍처 개요 #

파이프라인은 다섯 개의 개별 단계로 구성됩니다:

  1. 업로드 — 사용자가 CherryPy 웹 인터페이스를 통해 오디오 파일을 제출합니다. CherryPy는 파일을 임시 디렉터리에 저장하고 작업 ID를 반환합니다.
  2. 전사 — Audio Analyser는 Azure Batch Transcription REST API에 파일을 제출합니다. 배치 전사는 비동기적이므로 애플리케이션은 작업 상태 엔드포인트를 주기적으로 폴링하고 Succeeded 상태를 기다린 후 진행합니다.
  3. NLP — 원시 전사본 텍스트가 Azure AI Language로 전달되어 핵심 구문 추출, NER, 감정 분석 및 언어 감지가 수행됩니다.
  4. 번역(선택 사항) — 대상 언어가 지정된 경우 전사본이 Azure Translator로 전송되고, 번역된 텍스트에 대해 NLP 분석이 재실행됩니다.
  5. 출력 — 결과가 선택한 출력 형식(JSON, TXT 또는 SQLite)으로 작성되고 CherryPy 웹 UI에서 렌더링됩니다.

Python 표준 라이브러리 외부의 유일한 런타임 종속성은 azure-cognitiveservices-speech, azure-ai-textanalytics, azure-ai-translation-text 및 cherrypy입니다. 모든 Azure 자격 증명은 환경 변수에서 읽습니다.

Azure Cognitive Services: 배치 전사 엔진 #

Azure Speech 서비스 배치 전사 API(/speechtotext/v3.0/transcriptions)는 Azure Blob Storage의 오디오 파일에 대한 참조와 구성 JSON 본문을 수락합니다. Audio Analyser는 사전 서명된 SAS URL을 사용하여 로컬 파일을 Blob Storage에 업로드한 후 전사 작업을 제출합니다.

최소 작업 제출 페이로드:

{
  "contentUrls": ["https://<account>.blob.core.windows.net/<container>/<file>.wav?<sas>"],
  "locale": "en-US",
  "displayName": "audio-analyser-job-001",
  "properties": {
    "diarizationEnabled": true,
    "wordLevelTimestampsEnabled": true,
    "punctuationMode": "DictatedAndAutomatic",
    "profanityFilterMode": "Masked"
  }
}

응답의 recognizedPhrases 배열에는 인식된 발화당 하나의 객체가 포함됩니다. 각 항목에는 다음이 포함됩니다:

  • nBest[0].confidence — 0과 1 사이의 부동소수점 수
  • nBest[0].lexical — 발화된 원시 단어
  • nBest[0].itn — 역 텍스트 정규화 형식(숫자, 날짜, 통화 확장)
  • nBest[0].display — 구두점이 포함된 읽기 형식
  • speaker — 화자 분리 활성화 시 정수 화자 ID

Custom Speech 파인 튜닝은 도메인 특화 어휘에 사용할 수 있습니다. 발음 어휘집이나 적응 코퍼스(도메인을 대표하는 텍스트 문장 세트)를 업로드하면 언어 모델이 조정되고 금융 용어나 의학 용어와 같은 전문 콘텐츠의 WER을 크게 줄일 수 있습니다.

Azure AI Language를 사용한 자연어 처리 #

전사 후 Audio Analyser는 azure-ai-textanalytics Python SDK를 통해 표시 형식의 전사본을 Azure AI Language로 전송합니다:

from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential

client = TextAnalyticsClient(
    endpoint=os.environ["AZURE_LANGUAGE_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["AZURE_LANGUAGE_KEY"])
)

documents = [{"id": "1", "language": detected_lang, "text": transcript}]

sentiment_result = client.analyze_sentiment(documents, show_opinion_mining=True)
for doc in sentiment_result:
    print(f"Sentiment: {doc.sentiment}")
    print(f"Scores: pos={doc.confidence_scores.positive:.2f} "
          f"neg={doc.confidence_scores.negative:.2f} "
          f"neu={doc.confidence_scores.neutral:.2f}")
    for sentence in doc.sentences:
        for opinion in sentence.mined_opinions:
            print(f"  Target: {opinion.target.text}, "
                  f"Assessment: {[a.text for a in opinion.assessments]}")

keyphrases_result = client.extract_key_phrases(documents)
entities_result  = client.recognize_entities(documents)

show_opinion_mining=True는 측면 수준 감정 분석을 활성화합니다: API는 문서 수준 극성뿐만 아니라 특정 대상-평가 쌍(예: target="오디오 품질", assessment="불량")을 반환합니다. 이를 통해 고객 서비스 통화 분석에서 구체적인 문제를 파악하는 데 출력을 활용할 수 있습니다.

명명된 엔티티 인식은 텍스트 범위를 다음 중 하나로 분류합니다: Person, Organization, Location, Event, Product, DateTime, Quantity, IP, URL, Email, PersonType, Skill, Address, PhoneNumber.

Azure Translator를 통한 다국어 지원 #

Azure Translator는 사용자가 대상 언어를 요청할 때 언어 감지 후 호출됩니다. 이 서비스는 신경망 기계 번역(NMT)으로 135개 언어 및 방언을 지원합니다. Audio Analyser는 from 파라미터로 autodetect를 사용하는 /translate REST 엔드포인트를 사용하므로 소스 언어 지정이 필요 없습니다:

import requests, uuid

url = "https://api.cognitive.microsofttranslator.com/translate"
params = {"api-version": "3.0", "to": target_lang}
headers = {
    "Ocp-Apim-Subscription-Key": os.environ["AZURE_TRANSLATOR_KEY"],
    "Ocp-Apim-Subscription-Region": os.environ["AZURE_TRANSLATOR_REGION"],
    "Content-type": "application/json",
    "X-ClientTraceId": str(uuid.uuid4())
}
body = [{"text": transcript}]
response = requests.post(url, params=params, headers=headers, json=body)
translated_text = response.json()[0]["translations"][0]["text"]
detected_language = response.json()[0]["detectedLanguage"]["language"]

번역 후 Audio Analyser는 선택적으로 번역된 텍스트에 대해 Text Analytics NLP 처리를 재실행하여 소스 언어와 대상 언어 모두에서 핵심 구문 및 감정 출력을 사용할 수 있게 합니다.

출력 형식 선택(JSON, TXT, SQLite)은 시작 시 설정됩니다. SQLite 출력은 각 분석 세션을 작업 ID, 타임스탬프, 소스 언어, 전사본, 번역된 전사본, 감정 점수 및 JSON blob 형태의 핵심 구문 열이 있는 행으로 저장합니다 — 세션 간 SQL 쿼리가 가능합니다.

웹 레이어로서의 CherryPy #

CherryPy는 클래스 기반 컨트롤러를 사용하여 URL 경로를 Python 메서드에 매핑합니다. Audio Analyser는 세 가지 경로를 사용합니다:

경로 메서드 설명
GET / index() 업로드 양식 렌더링
POST /analyse analyse() 멀티파트 업로드 수락, 파이프라인 트리거, 작업 ID 반환
GET /results/<job_id> results() 작업 상태 폴링; 완료 시 결과 페이지 렌더링

최소 구성으로 서버 풋프린트를 작게 유지합니다:

import cherrypy

cherrypy.config.update({
    "server.socket_host": "0.0.0.0",
    "server.socket_port": 8080,
    "tools.sessions.on": True,
    "tools.sessions.timeout": 60
})
cherrypy.quickstart(AudioAnalyserApp(), "/", conf)

세션 상태는 현재 작업 ID, 선택한 출력 형식 및 대상 번역 언어를 보유합니다. CherryPy의 내장 세션 스토리지는 기본적으로 파일 기반이므로 외부 캐시 레이어가 필요 없습니다.

자주 묻는 질문 #

Audio Analyser는 어떤 오디오 형식과 파일 크기를 지원하나요? Azure Batch Transcription API는 최대 2.5시간 길이의 WAV, MP3, OGG 및 FLAC 파일을 지원합니다. 이 범위를 초과하는 파일은 업로드 전에 분할해야 합니다. 스테레오 파일이 지원되며, 모노 변환은 필요하지 않습니다.

화자 분리는 어떻게 작동하나요? 배치 전사 요청에서 diarizationEnabled: true를 설정하면 Azure의 화자 분리 모델이 활성화됩니다. 응답의 각 recognizedPhrase에는 speaker 정수 필드가 포함됩니다. 모델은 음향 특성으로 화자를 식별하고 세션 내에서 일관된 ID를 부여하지만, 별도의 음성 프로필 등록 단계 없이는 화자가 누구인지 식별하지 않습니다.

전사 후 오디오 파일이 보관되나요? 오디오 파일은 단기 SAS URL을 사용하여 Azure Blob Storage에 업로드되고 업로드 완료 후 임시 로컬 디렉터리에서 삭제됩니다. Azure Blob Storage의 blob 보존은 컨테이너의 수명 주기 정책에 따라 다릅니다. 기본적으로 Audio Analyser는 명시적인 삭제 정책을 설정하지 않으므로, 프로덕션 배포에서는 Azure 포털에서 단기 TTL 규칙(예: 1일 이상 된 blob 삭제)을 구성하는 것이 권장됩니다.

번역 없이 NLP 분석을 실행할 수 있나요? 예. 번역은 --target-lang CLI 플래그 또는 웹 UI의 대상 언어 드롭다운으로 제어되는 선택적 파이프라인 단계입니다. 대상 언어를 선택하지 않으면 파이프라인은 음성 텍스트 변환과 Text Analytics만 실행합니다.
