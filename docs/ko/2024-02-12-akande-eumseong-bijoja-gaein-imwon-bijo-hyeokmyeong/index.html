요약 / 핵심 내용

  • **Àkàndé ⧉**는 OpenAI Whisper 음성-텍스트 변환, GPT-4 채팅 완성, 로컬 SQLite 응답 캐시, fpdf2 PDF 내보내기를 단일 음성 기반 워크플로우로 연결하는 오픈소스 Python 음성 어시스턴트입니다. 클라우드 스토리지나 로컬 AI 모델 가중치가 필요 없습니다.
  • SQLite 캐시는 정규화된 쿼리 문자열의 SHA-256 해시를 원시 API 응답 텍스트에 매핑하여 저장합니다. 캐시 히트 시 토큰이 소모되지 않고 10ms 이내에 반환되어, 반복 쿼리(예: 회의 중 이전 결정 검토)가 사실상 무료입니다.
  • 다중 턴 대화는 메모리에서 messages 목록을 구축하고 모든 Chat Completions API 호출 시 이를 전달하여 유지됩니다. 모델은 전체 세션 기록을 받아 이전 교환을 참조할 수 있으며, 대신 턴당 토큰 사용량이 점진적으로 증가합니다.
  • PDF 요약 생성은 세션 messages 목록을 형식화된 fpdf2 문서로 직렬화합니다. 사용자 턴과 어시스턴트 턴이 레이블로 구분되고, 타임스탬프가 삽입되며, 자동 페이지 매김으로 모든 길이의 세션을 처리합니다. 파일은 로컬 파일 시스템에 저장됩니다.
  • 개인정보 보호 경계: 실시간 쿼리(및 컨텍스트 창 한도 내의 세션 기록)만 기기를 벗어납니다. 오디오 녹음, 전사본, 캐시된 응답은 OpenAI API 외의 어떤 원격 서비스에도 전송되지 않습니다.

Àkàndé ⧉는 세 가지 조합 가능한 구성 요소를 중심으로 구축된 오픈소스 Python 음성 어시스턴트입니다: 음성 인식을 위한 OpenAI Whisper, 언어 이해 및 생성을 위한 GPT-4 Chat Completions API, 그리고 응답 캐싱 및 세션 지속성을 위한 로컬 SQLite 데이터베이스입니다. 결과물은 로컬 모델 가중치, 오프라인 스토리지 인프라, 컨테이너 스택 없이 노트북에서 실행할 수 있는 음성 기반 워크플로우입니다.

이 글은 각 구성 요소의 기술 아키텍처, 캐싱 및 다중 턴 컨텍스트에 관한 설계 결정, PDF 내보내기 파이프라인을 설명합니다.

파이프라인 개요 #

단일 Àkàndé 상호작용은 다음 순서를 따릅니다:

  1. 오디오 캡처 — 사용자가 말합니다. 애플리케이션이 sounddevice 또는 호환 오디오 라이브러리를 사용하여 임시 WAV 파일에 오디오를 녹음합니다.
  2. 음성-텍스트 변환 — WAV 파일이 openai.audio.transcriptions.create()(Whisper API)에 제출됩니다. 전사본이 일반 문자열로 반환됩니다.
  3. 캐시 조회 — 전사본이 정규화(소문자 변환, 공백 압축)되고 SHA-256 해시됩니다. 해시가 로컬 SQLite response_cache 테이블에서 조회됩니다.
  4. API 호출 또는 캐시 히트 — 미스 발생 시, 전사본이 세션 messages 목록에 추가되어 openai.chat.completions.create()에 전송됩니다. 응답 텍스트는 캐시에 저장됩니다.
  5. 텍스트-음성 변환 — 응답 텍스트가 openai.audio.speech.create() 엔드포인트(TTS) 또는 로컬 TTS 라이브러리를 사용하여 오디오로 변환되어 재생됩니다.
  6. PDF 내보내기(요청 시) — 전체 messages 목록이 형식화된 fpdf2 문서로 직렬화되어 디스크에 기록됩니다.

OpenAI 통합: Chat Completions와 Whisper #

Àkàndé는 음성 인식과 텍스트 생성 모두에 openai Python SDK를 사용합니다. Whisper 전사 호출:

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

Chat Completions 호출은 세션 범위의 messages 목록을 유지합니다:

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

시스템 프롬프트는 세션 시작 시 한 번 앞에 추가되며, Àkàndé의 페르소나, 출력 형식, 도메인별 제약 조건을 제어합니다:

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

temperature=0.2를 설정하면 창의적 변형 대신 결정론을 선택하게 됩니다. 이는 세션 초반의 결정을 상기하는 사실 기반 쿼리에서 중요합니다.

SQLite 응답 캐시 #

캐시 스키마는 최소화되어 있습니다:

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

조회 및 쓰기 경로:

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

INSERT OR REPLACE는 모델 업그레이드 후 동일한 쿼리가 제출될 때 캐시된 응답이 업데이트되도록 보장합니다. TTL 기반 제거 쿼리(DELETE WHERE created_at < ?)를 시작 시 예약하여 캐시 크기를 제한할 수 있습니다.

캐시 히트 성능: 로컬 SSD에서 최대 약 100,000개 행의 테이블에 대한 SQLite 조회는 1ms 이내에 반환됩니다. 짧은 응답에 대한 GPT-4 API 실시간 호출의 왕복 대기 시간은 일반적으로 600–900ms입니다. 반복 쿼리가 몇 개 있는 일일 브리핑의 경우, 첫 번째 세션 이후 캐시가 대부분의 API 호출을 제거합니다.

PDF 요약 생성 #

PDF 내보내기는 이진 종속성이 없는 유지 관리 중인 Python PDF 라이브러리인 fpdf2를 사용합니다:

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell()은 줄 바꿈과 자동 페이지 나눔을 처리하므로, 어떤 길이의 세션이든 수동 페이지 매김 로직 없이 잘 형식화된 문서를 생성합니다. 출력물은 표준 Helvetica 메트릭을 초과하는 내장 글꼴 없이 PDF/A 호환 파일입니다.

개인정보 보호 모델 #

Àkàndé의 개인정보 보호 경계는 세 가지 사실로 정의됩니다:

  1. 오디오는 HTTPS를 통해 Whisper API에 제출되며, API 호출 이후 OpenAI에 의해 보존되지 않습니다(2024년 2월 기준 OpenAI API 데이터 사용 정책에 따름).
  2. Chat Completions API 호출은 세션 messages 목록을 전송합니다. 다중 턴 세션의 경우 전체 대화 기록을 포함할 수 있습니다.
  3. SQLite 데이터베이스와 PDF 파일은 완전히 로컬 파일 시스템에 존재하며, 어떤 클라우드 서비스에도 백그라운드 동기화가 발생하지 않습니다.

M&A 논의, 인사 문제, 규제 전략 등 민감한 주제를 다루는 임원 사용 사례의 경우, 배포 전에 API에 전송되는 세션 기록을 조직의 AI 사용 정책과 대조하여 검토해야 합니다. 시스템 프롬프트의 max_tokens 제한을 사용하여 의도된 공개 범위를 초과하는 컨텍스트의 의도치 않은 전송을 방지할 수 있습니다.

자주 묻는 질문 #

Àkàndé는 세션 종료 후 대화 기록을 보존하나요? 프로세스가 종료될 때 메모리 내 messages 목록이 삭제됩니다. 사용자가 PDF 내보내기를 트리거하거나 사용자 정의 지속성 레이어가 추가된 경우에만 대화 기록이 보존됩니다. SQLite 캐시는 쿼리 해시와 응답 텍스트를 저장하며, 전체 대화 컨텍스트는 저장하지 않습니다.

캐시는 유사하지만 동일하지 않은 쿼리를 어떻게 처리하나요? 캐시는 정규화된 쿼리 문자열에 대해 정확 일치 해싱을 사용합니다. 단어 하나가 다른 두 쿼리는 다른 해시를 생성하여 별도의 API 호출을 발생시킵니다. 의미론적 캐싱(근사 중복 쿼리를 매칭하기 위한 임베딩 유사성 사용)은 추가 벡터 조회 단계가 필요하며 기본 구현에는 포함되어 있지 않습니다.

Àkàndé가 기본적으로 사용하는 GPT 모델은 무엇인가요? 2024년 2월 기준 기본값은 gpt-4-turbo-preview입니다. 모델 이름은 설정 매개변수이므로 어떤 OpenAI 채팅 완성 모델로도 대체할 수 있습니다. gpt-3.5-turbo로 전환하면 토큰당 API 비용이 약 20배 감소하지만 복잡한 다단계 쿼리의 추론 품질이 저하됩니다.

PDF 내보내기 형식을 사용자 정의할 수 있나요? 예. fpdf2 내보내기 함수는 messages 목록만을 필수 입력으로 받으므로, 내보내기 함수를 편집하여 글꼴, 여백, 페이지 크기, 헤더 내용, 레이블을 모두 변경할 수 있습니다. fpdf2는 이미지, 표, Unicode 글꼴 추가도 지원하여 특정 브랜드 요구 사항이 있는 조직을 위해 더 풍부한 문서 레이아웃을 구성할 수 있습니다.
