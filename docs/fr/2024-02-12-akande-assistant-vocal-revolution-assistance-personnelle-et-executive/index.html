Résumé exécutif / Points clés

  • Àkàndé ⧉ est un assistant vocal Python open-source qui enchaîne OpenAI Whisper pour la conversion parole-texte, les complétions de chat GPT-4, un cache de réponses SQLite local et l'export PDF fpdf2 en un seul flux de travail vocal ne nécessitant ni stockage cloud ni poids de modèle IA local.
  • Le cache SQLite stocke des hachages SHA-256 de chaînes de requêtes normalisées associés au texte brut des réponses API ; les accès au cache ne coûtent aucun token et retournent en moins de 10 ms, rendant les requêtes répétées (comme la révision d'une décision prise plus tôt en réunion) essentiellement gratuites.
  • La conversation multi-tour est maintenue en construisant la liste messages en mémoire et en la transmettant à chaque appel API Chat Completions — le modèle reçoit l'historique complet de la session afin de pouvoir se référer aux échanges antérieurs, au prix d'une utilisation croissante des tokens à chaque tour.
  • La génération de résumés PDF sérialise la liste messages de la session dans un document fpdf2 formaté : les tours utilisateur et assistant sont étiquetés, les horodatages sont insérés, et la pagination automatique gère les sessions de n'importe quelle longueur ; le fichier est écrit dans le système de fichiers local, pas téléchargé.
  • Frontière de confidentialité : seule la requête en cours (et l'historique de session jusqu'à la limite de la fenêtre de contexte) quitte l'appareil — aucun enregistrement audio, aucune transcription et aucune réponse mise en cache n'est envoyé à un service distant autre que l'API OpenAI.

Àkàndé ⧉ est un assistant vocal Python open-source construit autour de trois composants modulables : OpenAI Whisper pour la reconnaissance vocale, l'API GPT-4 Chat Completions pour la compréhension et la génération du langage, et une base de données SQLite locale pour la mise en cache des réponses et la persistance des sessions. Le résultat est un flux de travail vocal exécutable sur un ordinateur portable sans poids de modèle local, infrastructure de stockage hors ligne ni pile de conteneurs.

Cet article décrit l'architecture technique de chaque composant, les décisions de conception concernant la mise en cache et le contexte multi-tour, ainsi que le pipeline d'export PDF.

Vue d'ensemble du pipeline #

Une interaction Àkàndé suit cette séquence :

  1. Capture audio — l'utilisateur parle ; l'application enregistre l'audio dans un fichier WAV temporaire via sounddevice ou une bibliothèque audio compatible.
  2. Conversion parole-texte — le fichier WAV est soumis à openai.audio.transcriptions.create() (API Whisper) ; la transcription est renvoyée sous forme de chaîne brute.
  3. Recherche dans le cache — la transcription est normalisée (mise en minuscules, espaces réduits) et hachée en SHA-256 ; le hachage est recherché dans la table SQLite locale response_cache.
  4. Appel API ou accès au cache — en cas d'échec du cache, la transcription est ajoutée à la liste messages de la session et envoyée à openai.chat.completions.create() ; le texte de réponse est stocké dans le cache.
  5. Synthèse vocale — le texte de réponse est converti en audio via l'endpoint openai.audio.speech.create() (TTS) ou une bibliothèque TTS locale, puis restitué.
  6. Export PDF (à la demande) — la liste complète messages est sérialisée dans un document fpdf2 formaté et écrite sur disque.

Intégration OpenAI : Chat Completions et Whisper #

Àkàndé utilise le SDK Python openai pour la reconnaissance vocale et la génération de texte. L'appel de transcription Whisper :

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

L'appel Chat Completions maintient une liste messages à portée de session :

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

Le prompt système est ajouté une seule fois au début de la session et contrôle la persona d'Àkàndé, le format de sortie et les contraintes propres au domaine :

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

La valeur temperature=0.2 privilégie le déterminisme sur la variation créative — essentiel pour les requêtes factuelles comme la mémorisation d'une décision prise plus tôt dans la session.

Cache de réponses SQLite #

Le schéma du cache est minimal :

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

Le chemin de lecture et d'écriture :

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

L'instruction INSERT OR REPLACE garantit qu'une réponse mise en cache est mise à jour si la même requête est soumise après une mise à niveau du modèle. Une requête d'éviction basée sur TTL (DELETE WHERE created_at < ?) peut être planifiée au démarrage pour limiter la taille du cache.

Performance des accès au cache : une recherche SQLite sur un SSD local retourne en moins de 1 ms pour des tables allant jusqu'à ~100 000 lignes. La latence aller-retour d'un appel API GPT-4 en direct est typiquement de 600–900 ms pour des réponses courtes. Pour un briefing quotidien avec quelques requêtes répétées, le cache élimine la plupart des appels API après la première session.

Génération de résumés PDF #

L'export PDF utilise fpdf2, une bibliothèque Python PDF maintenue sans dépendances binaires :

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell() gère le retour à la ligne et les sauts de page automatiques, de sorte que les sessions de n'importe quelle longueur produisent un document bien formaté sans logique de pagination manuelle. Le résultat est un fichier compatible PDF/A sans polices intégrées au-delà des métriques Helvetica standard.

Modèle de confidentialité #

La frontière de confidentialité dans Àkàndé est définie par trois faits :

  1. L'audio est soumis à l'API Whisper via HTTPS et n'est pas conservé par OpenAI au-delà de l'appel API (conformément à la politique d'utilisation des données API d'OpenAI en vigueur en février 2024).
  2. Les appels à l'API Chat Completions transmettent la liste messages de la session — qui peut contenir l'historique complet de la conversation pour les sessions multi-tours.
  3. La base de données SQLite et les fichiers PDF résident entièrement sur le système de fichiers local ; aucune synchronisation en arrière-plan vers un service cloud ne se produit.

Pour les cas d'usage exécutifs impliquant des sujets sensibles — discussions de F&A, questions de personnel, stratégie réglementaire — l'historique de session transmis à l'API doit être examiné par rapport à la politique d'utilisation de l'IA de l'organisation avant tout déploiement. La limite max_tokens sur le prompt système peut être utilisée pour empêcher la transmission involontaire d'un contexte dépassant la portée de divulgation prévue.

Questions fréquentes #

Àkàndé conserve-t-il l'historique des conversations après la fin de la session ? La liste messages en mémoire est abandonnée à la fermeture du processus. L'historique des conversations n'est conservé que si l'utilisateur déclenche un export PDF ou si une couche de persistance personnalisée est ajoutée. Le cache SQLite stocke les hachages de requêtes et le texte des réponses, pas le contexte complet de la conversation.

Comment le cache gère-t-il les requêtes similaires mais non identiques ? Le cache utilise un hachage exact sur la chaîne de requête normalisée. Deux requêtes différant d'un seul mot produiront des hachages différents et entraîneront des appels API distincts. La mise en cache sémantique (utilisant la similarité des embeddings pour correspondre aux requêtes quasi-dupliquées) nécessiterait une étape de recherche vectorielle supplémentaire et ne fait pas partie de l'implémentation de base.

Quel modèle GPT Àkàndé utilise-t-il par défaut ? Par défaut, c'est gpt-4-turbo-preview depuis février 2024. Le nom du modèle est un paramètre de configuration, tout modèle de complétion de chat OpenAI peut donc lui être substitué. Passer à gpt-3.5-turbo réduit le coût API d'environ 20× par token, mais diminue la qualité de raisonnement pour les requêtes complexes en plusieurs étapes.

Le format d'export PDF peut-il être personnalisé ? Oui. La fonction d'export fpdf2 accepte la liste messages comme seule entrée obligatoire ; la police, les marges, la taille de la page, le contenu de l'en-tête et les étiquettes peuvent tous être modifiés en éditant la fonction d'export. fpdf2 prend également en charge l'ajout d'images, de tableaux et de polices Unicode, permettant des mises en page de documents plus riches pour les organisations ayant des exigences spécifiques en matière d'image de marque.
