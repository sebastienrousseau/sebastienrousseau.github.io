Audio Analyser: Azure Speech, NLP, and Translation Pipeline

कार्यकारी सारांश / मुख्य बातें

  • Azure Batch Transcription API 2.5 घंटे तक की ऑडियो फाइलें (WAV/MP3/OGG/FLAC) स्वीकार करता है, उन्हें एसिंक्रोनस रूप से प्रोसेस करता है और प्रति-वाक्यांश nBest कैंडिडेट, कॉन्फिडेंस स्कोर, इनवर्स-टेक्स्ट-नॉर्मलाइज्ड (ITN) आउटपुट, और वैकल्पिक स्पीकर diarisation के साथ recognizedPhrases JSON एरे वापस करता है — स्ट्रीमिंग कनेक्शन आवश्यक नहीं (Microsoft Azure, 2024)।
  • Microsoft के न्यूरल अकॉस्टिक मॉडल ने Switchboard बातचीत बेंचमार्क पर पुराने हिडन मार्कोव मॉडल (HMM) बेसलाइन की तुलना में वर्ड एरर रेट को लगभग 50% कम किया, उस डेटासेट पर ~5.1% WER पर पेशेवर मानव ट्रांसक्राइबर के साथ समानता हासिल की (Xiong et al., Microsoft Research, 2016/2021 अपडेट)।
  • Azure Text Analytics (अब Azure AI Language का हिस्सा) ट्रांसक्रिप्ट टेक्स्ट को की फ्रेज़ एक्सट्रैक्शन, नामित इकाई पहचान (NER), ओपिनियन माइनिंग के साथ सेंटिमेंट एनालिसिस और भाषा पहचान के माध्यम से प्रोसेस करता है — Python SDK का उपयोग करके एकल analyze_sentiment या begin_analyze_actions कॉल में।
  • CherryPy वेब लेयर प्रदान करता है: URL रूटिंग, मल्टीपार्ट अपलोड हैंडलिंग, सेशन मैनेजमेंट और Jinja2 टेम्पलेट रेंडरिंग एक न्यूनतम Python प्रक्रिया में जो ऑर्केस्ट्रेशन ओवरहेड के बिना एकल कम-लागत VM पर चल सकती है।
  • Azure Translator NMT स्वचालित रूप से स्रोत भाषा का पता लगाता है और ट्रांसक्रिप्ट को 135 लक्ष्य भाषाओं में से किसी में भी अनुवाद करता है, जिससे एक ही पाइपलाइन रन में मूल और अनुवादित टेक्स्ट दोनों पर डाउनस्ट्रीम NLP विश्लेषण संभव होता है।

Audio Analyser ⧉ एक ओपन-सोर्स Python एप्लिकेशन है जो तीन Azure Cognitive Services को एक वर्कफ़्लो में जोड़ता है: स्पीच-टू-टेक्स्ट के लिए Batch Transcription, NLP के लिए Azure AI Language (Text Analytics) और बहुभाषी आउटपुट के लिए Azure Translator। वेब इंटरफेस CherryPy द्वारा सर्व किया जाता है, और परिणाम JSON, प्लेन टेक्स्ट, या लोकल SQLite डेटाबेस में सहेजे जा सकते हैं।

यह लेख प्रत्येक पाइपलाइन चरण की तकनीकी आर्किटेक्चर, Azure API अनुबंध और CherryPy लेयर में लिए गए डिज़ाइन निर्णयों का वर्णन करता है।

Audio Analyser कैसे काम करता है: आर्किटेक्चर अवलोकन #

पाइपलाइन के पाँच अलग चरण हैं:

  1. अपलोड — उपयोगकर्ता CherryPy वेब इंटरफेस के माध्यम से एक ऑडियो फाइल सबमिट करता है। CherryPy फाइल को एक अस्थायी डायरेक्टरी में स्टोर करता है और एक जॉब ID वापस करता है।
  2. ट्रांसक्रिप्शन — Audio Analyser फाइल को Azure Batch Transcription REST API पर सबमिट करता है। चूंकि बैच ट्रांसक्रिप्शन एसिंक्रोनस है, एप्लिकेशन अंतराल पर जॉब स्टेटस एंडपॉइंट को पोल करता है और आगे बढ़ने से पहले Succeeded अवस्था की प्रतीक्षा करता है।
  3. NLP — रॉ ट्रांसक्रिप्ट टेक्स्ट को की फ्रेज़ एक्सट्रैक्शन, NER, सेंटिमेंट एनालिसिस और भाषा पहचान के लिए Azure AI Language को पास किया जाता है।
  4. अनुवाद (वैकल्पिक) — यदि लक्ष्य भाषा निर्दिष्ट है, तो ट्रांसक्रिप्ट Azure Translator को भेजा जाता है और अनुवादित टेक्स्ट पर NLP विश्लेषण फिर से चलाया जाता है।
  5. आउटपुट — परिणाम चयनित आउटपुट फॉर्मेट (JSON, TXT या SQLite) में लिखे जाते हैं और CherryPy वेब UI में रेंडर होते हैं।

Python स्टैंडर्ड लाइब्रेरी के बाहर एकमात्र रनटाइम डिपेंडेंसी हैं: azure-cognitiveservices-speech, azure-ai-textanalytics, azure-ai-translation-text और cherrypy। सभी Azure क्रेडेंशियल एनवायरनमेंट वेरिएबल से पढ़े जाते हैं।

Azure Cognitive Services: बैच ट्रांसक्रिप्शन इंजन #

Azure Speech service बैच ट्रांसक्रिप्शन API (/speechtotext/v3.0/transcriptions) Azure Blob Storage में ऑडियो फाइल का संदर्भ और एक कॉन्फिगरेशन JSON बॉडी स्वीकार करता है। Audio Analyser प्री-साइन्ड SAS URL का उपयोग करके लोकल फाइल को Blob Storage में अपलोड करता है, फिर ट्रांसक्रिप्शन जॉब सबमिट करता है।

न्यूनतम जॉब सबमिशन पेलोड:

{
  "contentUrls": ["https://<account>.blob.core.windows.net/<container>/<file>.wav?<sas>"],
  "locale": "en-US",
  "displayName": "audio-analyser-job-001",
  "properties": {
    "diarizationEnabled": true,
    "wordLevelTimestampsEnabled": true,
    "punctuationMode": "DictatedAndAutomatic",
    "profanityFilterMode": "Masked"
  }
}

रिस्पॉन्स में recognizedPhrases एरे में प्रत्येक पहचाने गए उच्चारण के लिए एक ऑब्जेक्ट होता है। प्रत्येक एंट्री में शामिल हैं:

  • nBest[0].confidence — 0 और 1 के बीच फ्लोट
  • nBest[0].lexical — जैसा बोला गया कच्चे शब्द
  • nBest[0].itn — इनवर्स-टेक्स्ट-नॉर्मलाइज्ड फॉर्म (संख्याएं, तारीखें, मुद्राएं विस्तारित)
  • nBest[0].display — पंक्चुएशन के साथ पढ़ने के लिए फॉर्मेट किया गया
  • speaker — diarisation सक्षम होने पर इंटीजर स्पीकर ID

डोमेन-विशिष्ट शब्दावली के लिए Custom Speech फाइन-ट्यूनिंग उपलब्ध है। एक उच्चारण लेक्सिकॉन या अडेप्टेशन कॉर्पस (डोमेन का प्रतिनिधित्व करने वाले टेक्स्ट वाक्यों का एक सेट) अपलोड करना भाषा मॉडल को समायोजित करता है और वित्तीय शब्दों या चिकित्सा जार्गन जैसी विशेष सामग्री पर WER को काफी कम कर सकता है।

Azure AI Language के साथ नेचुरल लैंग्वेज प्रोसेसिंग #

ट्रांसक्रिप्शन के बाद, Audio Analyser azure-ai-textanalytics Python SDK के माध्यम से डिस्प्ले-फॉर्म ट्रांसक्रिप्ट को Azure AI Language को भेजता है:

from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential

client = TextAnalyticsClient(
    endpoint=os.environ["AZURE_LANGUAGE_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["AZURE_LANGUAGE_KEY"])
)

documents = [{"id": "1", "language": detected_lang, "text": transcript}]

sentiment_result = client.analyze_sentiment(documents, show_opinion_mining=True)
for doc in sentiment_result:
    print(f"Sentiment: {doc.sentiment}")
    print(f"Scores: pos={doc.confidence_scores.positive:.2f} "
          f"neg={doc.confidence_scores.negative:.2f} "
          f"neu={doc.confidence_scores.neutral:.2f}")
    for sentence in doc.sentences:
        for opinion in sentence.mined_opinions:
            print(f"  Target: {opinion.target.text}, "
                  f"Assessment: {[a.text for a in opinion.assessments]}")

keyphrases_result = client.extract_key_phrases(documents)
entities_result  = client.recognize_entities(documents)

show_opinion_mining=True एस्पेक्ट-लेवल सेंटिमेंट सक्षम करता है: API केवल डॉक्यूमेंट-लेवल पोलैरिटी नहीं बल्कि विशिष्ट टार्गेट–असेसमेंट जोड़े भी वापस करता है (जैसे, target="audio quality", assessment="poor")। यह आउटपुट को कस्टमर सर्विस कॉल एनालिसिस में ठोस समस्याओं की पहचान के लिए उपयोगी बनाता है।

नामित इकाई पहचान स्पैन को इनमें से एक के रूप में वर्गीकृत करती है: Person, Organization, Location, Event, Product, DateTime, Quantity, IP, URL, Email, PersonType, Skill, Address, PhoneNumber।

Azure Translator के माध्यम से बहुभाषी समर्थन #

Azure Translator को भाषा पहचान के बाद तब बुलाया जाता है जब उपयोगकर्ता लक्ष्य भाषा का अनुरोध करता है। सर्विस न्यूरल मशीन ट्रांसलेशन (NMT) के साथ 135 भाषाओं और बोलियों का समर्थन करती है। Audio Analyser from पैरामीटर के रूप में autodetect के साथ /translate REST एंडपॉइंट का उपयोग करता है, इसलिए स्रोत-भाषा विशिष्टता की आवश्यकता नहीं:

import requests, uuid

url = "https://api.cognitive.microsofttranslator.com/translate"
params = {"api-version": "3.0", "to": target_lang}
headers = {
    "Ocp-Apim-Subscription-Key": os.environ["AZURE_TRANSLATOR_KEY"],
    "Ocp-Apim-Subscription-Region": os.environ["AZURE_TRANSLATOR_REGION"],
    "Content-type": "application/json",
    "X-ClientTraceId": str(uuid.uuid4())
}
body = [{"text": transcript}]
response = requests.post(url, params=params, headers=headers, json=body)
translated_text = response.json()[0]["translations"][0]["text"]
detected_language = response.json()[0]["detectedLanguage"]["language"]

अनुवाद के बाद, Audio Analyser वैकल्पिक रूप से अनुवादित टेक्स्ट पर Text Analytics NLP पास फिर से चलाता है ताकि की फ्रेज़ और सेंटिमेंट आउटपुट स्रोत और लक्ष्य दोनों भाषाओं में उपलब्ध हों।

आउटपुट फॉर्मेट चयन (JSON, TXT, SQLite) स्टार्टअप पर सेट किया जाता है। SQLite आउटपुट प्रत्येक एनालिसिस सेशन को जॉब ID, टाइमस्टैम्प, स्रोत भाषा, ट्रांसक्रिप्ट, अनुवादित ट्रांसक्रिप्ट, सेंटिमेंट स्कोर और JSON blob के रूप में की फ्रेज़ के लिए कॉलम के साथ एक पंक्ति के रूप में स्टोर करता है — सेशन में SQL क्वेरी सक्षम करता है।

CherryPy वेब लेयर के रूप में #

CherryPy क्लास-बेस्ड कंट्रोलर का उपयोग करके URL रूट को Python मेथड में मैप करता है। Audio Analyser तीन रूट का उपयोग करता है:

रूट मेथड विवरण
GET / index() अपलोड फॉर्म रेंडर करता है
POST /analyse analyse() मल्टीपार्ट अपलोड स्वीकार करता है, पाइपलाइन ट्रिगर करता है, जॉब ID वापस करता है
GET /results/<job_id> results() जॉब स्टेटस पोल करता है; पूर्ण होने पर रिजल्ट पेज रेंडर करता है

न्यूनतम कॉन्फिगरेशन सर्वर फुटप्रिंट छोटा रखती है:

import cherrypy

cherrypy.config.update({
    "server.socket_host": "0.0.0.0",
    "server.socket_port": 8080,
    "tools.sessions.on": True,
    "tools.sessions.timeout": 60
})
cherrypy.quickstart(AudioAnalyserApp(), "/", conf)

सेशन स्टेट वर्तमान जॉब ID, चयनित आउटपुट फॉर्मेट और लक्ष्य अनुवाद भाषा रखती है। CherryPy की बिल्ट-इन सेशन स्टोरेज डिफ़ॉल्ट रूप से फाइल-बैक्ड है, जिसके लिए कोई बाहरी कैश लेयर आवश्यक नहीं।

अक्सर पूछे जाने वाले प्रश्न #

Audio Analyser कौन से ऑडियो फॉर्मेट और फाइल आकार स्वीकार करता है? Azure Batch Transcription API 2.5 घंटे तक की WAV, MP3, OGG और FLAC फाइलों का समर्थन करता है। इस रेंज से बाहर की फाइलें अपलोड से पहले विभाजित की जानी चाहिए। स्टीरियो फाइलें स्वीकार की जाती हैं; मोनो रूपांतरण आवश्यक नहीं।

स्पीकर diarisation कैसे काम करती है? बैच ट्रांसक्रिप्शन अनुरोध में diarizationEnabled: true सेट करना Azure के स्पीकर सेपरेशन मॉडल को सक्रिय करता है। रिस्पॉन्स में प्रत्येक recognizedPhrase में एक speaker इंटीजर फील्ड शामिल होता है। मॉडल अकॉस्टिक विशेषताओं द्वारा स्पीकर की पहचान करता है और एक सेशन के भीतर सुसंगत ID असाइन करता है, लेकिन अलग वॉइस प्रोफाइल एनरोलमेंट चरण के बिना स्पीकर की पहचान नहीं करता।

क्या ट्रांसक्रिप्शन के बाद ऑडियो फाइलें रखी जाती हैं? ऑडियो फाइलें Azure Blob Storage पर शॉर्ट-लिव्ड SAS URL के साथ अपलोड की जाती हैं और अपलोड पूरा होने के बाद अस्थायी लोकल डायरेक्टरी से हटा दी जाती हैं। Azure Blob Storage में blobs की रिटेंशन कंटेनर की लाइफसाइकिल पॉलिसी पर निर्भर करती है; डिफ़ॉल्ट रूप से, Audio Analyser कोई स्पष्ट डिलीशन पॉलिसी सेट नहीं करता, इसलिए प्रोडक्शन डिप्लॉयमेंट के लिए Azure पोर्टल में शॉर्ट TTL नियम (जैसे, 1 दिन से पुराने blobs हटाएं) कॉन्फिगर करने की सिफारिश की जाती है।

क्या NLP विश्लेषण अनुवाद के बिना चलाया जा सकता है? हाँ। अनुवाद एक वैकल्पिक पाइपलाइन चरण है जिसे --target-lang CLI फ्लैग या वेब UI में लक्ष्य भाषा ड्रॉपडाउन द्वारा नियंत्रित किया जाता है। जब कोई लक्ष्य भाषा नहीं चुनी जाती, पाइपलाइन केवल स्पीच-टू-टेक्स्ट और Text Analytics चलाती है।
