# ADR-0014: The site's layouts come from a theme

**Site:** sebastienrousseau.com
**Author:** Sebastien Rousseau
**Status:** Accepted
**Date:** 2026-10-06
**Supersedes:** the hand-maintained `_layouts/index.html` shell and the slicing in `scripts/generators/gen_layouts.py`
**Related:** [ADR-0002](0002-pin-build-toolchains.md), [ADR-0003](0003-build-copy-pipeline.md), [native migration spec](../ssg-fixes-and-native-migration-spec.md)

---

## Context

The twelve files in `_layouts/` were 213 KB each: one shared shell with the
whole 184 KB stylesheet inlined, repeated per layout, generated by slicing
`index.html` at two markers and injecting a hero, a main region and a
JSON-LD block. Any change to the shell meant regenerating all twelve, and
the generator and the committed files drifted (the committed layouts no
longer carried the markers the generator cuts on).

ssg 0.0.50 and later resolve `{{#extends "base"}}`, `{{#block}}` and
`{{> partial}}` in the compile stage, and the official theme repository
(`ssg-themes.github.io`) publishes themes in exactly that shape.

## Decision

The theme `themes/sebastienrousseau/` in `ssg-themes.github.io` is the
source of truth for the site's layouts. It holds one shell
(`base.html`, `header.html`, `footer.html`, `styles.css`) and one small
layout per kind. The site consumes it flattened:
`tools/flatten.py --site <theme>/_layouts _layouts` resolves the
inheritance and inlines the stylesheet, because the postbuild reads the
flat files directly (`postbuild_assets._LAYOUT_WITH_CSP`,
`postbuild_transforms._theme_init_src_path`, the design-token freeze
test). The flattened files are committed, so a checkout builds without
the theme repository present; `make theme-sync` refreshes them.

Three changes separate the flattened files from the previous generated
ones. The head comment that documents the CSP no longer quotes a
literal `<script type="application/ld+json">` tag: three scanners that
are not comment-aware (`test_lang_no_leakage`, the theme gallery's
structured-data check and `ssg audit`) read it as a real block, and
`postbuild_assets._hashable_scripts` had to strip comments to work
around it. This is the one change that reaches a page, as an HTML
comment, and it is the only difference on every page between a build
from these layouts and the baseline. `{{!content}}` for `{{content}}` never reaches a page: identical on
staticdatagen 0.0.21 and later, and the raw form the theme gallery
mandates. `"inLanguage": "{{language}}"` for the hard-coded `"en-GB"` in
the JSON-LD graphs renders identically on English pages (every page
supplies `language`, which `<html lang>` already uses) and renders the
locale's value on translated pages, where `postbuild_lib.seo` rewrote
it afterwards; that rewrite becomes a no-op.

## Consequences

- `scripts/generators/gen_layouts.py` and `make regenerate` no longer
  produce the layouts; they stay for one iteration because the unit
  suite imports the module, and are removed with their tests next.
- A layout change is made in the theme, flattened, and the diff of
  `_layouts/` is reviewed in the site's pull request.
- Verification on 2026-10-06: the flattened layouts compiled through ssg
  0.0.66 produced HTML identical to the previous layouts on 14 sample
  pages; a full `./build.sh` from flattened layouts, hashed file by file
  against the baseline build, left every page identical and differed
  only in the per-locale feeds (`lastBuildDate` from the wall clock) and
  the changelog page (pull-request links read from git history, absent
  in the scratch checkout).
