Audio Analyser: Azure Speech, NLP, and Translation Pipeline

Arkitektur och pipeline för ett Azure-baserat talanalysverktyg

TL;DR. Audio Analyser använder Azures neurala speech-to-text-modeller, Text Analytics NLP och CherryPy för att omvandla ljudinspelningar till sökbara transkript med sentimentpoäng, nyckelordsextrahering och flerspråkiga översättningar.

Points clés

  • Hur Audio Analyser fungerar: Arkitekturöversikt. Pipeline har fem diskreta steg:.
  • Azure Cognitive Services: Batch-transkriptionsmotorn. Azure Speech-tjänstens API för batch-transkription (/speechtotext/v3.0/transcriptions) tar emot en referens till en ljudfil i Azure Blob Storage och en konfigurations-JSON-kropp.
  • Naturlig språkbehandling med Azure AI Language. Efter transkription skickar Audio Analyser transkriptet i visningsform till Azure AI Language via Python SDK azure-ai-textanalytics:.
  • Flerspråkigt stöd via Azure Translator. Azure Translator anropas efter språkidentifiering när användaren begär ett målspråk.

Sammanfattning / Viktiga slutsatser

  • Azure Batch Transcription API tar emot ljudfiler upp till 2,5 timmar (WAV/MP3/OGG/FLAC), bearbetar dem asynkront och returnerar en recognizedPhrases JSON-array med nBest-kandidater per fras, konfidensvärden, invers textnormaliserad (ITN) utdata och valfri talardiarisering — ingen strömmande anslutning krävs (Microsoft Azure, 2024).
  • Microsofts neurala akustiska modeller reducerade ordfelfrekvensen med ungefär 50 % i jämförelse med tidigare hidden Markov model (HMM)-baslinjer på Switchboard-konversationsbenchmarken och nådde paritet med professionella mänskliga transkribenter på det datasetet vid ~5,1 % WER (Xiong et al., Microsoft Research, 2016/uppdatering 2021).
  • Azure Text Analytics (numera en del av Azure AI Language) bearbetar transkripttext genom extrahering av nyckelfraser, igenkänning av namngivna entiteter (NER), sentimentanalys med åsiktsutvinning och språkidentifiering — allt i ett enda analyze_sentiment- eller begin_analyze_actions-anrop med Python SDK.
  • CherryPy tillhandahåller webbnivån: URL-routing, multipart-uppladdningshantering, sessionshantering och Jinja2-mallrendering i en minimal Python-process som kan köras på en enda billig VM utan orkestreringsoverhead.
  • Azure Translator NMT identifierar automatiskt källspråket och översätter transkript till valfritt av 135 målspråk, vilket möjliggör efterföljande NLP-analys på både originalet och den översatta texten inom samma pipeline-körning.

Audio Analyser ⧉ är ett Python-program med öppen källkod som kopplar samman tre Azure Cognitive Services i ett enda arbetsflöde: Batch Transcription för taligenkänning, Azure AI Language (Text Analytics) för NLP och Azure Translator för flerspråkig utdata. Webbgränssnittet hanteras av CherryPy och resultaten kan sparas till JSON, ren text eller en lokal SQLite-databas.

Den här artikeln beskriver den tekniska arkitekturen för varje pipeline-steg, Azure API-kontrakten och designvalen som gjorts i CherryPy-lagret.

Hur Audio Analyser fungerar: Arkitekturöversikt #

Pipeline har fem diskreta steg:

  1. Uppladdning — användaren skickar in en ljudfil via CherryPy-webbgränssnittet. CherryPy lagrar filen i en tillfällig katalog och returnerar ett jobb-ID.
  2. Transkription — Audio Analyser skickar filen till Azure Batch Transcription REST API. Eftersom batch-transkription är asynkron avfrågar applikationen jobbstatusens slutpunkt med jämna mellanrum och väntar på tillståndet Succeeded innan den fortsätter.
  3. NLP — den råa transkripttexten skickas till Azure AI Language för extrahering av nyckelfraser, NER, sentimentanalys och språkidentifiering.
  4. Översättning (valfritt) — om ett målspråk anges skickas transkriptet till Azure Translator och NLP-analysen körs om på den översatta texten.
  5. Utdata — resultaten skrivs till det valda utdataformatet (JSON, TXT eller SQLite) och renderas i CherryPy-webbgränssnittet.

De enda körtidsberoendena utanför Pythons standardbibliotek är azure-cognitiveservices-speech, azure-ai-textanalytics, azure-ai-translation-text och cherrypy. Alla Azure-uppgifter läses från miljövariabler.

Azure Cognitive Services: Batch-transkriptionsmotorn #

Azure Speech-tjänstens API för batch-transkription (/speechtotext/v3.0/transcriptions) tar emot en referens till en ljudfil i Azure Blob Storage och en konfigurations-JSON-kropp. Audio Analyser laddar upp den lokala filen till Blob Storage med en försignerad SAS-URL och skickar sedan transkriptionsjobbet.

En minimal payload för jobbinlämning:

{
  "contentUrls": ["https://<account>.blob.core.windows.net/<container>/<file>.wav?<sas>"],
  "locale": "en-US",
  "displayName": "audio-analyser-job-001",
  "properties": {
    "diarizationEnabled": true,
    "wordLevelTimestampsEnabled": true,
    "punctuationMode": "DictatedAndAutomatic",
    "profanityFilterMode": "Masked"
  }
}

Svarsarrayen recognizedPhrases innehåller ett objekt per igenkänt yttrande. Varje post inkluderar:

  • nBest[0].confidence — flyttal mellan 0 och 1
  • nBest[0].lexical — råa ord som de uttalades
  • nBest[0].itn — invers textnormaliserad form (tal, datum, valutor expanderade)
  • nBest[0].display — formaterad för läsning, med skiljetecken
  • speaker — heltalstalar-ID när diarisering är aktiverad

Finjustering av Custom Speech är tillgänglig för domänspecifikt ordförråd. Att ladda upp ett uttalslexikon eller ett anpassningscorpus (en uppsättning textmeningar som är representativa för domänen) justerar språkmodellen och kan avsevärt minska WER på specialiserat innehåll som finansiella termer eller medicinsk jargong.

Naturlig språkbehandling med Azure AI Language #

Efter transkription skickar Audio Analyser transkriptet i visningsform till Azure AI Language via Python SDK azure-ai-textanalytics:

from azure.ai.textanalytics import TextAnalyticsClient
from azure.core.credentials import AzureKeyCredential

client = TextAnalyticsClient(
    endpoint=os.environ["AZURE_LANGUAGE_ENDPOINT"],
    credential=AzureKeyCredential(os.environ["AZURE_LANGUAGE_KEY"])
)

documents = [{"id": "1", "language": detected_lang, "text": transcript}]

sentiment_result = client.analyze_sentiment(documents, show_opinion_mining=True)
for doc in sentiment_result:
    print(f"Sentiment: {doc.sentiment}")
    print(f"Scores: pos={doc.confidence_scores.positive:.2f} "
          f"neg={doc.confidence_scores.negative:.2f} "
          f"neu={doc.confidence_scores.neutral:.2f}")
    for sentence in doc.sentences:
        for opinion in sentence.mined_opinions:
            print(f"  Target: {opinion.target.text}, "
                  f"Assessment: {[a.text for a in opinion.assessments]}")

keyphrases_result = client.extract_key_phrases(documents)
entities_result  = client.recognize_entities(documents)

show_opinion_mining=True aktiverar aspektnivåsentiment: API:et returnerar inte bara dokumentnivåpolaritet utan specifika mål–bedömningspar (t.ex. target="ljudkvalitet", assessment="dålig"). Detta gör utdata användbar för att identifiera konkreta problem i analys av kundtjänstsamtal.

Igenkänning av namngivna entiteter klassificerar spann som ett av: Person, Organization, Location, Event, Product, DateTime, Quantity, IP, URL, Email, PersonType, Skill, Address, PhoneNumber.

Flerspråkigt stöd via Azure Translator #

Azure Translator anropas efter språkidentifiering när användaren begär ett målspråk. Tjänsten stöder 135 språk och dialekter med neural maskinöversättning (NMT). Audio Analyser använder REST-slutpunkten /translate med autodetect som from-parameter, så ingen källspråksspecifikation krävs:

import requests, uuid

url = "https://api.cognitive.microsofttranslator.com/translate"
params = {"api-version": "3.0", "to": target_lang}
headers = {
    "Ocp-Apim-Subscription-Key": os.environ["AZURE_TRANSLATOR_KEY"],
    "Ocp-Apim-Subscription-Region": os.environ["AZURE_TRANSLATOR_REGION"],
    "Content-type": "application/json",
    "X-ClientTraceId": str(uuid.uuid4())
}
body = [{"text": transcript}]
response = requests.post(url, params=params, headers=headers, json=body)
translated_text = response.json()[0]["translations"][0]["text"]
detected_language = response.json()[0]["detectedLanguage"]["language"]

Efter översättning kör Audio Analyser valfritt om Text Analytics NLP-passet på den översatta texten så att nyckelfraser och sentimentutdata är tillgängliga på både käll- och målspråken.

Val av utdataformat (JSON, TXT, SQLite) ställs in vid start. SQLite-utdatan lagrar varje analysession som en rad med kolumner för jobb-ID, tidsstämpel, källspråk, transkript, översatt transkript, sentimentpoäng och nyckelfraser som en JSON-blob — vilket möjliggör SQL-frågor över sessioner.

CherryPy som webblager #

CherryPy mappar URL-rutter till Python-metoder med klassbaserade kontroller. Audio Analyser använder tre rutter:

Rutt Metod Beskrivning
GET / index() Renderar uppladdningsformuläret
POST /analyse analyse() Tar emot multipart-uppladdning, utlöser pipeline, returnerar jobb-ID
GET /results/<job_id> results() Avfrågar jobbstatus; renderar resultatsidan när klar

Den minimala konfigurationen håller serverns fotavtryck litet:

import cherrypy

cherrypy.config.update({
    "server.socket_host": "0.0.0.0",
    "server.socket_port": 8080,
    "tools.sessions.on": True,
    "tools.sessions.timeout": 60
})
cherrypy.quickstart(AudioAnalyserApp(), "/", conf)

Sessionstillståndet håller det aktuella jobb-ID:t, valt utdataformat och målöversättningsspråk. CherryPys inbyggda sessionslagring är filbaserad som standard och kräver inget externt cachelager.

Vanliga frågor #

Vilka ljudformat och filstorlekar tar Audio Analyser emot? Azure Batch Transcription API stöder WAV-, MP3-, OGG- och FLAC-filer upp till 2,5 timmar i längd. Filer utanför detta intervall bör delas upp före uppladdning. Stereofiler accepteras; mono-konvertering krävs inte.

Hur fungerar talar-diarisering? Att ange diarizationEnabled: true i batch-transkriptionsbegäran aktiverar Azures talarspecifikationsmodell. Varje recognizedPhrase i svaret innehåller ett heltalsfält speaker. Modellen identifierar talare via akustiska egenskaper och tilldelar konsekventa ID:n inom en session, men identifierar inte vem talarna är utan ett separat steg för registrering av röstprofil.

Behålls ljudfiler efter transkription? Ljudfiler laddas upp till Azure Blob Storage med en kortlivad SAS-URL och raderas från den temporära lokala katalogen efter att uppladdningen är klar. Lagring av blobs i Azure Blob Storage beror på containerns livscykelprincip; som standard ställer Audio Analyser inte in någon explicit raderingsprincip, så att konfigurera en kort TTL-regel (t.ex. radera blobs äldre än 1 dag) i Azure-portalen rekommenderas för produktionsinstallationer.

Kan NLP-analysen köras utan översättning? Ja. Översättning är ett valfritt pipeline-steg som styrs av CLI-flaggan --target-lang eller rullgardinsmenyn för målspråk i webbgränssnittet. När inget målspråk väljs kör pipeline enbart taligenkänning och Text Analytics.
