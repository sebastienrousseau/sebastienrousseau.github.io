Àkàndé: GPT-Powered Voice Assistant for Executives

Architektur eines Open-Source-Python-Sprachassistenten: Whisper, GPT-4, SQLite-Cache und fpdf2

Zusammenfassung / Wichtige Erkenntnisse

  • Àkàndé ⧉ ist ein quelloffener Python-Sprachassistent, der OpenAI Whisper für die Spracherkennung, GPT-4-Chat-Vervollständigungen, einen lokalen SQLite-Antwortcache und den fpdf2-PDF-Export zu einem einzigen sprachgesteuerten Workflow verkettet, der weder Cloud-Speicher noch lokale KI-Modellgewichte benötigt.
  • Der SQLite-Cache speichert SHA-256-Hashes normalisierter Abfragezeichenketten, die dem rohen API-Antworttext zugeordnet sind; Cache-Treffer kosten null Token und liefern Ergebnisse in unter 10 ms, wodurch wiederholte Abfragen (wie das Nachschlagen einer früher in einer Besprechung getroffenen Entscheidung) praktisch kostenlos sind.
  • Der Mehrfachdialog wird durch den Aufbau der messages-Liste im Arbeitsspeicher und deren Übergabe bei jedem Chat Completions API-Aufruf aufrechterhalten — das Modell erhält den vollständigen Sitzungsverlauf, um auf frühere Austausche verweisen zu können, auf Kosten eines schrittweise steigenden Token-Verbrauchs pro Gesprächsschritt.
  • Die PDF-Zusammenfassungsgenerierung serialisiert die messages-Liste der Sitzung in ein formatiertes fpdf2-Dokument: Benutzerbeiträge und Assistentenbeiträge werden beschriftet, Zeitstempel eingefügt und die automatische Paginierung verwaltet Sitzungen beliebiger Länge; die Datei wird in das lokale Dateisystem geschrieben, nicht hochgeladen.
  • Datenschutzgrenze: Nur die aktuelle Abfrage (und der Sitzungsverlauf bis zur Kontextfensterbegrenzung) verlässt das Gerät — keine Audioaufnahmen, keine Transkripte und keine gecachten Antworten werden an einen anderen externen Dienst als die OpenAI-API gesendet.

Àkàndé ⧉ ist ein quelloffener Python-Sprachassistent, der auf drei modularen Komponenten basiert: OpenAI Whisper für die Spracherkennung, die GPT-4 Chat Completions API für das Sprachverständnis und die Sprachgenerierung sowie eine lokale SQLite-Datenbank für den Antwort-Cache und die Sitzungspersistenz. Das Ergebnis ist ein sprachgesteuerter Workflow, der auf einem Laptop ohne lokale Modellgewichte, Offline-Speicherinfrastruktur oder Container-Stack betrieben werden kann.

Dieser Artikel beschreibt die technische Architektur jeder Komponente, die Designentscheidungen rund um Caching und Mehrfachdialog-Kontext sowie die PDF-Export-Pipeline.

Pipeline-Übersicht #

Eine einzelne Àkàndé-Interaktion folgt dieser Abfolge:

  1. Audioaufnahme — der Benutzer spricht; die Anwendung zeichnet Audio in eine temporäre WAV-Datei auf, unter Verwendung von sounddevice oder einer kompatiblen Audiobibliothek.
  2. Spracherkennung — die WAV-Datei wird an openai.audio.transcriptions.create() (Whisper API) übermittelt; das Transkript wird als einfache Zeichenkette zurückgegeben.
  3. Cache-Suche — das Transkript wird normalisiert (Kleinschreibung, Leerzeichen reduziert) und mit SHA-256 gehasht; der Hash wird in der lokalen SQLite-Tabelle response_cache nachgeschlagen.
  4. API-Aufruf oder Cache-Treffer — bei einem Fehlschlag wird das Transkript an die messages-Liste der Sitzung angehängt und an openai.chat.completions.create() gesendet; der Antworttext wird im Cache gespeichert.
  5. Text-zu-Sprache — der Antworttext wird über den Endpunkt openai.audio.speech.create() (TTS) oder eine lokale TTS-Bibliothek in Audio umgewandelt und abgespielt.
  6. PDF-Export (auf Abruf) — die vollständige messages-Liste wird in ein formatiertes fpdf2-Dokument serialisiert und auf den Datenträger geschrieben.

OpenAI-Integration: Chat Completions und Whisper #

Àkàndé verwendet das Python-SDK openai sowohl für die Spracherkennung als auch für die Textgenerierung. Der Whisper-Transkriptionsaufruf:

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

Der Chat-Completions-Aufruf pflegt eine sitzungsbezogene messages-Liste:

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

Der System-Prompt wird einmal zu Beginn der Sitzung vorangestellt und steuert Àkàndés Persona, das Ausgabeformat und domänenspezifische Einschränkungen:

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

Die Einstellung temperature=0.2 tauscht kreative Variation gegen Determinismus — wichtig für sachliche Abfragen wie das Abrufen einer früher in der Sitzung getroffenen Entscheidung.

SQLite-Antwortcache #

Das Cache-Schema ist minimal gehalten:

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

Der Such- und Schreibpfad:

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

INSERT OR REPLACE stellt sicher, dass eine gecachte Antwort aktualisiert wird, wenn dieselbe Abfrage nach einem Modell-Upgrade eingereicht wird. Eine TTL-basierte Bereinigungsabfrage (DELETE WHERE created_at < ?) kann beim Start geplant werden, um die Cache-Größe zu begrenzen.

Cache-Trefferleistung: Eine SQLite-Suche auf einer lokalen SSD liefert für Tabellen mit bis zu ~100.000 Zeilen Ergebnisse in unter 1 ms. Die Roundtrip-Latenz für einen GPT-4-API-Aufruf in Echtzeit beträgt für kurze Antworten typischerweise 600–900 ms. Für ein tägliches Briefing mit einigen wenigen wiederholten Abfragen eliminiert der Cache nach der ersten Sitzung die meisten API-Aufrufe.

PDF-Zusammenfassungsgenerierung #

Der PDF-Export verwendet fpdf2, eine gepflegte Python-PDF-Bibliothek ohne binäre Abhängigkeiten:

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell() übernimmt den Zeilenumbruch und die automatischen Seitenumbrüche, sodass Sitzungen beliebiger Länge ein gut formatiertes Dokument ohne manuelle Paginierungslogik erzeugen. Die Ausgabe ist eine PDF/A-kompatible Datei ohne eingebettete Schriftarten, abgesehen von den Standard-Helvetica-Metriken.

Datenschutzmodell #

Die Datenschutzgrenze in Àkàndé wird durch drei Tatsachen definiert:

  1. Audio wird über HTTPS an die Whisper API übermittelt und von OpenAI nicht über den API-Aufruf hinaus gespeichert (gemäß der API-Datennutzungsrichtlinie von OpenAI vom Februar 2024).
  2. Chat Completions API-Aufrufe übertragen die messages-Liste der Sitzung — die bei Mehrfachdialog-Sitzungen den vollständigen Gesprächsverlauf enthalten kann.
  3. Die SQLite-Datenbank und PDF-Dateien befinden sich vollständig im lokalen Dateisystem; keine Hintergrundsynchronisation mit einem Cloud-Dienst findet statt.

Für Führungskräfte-Anwendungsfälle mit sensiblen Themen — M&A-Gespräche, Personalangelegenheiten, regulatorische Strategie — sollte der an die API übermittelte Sitzungsverlauf vor dem Einsatz anhand der KI-Nutzungsrichtlinie der Organisation überprüft werden. Die max_tokens-Begrenzung im System-Prompt kann verwendet werden, um die unbeabsichtigte Übertragung von Kontext zu verhindern, der den beabsichtigten Offenbarungsumfang übersteigt.

Häufig gestellte Fragen #

Behält Àkàndé den Gesprächsverlauf nach dem Sitzungsende? Die messages-Liste im Arbeitsspeicher wird beim Beenden des Prozesses verworfen. Der Gesprächsverlauf wird nur dann beibehalten, wenn der Benutzer einen PDF-Export auslöst oder eine benutzerdefinierte Persistenzschicht hinzugefügt wird. Der SQLite-Cache speichert Abfrage-Hashes und Antworttexte, nicht den vollständigen Gesprächskontext.

Wie geht der Cache mit ähnlichen, aber nicht identischen Abfragen um? Der Cache verwendet Exact-Match-Hashing auf der normalisierten Abfragezeichenkette. Zwei Abfragen, die sich um ein einziges Wort unterscheiden, erzeugen unterschiedliche Hashes und führen zu separaten API-Aufrufen. Semantisches Caching (das Embedding-Ähnlichkeit verwendet, um nahezu doppelte Abfragen abzugleichen) würde einen zusätzlichen Vektorsuche-Schritt erfordern und ist nicht Teil der Basisimplementierung.

Welches GPT-Modell verwendet Àkàndé standardmäßig? Der Standardwert ist gpt-4-turbo-preview seit Februar 2024. Der Modellname ist ein Konfigurationsparameter, sodass jedes OpenAI-Chat-Vervollständigungsmodell ersetzt werden kann. Der Wechsel zu gpt-3.5-turbo reduziert die API-Kosten um etwa den Faktor 20 pro Token, senkt jedoch die Qualität der Schlussfolgerungen bei komplexen mehrstufigen Abfragen.

Kann das PDF-Exportformat angepasst werden? Ja. Die fpdf2-Exportfunktion akzeptiert die messages-Liste als einzige erforderliche Eingabe, sodass Schriftart, Ränder, Seitengröße, Kopfzeileninhalt und Beschriftung durch Bearbeitung der Exportfunktion angepasst werden können. fpdf2 unterstützt auch das Hinzufügen von Bildern, Tabellen und Unicode-Schriftarten, was reichhaltigere Dokumentlayouts für Organisationen mit spezifischen Anforderungen an die Markengestaltung ermöglicht.
