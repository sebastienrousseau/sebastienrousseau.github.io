Àkàndé: asistente de voz impulsado por GPT para directivos

Arquitectura de un asistente de voz Python de código abierto: Whisper, GPT-4, caché SQLite y fpdf2

Resumen ejecutivo / Puntos clave

  • Àkàndé ⧉ es un asistente de voz Python de código abierto que encadena OpenAI Whisper para la conversión voz-texto, las finalizaciones de chat GPT-4, una caché de respuestas SQLite local y la exportación PDF con fpdf2 en un único flujo de trabajo por voz que no requiere almacenamiento en la nube ni pesos de modelo de IA local.
  • La caché SQLite almacena hashes SHA-256 de cadenas de consulta normalizadas asociados al texto bruto de las respuestas API; los aciertos de caché no cuestan ningún token y retornan en menos de 10 ms, haciendo que las consultas repetidas (como revisar una decisión tomada antes en una reunión) sean esencialmente gratuitas.
  • La conversación multi-turno se mantiene construyendo la lista messages en memoria y pasándola en cada llamada a la API Chat Completions — el modelo recibe el historial completo de la sesión para poder referirse a intercambios anteriores, a costa de un uso de tokens incrementalmente mayor por turno.
  • La generación de resúmenes PDF serializa la lista messages de la sesión en un documento fpdf2 formateado: los turnos del usuario y del asistente están etiquetados, se insertan marcas de tiempo y la paginación automática gestiona sesiones de cualquier longitud; el archivo se escribe en el sistema de archivos local, no se carga.
  • Límite de privacidad: solo la consulta en curso (y el historial de sesión hasta el límite de la ventana de contexto) abandona el dispositivo — ninguna grabación de audio, ninguna transcripción ni ninguna respuesta en caché se envía a ningún servicio remoto distinto de la API de OpenAI.

Àkàndé ⧉ es un asistente de voz Python de código abierto construido en torno a tres componentes modulables: OpenAI Whisper para el reconocimiento de voz, la API GPT-4 Chat Completions para la comprensión y generación del lenguaje, y una base de datos SQLite local para el almacenamiento en caché de respuestas y la persistencia de sesiones. El resultado es un flujo de trabajo por voz que puede ejecutarse en un portátil sin pesos de modelo local, infraestructura de almacenamiento sin conexión ni pila de contenedores.

Este artículo describe la arquitectura técnica de cada componente, las decisiones de diseño en torno al almacenamiento en caché y el contexto multi-turno, y el pipeline de exportación PDF.

Visión general del pipeline #

Una interacción de Àkàndé sigue esta secuencia:

  1. Captura de audio — el usuario habla; la aplicación graba el audio en un archivo WAV temporal usando sounddevice o una biblioteca de audio compatible.
  2. Conversión voz a texto — el archivo WAV se envía a openai.audio.transcriptions.create() (API Whisper); la transcripción se devuelve como una cadena de texto plano.
  3. Búsqueda en caché — la transcripción se normaliza (convertida a minúsculas, espacios reducidos) y se hashea con SHA-256; el hash se busca en la tabla SQLite local response_cache.
  4. Llamada API o acierto de caché — si no hay coincidencia, la transcripción se añade a la lista messages de la sesión y se envía a openai.chat.completions.create(); el texto de respuesta se almacena en la caché.
  5. Síntesis de voz — el texto de respuesta se convierte a audio usando el endpoint openai.audio.speech.create() (TTS) o una biblioteca TTS local, y se reproduce.
  6. Exportación PDF (bajo demanda) — la lista completa messages se serializa en un documento fpdf2 formateado y se escribe en disco.

Integración con OpenAI: Chat Completions y Whisper #

Àkàndé utiliza el SDK Python openai tanto para el reconocimiento de voz como para la generación de texto. La llamada de transcripción Whisper:

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

La llamada Chat Completions mantiene una lista messages con ámbito de sesión:

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

El prompt del sistema se antepone una sola vez al inicio de la sesión y controla la personalidad de Àkàndé, el formato de salida y cualquier restricción específica del dominio:

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

Establecer temperature=0.2 sacrifica la variación creativa en favor del determinismo — importante para consultas factuales como recordar una decisión tomada anteriormente en la sesión.

Caché de respuestas SQLite #

El esquema de la caché es mínimo:

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

La ruta de lectura y escritura:

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

INSERT OR REPLACE garantiza que una respuesta en caché se actualice si la misma consulta se envía tras una actualización del modelo. Una consulta de desalojo basada en TTL (DELETE WHERE created_at < ?) puede programarse al inicio para limitar el tamaño de la caché.

Rendimiento de los aciertos de caché: una búsqueda SQLite en un SSD local retorna en menos de 1 ms para tablas de hasta ~100.000 filas. La latencia de ida y vuelta de una llamada en tiempo real a la API GPT-4 es normalmente de 600–900 ms para respuestas cortas. Para un briefing diario con unas pocas consultas repetidas, la caché elimina la mayoría de las llamadas API después de la primera sesión.

Generación de resúmenes PDF #

La exportación PDF utiliza fpdf2, una biblioteca Python PDF mantenida sin dependencias binarias:

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell() gestiona el ajuste de línea y los saltos de página automáticos, de modo que las sesiones de cualquier longitud producen un documento bien formateado sin lógica de paginación manual. El resultado es un archivo compatible con PDF/A sin fuentes incrustadas más allá de las métricas estándar de Helvetica.

Modelo de privacidad #

El límite de privacidad en Àkàndé está definido por tres hechos:

  1. El audio se envía a la API Whisper a través de HTTPS y OpenAI no lo retiene más allá de la llamada API (según la política de uso de datos de la API de OpenAI vigente en febrero de 2024).
  2. Las llamadas a la API Chat Completions transmiten la lista messages de la sesión — que puede contener el historial completo de la conversación en sesiones multi-turno.
  3. La base de datos SQLite y los archivos PDF residen íntegramente en el sistema de archivos local; no se produce ninguna sincronización en segundo plano con ningún servicio en la nube.

Para casos de uso ejecutivos que involucren temas sensibles — discusiones de M&A, asuntos de personal, estrategia regulatoria — el historial de sesión transmitido a la API debe revisarse con respecto a la política de uso de IA de la organización antes de su despliegue. El límite max_tokens en el prompt del sistema puede utilizarse para evitar la transmisión inadvertida de contexto que supere el alcance de divulgación previsto.

Preguntas frecuentes #

¿Àkàndé retiene el historial de conversaciones después de que finaliza la sesión? La lista messages en memoria se descarta cuando el proceso termina. El historial de conversaciones solo se retiene si el usuario activa una exportación PDF o si se añade una capa de persistencia personalizada. La caché SQLite almacena hashes de consultas y texto de respuestas, no el contexto completo de la conversación.

¿Cómo gestiona la caché las consultas similares pero no idénticas? La caché utiliza hashing de coincidencia exacta sobre la cadena de consulta normalizada. Dos consultas que difieran en una sola palabra producirán hashes diferentes y darán lugar a llamadas API separadas. El almacenamiento en caché semántico (que utiliza similitud de embeddings para hacer coincidir consultas casi duplicadas) requeriría un paso adicional de búsqueda vectorial y no forma parte de la implementación base.

¿Qué modelo GPT usa Àkàndé por defecto? El valor predeterminado es gpt-4-turbo-preview desde febrero de 2024. El nombre del modelo es un parámetro de configuración, por lo que puede sustituirse por cualquier modelo de finalización de chat de OpenAI. Cambiar a gpt-3.5-turbo reduce el costo de la API en aproximadamente 20× por token, pero reduce la calidad de razonamiento para consultas complejas de varios pasos.

¿Se puede personalizar el formato de exportación PDF? Sí. La función de exportación fpdf2 acepta la lista messages como única entrada requerida, por lo que la fuente, los márgenes, el tamaño de página, el contenido del encabezado y el etiquetado pueden modificarse editando la función de exportación. fpdf2 también admite la adición de imágenes, tablas y fuentes Unicode, lo que permite diseños de documentos más elaborados para organizaciones con requisitos específicos de identidad corporativa.
