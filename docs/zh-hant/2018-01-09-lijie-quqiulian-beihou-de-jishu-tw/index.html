理解區塊鏈背後的技術

執行摘要 / 核心要點

  • 問題所在。 數位現金需要解決雙重支付問題：在沒有可信清算機構的情況下，防止同一單位被消費兩次。Bitcoin 2008 年的白皮書透過用密碼學證明和分散式共識取代可信中介解決了這一問題（Nakamoto, 2008）。
  • 資料結構。 區塊鏈是一個區塊的鏈結串列，每個區塊頭都包含前一個區塊頭的 SHA-256 雜湊值。雜湊鏈使歷史記錄只可追加：修改任何過去的區塊都會使此後每個雜湊值失效，迫使攻擊者重新完成所有後續的 proof-of-work。
  • Merkle 樹。 區塊內的交易被雜湊化為二元 Merkle 樹。儲存在區塊頭中的根雜湊值允許高效驗證任何單筆交易，無需下載完整區塊——這是輕量級 SPV 客戶端的基礎。
  • Ethereum 的擴充。 Ethereum 的黃皮書（2014 年）引入了 EVM——一個在每個全節點上執行的確定性堆疊機器。智慧合約是部署到鏈上的位元組碼；它們在所有節點上以相同方式執行並以原子方式結算，用自我執行程式碼取代了可信中介（Wood, 2014）。
  • 實際意義。 自 2017 年以來部署的每一個代幣化資產、穩定幣和 DeFi 協定都執行在這些基礎之上。理解雜湊鏈、Merkle 樹和 EVM 執行模型，是使用任何基於 Ethereum 系統的前提條件。

區塊鏈解決的問題 #

在 Bitcoin 出現之前，數位支付需要一個可信中介——銀行、支付處理商或清算所——來防止雙重支付。如果 Alice 向 Bob 傳送代表 10 英鎊的數位檔案，檔案本身沒有任何東西能阻止她向 Carol 傳送一份相同的副本。每個現有系統中的解決方案都是中心化記帳：銀行的帳本顯示錢已被花費，因此無法再次花費。

Bitcoin 的貢獻在於用分散式帳本取代了那個可信帳本，其中所有交易的記錄在數千個獨立節點上被複製。節點間的相互不信任透過兩種機制轉化為安全性：

  1. 密碼學鏈結。 每個交易區塊都包含前一個區塊的雜湊值。雜湊函數是一種單向確定性映射：給定任何輸入，函數產生固定長度的輸出，即使輸入改變一個位元也會產生完全不同的輸出。這意味著對歷史區塊的任何修改都會使其後的每個區塊失效。

  2. Proof-of-work 共識。 新增區塊需要找到一個 nonce 值，使區塊的雜湊值低於目標閾值——找到它在計算上昂貴，驗證它則極其廉價。這使得重寫歷史的代價與被修改區塊的深度成正比，因為攻擊者必須從該區塊到鏈尖重新完成所有的 proof-of-work。

這種組合意味著，具有最多累積 proof-of-work 的最長鏈，從其構造上來說，就是由誠實參與者消耗真實資源所維護的那條鏈。

密碼學構建模組 #

區塊鏈技術將三種預先存在的密碼學原語組合成一種新的架構：

SHA-256 雜湊函數 #

SHA-256（安全雜湊演算法 256 位元）是由 NIST 標準化的 SHA-2 系列成員。它接受任意長度的輸入，並產生 256 位元的輸出。區塊鏈使用的關鍵特性：

  • 確定性。 相同的輸入始終產生相同的輸出。
  • 原像抗性。 給定雜湊輸出，在計算上不可行重建輸入。
  • 雪崩效應。 改變輸入的一個位元會改變大約一半的輸出位元，使暴力搜尋效率低下。
  • 碰撞抗性。 在計算上不可行找到產生相同雜湊值的兩個不同輸入。

Bitcoin 將 SHA-256 應用兩次（SHA-256d），以增強對長度延伸攻擊的安全性。Ethereum 使用 Keccak-256，一種 SHA-3 決賽入圍變體。

Merkle 樹 #

Merkle 樹是雜湊值的二元樹。每個葉節點是一筆交易的雜湊值。每個內部節點是其兩個子節點的雜湊值。根節點——Merkle 根——將區塊中的所有交易彙總為儲存在區塊頭中的單個 32 位元組值。

實際意義：要驗證特定交易是否包含在區塊中，只需 log₂(n) 個雜湊值，而不是所有 n 筆交易。對於包含 2,000 筆交易的區塊，驗證只需要 11 個雜湊值而非 2,000 個——這是輕量級客戶端簡化支付驗證（SPV）的基礎。

數位簽章（ECDSA） #

Bitcoin 和 Ethereum 中的交易授權使用基於 secp256k1 曲線的橢圓曲線數位簽章演算法（ECDSA）。私鑰對交易簽章；任何節點都可以使用對應的公鑰驗證簽章，而無需知道私鑰。這確保只有私鑰持有者才能授權從某個地址進行花費。

Ethereum 地址是公鑰 Keccak-256 雜湊值的最後 20 個位元組——這種推導方式使地址緊湊且可攜，同時在密碼學上與金鑰對綁定。

Bitcoin 區塊鏈的工作原理 #

一個 Bitcoin 區塊包含三個邏輯元件：

區塊頭——80 位元組，包含：協定版本、前一個區塊頭的雜湊值、交易的 Merkle 根、Unix 時間戳記、當前難度目標和 nonce。礦工不斷迭代 nonce（有時還有時間戳記或 coinbase 交易中的額外 nonce），直到區塊頭的雙重 SHA-256 雜湊值低於難度目標。

交易列表——區塊中包含的有序交易集合。coinbase 交易（第一筆）將區塊獎勵和交易費分配給礦工的地址。

鏈——區塊頭的鏈結。鏈中累積的 proof-of-work（生產每個區塊所做的所有工作總和）決定哪個分叉是規範鏈。節點始終遵循具有最多累積工作量的鏈。

Bitcoin 的目標區塊時間為 10 分鐘。難度每 2,016 個區塊（約兩週）調整一次，以在總網路雜湊率變化時維持該目標。

Ethereum 的可程式化層 #

Ethereum 將 Bitcoin 的交易模型從「轉移價值」泛化為「執行程式碼」。主要新增內容：

以太坊虛擬機器（EVM）。 一個 256 位元字、基於堆疊的虛擬機器，在所有全節點上確定性地執行。每個操作碼都有明確的 gas 成本。計算受區塊 gas 限制約束，防止無限迴圈使網路停止。所有節點在相同狀態下執行相同位元組碼必須產生相同輸出——這種對執行的共識使智慧合約無需信任。

帳戶。 Ethereum 有兩種帳戶類型：由私鑰控制的外部擁有帳戶（EOA），以及程式碼儲存在鏈上的合約帳戶。傳送到合約地址的交易會觸發合約位元組碼的執行。

狀態。 Ethereum 的全域狀態是地址到帳戶狀態（nonce、餘額、儲存、程式碼雜湊）的映射。狀態根——所有帳戶狀態的 Merkle Patricia 前綴樹——包含在每個區塊頭中，允許高效證明任何區塊高度下任何帳戶的狀態。

Gas。 使用者為每個 EVM 操作支付 gas（以 ETH 計）。Gas 有兩個功能：它補償礦工/驗證者的計算，並限制單筆交易可消耗的資源，防止透過昂貴操作進行阻斷服務攻擊。

用 Solidity 編寫智慧合約 #

Solidity 是一種靜態型別、面向合約的語言，可編譯為 EVM 位元組碼。一個最小化的代幣合約說明了核心概念：

pragma solidity ^0.8.0;

contract MyToken {
    string public name;
    string public symbol;
    uint8 public decimals;
    uint256 public totalSupply;
    mapping(address => uint256) public balanceOf;

    event Transfer(address indexed from, address indexed to, uint256 value);

    constructor(
        string memory _name,
        string memory _symbol,
        uint8 _decimals,
        uint256 _totalSupply
    ) {
        name = _name;
        symbol = _symbol;
        decimals = _decimals;
        totalSupply = _totalSupply;
        balanceOf[msg.sender] = _totalSupply;
    }

    function transfer(address _to, uint256 _value) external returns (bool) {
        require(balanceOf[msg.sender] >= _value, "Insufficient balance");
        balanceOf[msg.sender] -= _value;
        balanceOf[_to] += _value;
        emit Transfer(msg.sender, _to, _value);
        return true;
    }
}

關鍵觀察：mapping(address => uint256) 是 EVM 儲存佈局，而不是記憶體資料結構——讀寫都需要消耗 gas。require 在失敗時回滾整個交易，退還未使用的 gas。event Transfer 發出一個日誌，鏈下索引器使用該日誌追蹤轉帳，而無需重新讀取完整狀態。constructor 在部署時執行一次；後續呼叫轉到具名函數。

ERC-20 標準規範了同質化代幣的通用介面——transfer、transferFrom、approve、allowance、balanceOf、totalSupply——允許任何 ERC-20 相容代幣與任何支援 ERC-20 的交易所或錢包協作，無需自訂整合。

從帳本到金融基礎設施 #

此處描述的區塊鏈原語——雜湊鏈、Merkle 樹、EVM 和 ERC-20——在 2018 年至 2026 年間成為更廣泛金融應用的基礎：

去中心化金融（DeFi）。 借貸協定（Compound、Aave）、自動做市商（Uniswap）和收益聚合器都以 EVM 智慧合約形式執行。它們用自我執行的程式碼和鏈上流動性池取代了傳統金融中介的清算、託管和結算功能。

代幣化資產。 中央銀行和商業銀行正在 EVM 相容鏈的許可變體上試驗代幣化存款、代幣化債券和代幣化貨幣市場基金。其底層機制——雜湊安全的狀態轉換、原子結算、可程式化轉帳規則——是 2014 年 Ethereum 架構的直接後代。

央行數位貨幣。 Bank of England 的批發 CBDC 研究、ECB 的數位歐元計畫以及 Project Agorá 都在探索源自或相容於 Bitcoin 和 Ethereum 基礎設計的 DLT 架構。即使許可和治理模型與公共區塊鏈完全不同，共識和雜湊鏈結構仍然具有重要意義。

從 2008 年 Bitcoin 白皮書到 2026 年代幣化金融的旅程跨越了二十年，但它執行在一個連貫的技術脈絡上。理解 SHA-256 雜湊鏈如何強制執行不可變性、Merkle 樹如何實現高效驗證，以及 EVM 如何以原子方式執行智慧合約，是評估區塊鏈在受監管金融服務中能做什麼和不能做什麼的先決條件。

常見問題 #

區塊鏈與分散式資料庫有什麼區別？

傳統的分散式資料庫為了可用性和效能而在節點間複製資料，但信任是中心化的——管理員可以修改記錄。區塊鏈透過雜湊鏈和共識使篡改在計算上代價高昂：修改任何歷史記錄需要重新完成所有後續的 proof-of-work 或 proof-of-stake，並說服網路接受修改後的分叉。其顯著特性是透過密碼學和激勵設計而非存取控制來強制執行的防篡改性。

Ethereum 為什麼使用 Keccak-256 而不是 SHA-256？

Ethereum 採用 Keccak-256（NIST 標準化調整前的 SHA-3 決賽入圍演算法），部分原因是其設計者希望獨立於 Bitcoin 已經依賴的 SHA-2 系列。Keccak 還具有不同的代數特性，使其對某些 EVM 操作具有吸引力。對開發者的實際影響是，Ethereum 地址推導和儲存槽雜湊使用 Keccak-256，而不是 Bitcoin 中的 SHA-256d。

EVM 中的「gas」防止什麼？

Gas 防止兩類攻擊。首先，它防止透過計算昂貴的操作進行阻斷服務攻擊：每個操作碼都消耗 gas，因此攻擊者無法強迫網路免費執行無限迴圈。其次，區塊 gas 限制限制了每個區塊的總計算量，確保區塊驗證時間對全節點保持有界且可預測。沒有 gas，單個合約呼叫可能透過執行無限計算使網路停止。

proof-of-stake 與 proof-of-work 相比如何改變安全模型？

在 proof-of-work 中，安全性由能源消耗提供：攻擊鏈需要控制網路超過 50% 的雜湊率，這意味著控制超過 50% 的實體硬體和電力。在 proof-of-stake 中（Ethereum 自 2022 年合併後採用），安全性由經濟質押提供：驗證者鎖定 ETH 作為抵押品，如果他們簽署相互衝突的區塊，抵押品將被削減。51% 攻擊需要獲取並冒險使用超過 50% 的所有質押 ETH——這是資本成本而非硬體和能源成本。在理性驗證者更傾向於費用收入而非資本損失的假設下，安全模型不同但在經濟上具有數學上的可比性。
