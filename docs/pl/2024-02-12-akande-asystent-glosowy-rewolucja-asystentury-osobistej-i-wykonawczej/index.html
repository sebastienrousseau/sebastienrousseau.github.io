Àkàndé: GPT-Powered Voice Assistant for Executives

Streszczenie / Kluczowe wnioski

  • Àkàndé ⧉ to open-source'owy asystent głosowy w Pythonie łączący zamianę mowy na tekst przez OpenAI Whisper, uzupełnienia czatu GPT-4, lokalną pamięć podręczną odpowiedzi SQLite i eksport PDF przez fpdf2 w jeden głosowy przepływ pracy bez potrzeby przechowywania w chmurze i lokalnych wag modeli AI.
  • Pamięć podręczna SQLite przechowuje skróty SHA-256 znormalizowanych ciągów zapytań odwzorowanych na surowy tekst odpowiedzi API; trafienia w pamięć podręczną nie kosztują tokenów i zwracają wyniki w poniżej 10 ms, dzięki czemu powtarzające się zapytania (takie jak przeglądanie decyzji z wcześniejszej części spotkania) są praktycznie bezpłatne.
  • Wieloturowa konwersacja jest utrzymywana przez budowanie listy messages w pamięci i przekazywanie jej przy każdym wywołaniu Chat Completions API — model otrzymuje pełną historię sesji, dzięki czemu może odwoływać się do wcześniejszych wymian, za cenę stopniowego wzrostu zużycia tokenów na turę.
  • Generowanie podsumowania PDF serializuje listę messages sesji do sformatowanego dokumentu fpdf2: tury użytkownika i asystenta są oznaczone etykietami, wstawiane są znaczniki czasu, a automatyczna paginacja obsługuje sesje dowolnej długości; plik jest zapisywany w lokalnym systemie plików, a nie przesyłany.
  • Granica prywatności: tylko bieżące zapytanie (i historia sesji do limitu okna kontekstowego) opuszcza urządzenie — żadne nagrania audio, transkrypcje ani buforowane odpowiedzi nie są wysyłane do żadnego zdalnego serwisu innego niż OpenAI API.

Àkàndé ⧉ to open-source'owy asystent głosowy w Pythonie zbudowany wokół trzech kompozytowalnych komponentów: OpenAI Whisper do rozpoznawania mowy, GPT-4 Chat Completions API do rozumienia i generowania języka oraz lokalnej bazy danych SQLite do buforowania odpowiedzi i utrwalania sesji. Rezultatem jest głosowy przepływ pracy, który można uruchomić na laptopie bez lokalnych wag modelu, infrastruktury pamięci masowej offline ani stosu kontenerów.

Ten artykuł opisuje architekturę techniczną każdego komponentu, decyzje projektowe dotyczące buforowania i wieloturowego kontekstu oraz potok eksportu PDF.

Przegląd potoku #

Pojedyncza interakcja z Àkàndé przebiega według następującej sekwencji:

  1. Przechwytywanie dźwięku — użytkownik mówi; aplikacja nagrywa dźwięk do tymczasowego pliku WAV przy użyciu sounddevice lub kompatybilnej biblioteki audio.
  2. Zamiana mowy na tekst — plik WAV jest przesyłany do openai.audio.transcriptions.create() (Whisper API); transkrypt jest zwracany jako zwykły ciąg znaków.
  3. Wyszukiwanie w pamięci podręcznej — transkrypt jest normalizowany (zmiana na małe litery, kompresja białych znaków) i haszowany SHA-256; skrót jest wyszukiwany w lokalnej tabeli SQLite response_cache.
  4. Wywołanie API lub trafienie w pamięć podręczną — przy braku trafienia transkrypt jest dołączany do listy messages sesji i wysyłany do openai.chat.completions.create(); tekst odpowiedzi jest przechowywany w pamięci podręcznej.
  5. Zamiana tekstu na mowę — tekst odpowiedzi jest konwertowany na dźwięk za pomocą punktu końcowego openai.audio.speech.create() (TTS) lub lokalnej biblioteki TTS i odtwarzany.
  6. Eksport PDF (na żądanie) — pełna lista messages jest serializowana do sformatowanego dokumentu fpdf2 i zapisywana na dysku.

Integracja OpenAI: Chat Completions i Whisper #

Àkàndé używa openai Python SDK zarówno do rozpoznawania mowy, jak i do generowania tekstu. Wywołanie transkrypcji Whisper:

with open(audio_file_path, "rb") as f:
    transcript = openai.audio.transcriptions.create(
        model="whisper-1",
        file=f,
        language=None  # auto-detect
    )
user_text = transcript.text

Wywołanie Chat Completions utrzymuje listę messages ograniczoną do zakresu sesji:

messages.append({"role": "user", "content": user_text})

response = openai.chat.completions.create(
    model="gpt-4-turbo-preview",
    messages=messages,
    temperature=0.2,
    max_tokens=1024
)

assistant_text = response.choices[0].message.content
messages.append({"role": "assistant", "content": assistant_text})

Systemowy prompt jest dodawany raz na początku sesji i kontroluje personę Àkàndé, format wyjścia oraz wszelkie ograniczenia dziedzinowe:

messages = [
    {
        "role": "system",
        "content": (
            "You are Àkàndé, a concise executive assistant. "
            "Respond in plain prose. Do not use markdown. "
            "If asked to summarise, produce three bullet points maximum."
        )
    }
]

Ustawienie temperature=0.2 zamienia kreatywną zmienność na determinizm — ważne przy zapytaniach faktograficznych, takich jak przypominanie decyzji z wcześniejszej części sesji.

Pamięć podręczna odpowiedzi SQLite #

Schemat pamięci podręcznej jest minimalny:

CREATE TABLE IF NOT EXISTS response_cache (
    query_hash  TEXT PRIMARY KEY,
    response    TEXT NOT NULL,
    created_at  INTEGER NOT NULL  -- Unix timestamp
);

Ścieżka wyszukiwania i zapisu:

import hashlib, sqlite3, time

def _normalise(text: str) -> str:
    return " ".join(text.lower().split())

def cache_get(conn: sqlite3.Connection, query: str) -> str | None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    row = conn.execute(
        "SELECT response FROM response_cache WHERE query_hash = ?", (h,)
    ).fetchone()
    return row[0] if row else None

def cache_set(conn: sqlite3.Connection, query: str, response: str) -> None:
    h = hashlib.sha256(_normalise(query).encode()).hexdigest()
    conn.execute(
        "INSERT OR REPLACE INTO response_cache VALUES (?, ?, ?)",
        (h, response, int(time.time()))
    )
    conn.commit()

INSERT OR REPLACE gwarantuje aktualizację buforowanej odpowiedzi przy ponownym przesłaniu tego samego zapytania po aktualizacji modelu. Zapytanie usuwające wpisy na podstawie TTL (DELETE WHERE created_at < ?) można zaplanować przy uruchomieniu w celu ograniczenia rozmiaru pamięci podręcznej.

Wydajność trafień w pamięć podręczną: wyszukiwanie SQLite na lokalnym dysku SSD zwraca wyniki w poniżej 1 ms dla tabel do ~100 000 wierszy. Opóźnienie round-trip rzeczywistego wywołania GPT-4 API wynosi zazwyczaj 600–900 ms dla krótkich odpowiedzi. W przypadku codziennego briefingu z kilkoma powtarzającymi się zapytaniami pamięć podręczna eliminuje większość wywołań API po pierwszej sesji.

Generowanie podsumowania PDF #

Eksport PDF korzysta z fpdf2, utrzymywanej biblioteki Python do generowania PDF bez binarnych zależności:

from fpdf import FPDF
from datetime import datetime

def export_session_pdf(messages: list[dict], output_path: str) -> None:
    pdf = FPDF()
    pdf.add_page()
    pdf.set_font("Helvetica", size=11)
    pdf.set_margins(20, 20, 20)

    pdf.set_font("Helvetica", "B", 14)
    pdf.cell(0, 10, f"Àkàndé Session — {datetime.now():%Y-%m-%d %H:%M}", ln=True)
    pdf.ln(4)

    for msg in messages:
        if msg["role"] == "system":
            continue
        label = "You" if msg["role"] == "user" else "Àkàndé"
        pdf.set_font("Helvetica", "B", 10)
        pdf.cell(0, 6, label, ln=True)
        pdf.set_font("Helvetica", size=10)
        pdf.multi_cell(0, 5, msg["content"])
        pdf.ln(3)

    pdf.output(output_path)

multi_cell() obsługuje zawijanie wierszy i automatyczne podziały stron, więc sesje dowolnej długości tworzą dobrze sformatowany dokument bez ręcznej logiki paginacji. Wynikiem jest plik zgodny z PDF/A bez osadzonych czcionek poza standardowymi metrykami Helvetica.

Model prywatności #

Granica prywatności w Àkàndé jest określona przez trzy fakty:

  1. Audio jest przesyłane do Whisper API przez HTTPS i nie jest przechowywane przez OpenAI po wywołaniu API (zgodnie z polityką użytkowania danych OpenAI API z lutego 2024 r.).
  2. Wywołania Chat Completions API przesyłają listę messages sesji — która może zawierać pełną historię konwersacji dla sesji wieloturowych.
  3. Baza danych SQLite i pliki PDF znajdują się wyłącznie w lokalnym systemie plików; nie dochodzi do synchronizacji w tle z żadną usługą chmurową.

W przypadkach użycia przez kadrę kierowniczą obejmujących wrażliwe tematy — dyskusje o fuzjach i przejęciach, sprawy kadrowe, strategia regulacyjna — historia sesji przekazywana do API powinna zostać zweryfikowana pod kątem zgodności z polityką AI organizacji przed wdrożeniem. Limit max_tokens w systemowym prompcie może służyć do zapobiegania niezamierzonemu przesłaniu kontekstu przekraczającego zamierzony zakres ujawnienia.

Często zadawane pytania #

Czy Àkàndé zachowuje historię konwersacji po zakończeniu sesji? Lista messages w pamięci jest usuwana po zakończeniu procesu. Historia konwersacji jest zachowywana tylko wtedy, gdy użytkownik inicjuje eksport PDF lub dodana zostanie niestandardowa warstwa utrwalania. Pamięć podręczna SQLite przechowuje skróty zapytań i tekst odpowiedzi, a nie pełny kontekst konwersacji.

Jak pamięć podręczna obsługuje zapytania podobne, ale nie identyczne? Pamięć podręczna używa haszowania z dokładnym dopasowaniem na znormalizowanym ciągu zapytania. Dwa zapytania różniące się jednym słowem wygenerują różne skróty i skutkują oddzielnymi wywołaniami API. Semantyczne buforowanie (używające podobieństwa osadzeń do dopasowania niemal zduplikowanych zapytań) wymagałoby dodatkowego kroku wyszukiwania wektorowego i nie jest częścią podstawowej implementacji.

Którego modelu GPT Àkàndé używa domyślnie? Domyślnym modelem od lutego 2024 r. jest gpt-4-turbo-preview. Nazwa modelu jest parametrem konfiguracyjnym, więc można zastąpić go dowolnym modelem uzupełniania czatu OpenAI. Przełączenie na gpt-3.5-turbo zmniejsza koszt API o około 20× na token, ale obniża jakość rozumowania w przypadku złożonych zapytań wieloetapowych.

Czy format eksportu PDF można dostosować? Tak. Funkcja eksportu fpdf2 przyjmuje listę messages jako jedyne wymagane wejście, więc czcionkę, marginesy, rozmiar strony, zawartość nagłówka i oznaczenia można zmienić, edytując funkcję eksportu. fpdf2 obsługuje również dodawanie obrazów, tabel i czcionek Unicode, umożliwiając bogatsze układy dokumentów dla organizacji o określonych wymaganiach dotyczących marki.
